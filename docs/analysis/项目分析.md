# 项目分析

本文档面向刚接触这个项目的新手，先用“它是什么、解决什么、文件在哪里”的方式建立整体地图。

## 1. 这个项目是做什么的？

这是一个基于 Qt Widgets 的工业视觉检测桌面程序。工程入口和构建配置可以从以下文件看到：

- `qt_ui_test.pro`：qmake 工程文件，声明了 Qt 模块、C++17、OpenCV、HALCON include 路径，以及要编译的源码、头文件、UI 文件和资源文件。
- `src/main.cpp`：程序入口，初始化 HALCON 环境、安装日志处理、加载样式，然后显示登录窗口。
- `src/LoginWindow.cpp`：登录窗口，用户选择设备和角色，密码通过后进入主窗口。
- `src/MainWindow.cpp`：主界面，负责打开相机、显示实时画面、管理方案、运行检测工具链、展示 OK/NG 结果。

从代码结构看，它的核心流程大概是：

1. 启动程序并初始化 HALCON：`src/main.cpp`、`src/algorithms/halcon/HalconRuntimePaths.cpp`
2. 登录并选择设备/用户：`src/LoginWindow.cpp`
3. 主界面显示相机图像：`src/MainWindow.cpp`、`src/frame/CameraFrameProvider.cpp`
4. 配置检测方案和工具：`src/ToolsDialog.cpp`、`src/ToolLibraryDialog.cpp`、`src/*PresenceDialog.cpp`、`src/ObjectDetectionDialog.cpp`
5. 运行工具链并输出检测结果：`src/toolcore/ToolEngine.cpp`、`src/tooladapters/*.cpp`

## 2. 它主要解决什么问题？

它主要解决“工业相机拍到一张图后，如何自动判断产品是否合格”的问题。

换成更直白的话：项目让用户把多种视觉检测能力配置成一套“方案”，然后对实时相机画面运行这些检测工具，最后给出 OK/NG、数量、分数、轮廓/框线等结果。

目前代码里能看到的主要检测能力包括：

- OCR 文字识别：`src/algorithms/ocr/OcrHalconRunner.cpp`、`src/tooladapters/OcrAdapter.cpp`
- 模板/图案存在检测：`src/algorithms/presence/PatternPresenceHalconRunner.cpp`、`src/tooladapters/PatternPresenceAdapter.cpp`
- Blob、圆、边、线、轮廓等存在检测：`src/algorithms/presence/BlobPresenceHalconRunner.cpp`、`src/algorithms/presence/CirclePresenceHalconRunner.cpp`、`src/algorithms/presence/EdgePresenceHalconRunner.cpp`、`src/algorithms/presence/LinePresenceHalconRunner.cpp`、`src/algorithms/presence/ContourPresenceHalconRunner.cpp`
- AI 目标检测，包含 RKNN/YOLO 相关桥接：`src/algorithms/ai/AiDetectionRunner.cpp`、`src/tooladapters/AiDetectionAdapter.cpp`、`rk_ai_materials/`

检测方案会保存到 `projects/` 下，例如：

- `projects/scheme_1/scheme.json`
- `projects/scheme_75381ddd/scheme.json`
- `projects/scheme_1/reference.png`

也就是说，这个项目不仅是“跑算法”，还包含“配置检测方案、保存方案、加载基准图、显示检测结果”的完整桌面工作流。

## 3. 项目里最重要的几个目录分别是干什么的？

- `src/`：最重要的源码目录。主窗口、登录窗口、工具配置窗口、相机取流、工具引擎、算法适配器、HALCON/AI 算法 runner 都在这里。
- `src/toolcore/`：检测工具的通用核心层，例如工具类型、工具配置、工具请求、工具结果、工具引擎。代表文件：`src/toolcore/ToolEngine.cpp`、`src/toolcore/ToolConfig.h`、`src/toolcore/ToolTypes.h`。
- `src/tooladapters/`：把通用工具配置转换成具体算法调用的“适配层”。代表文件：`src/tooladapters/PatternPresenceAdapter.cpp`、`src/tooladapters/AiDetectionAdapter.cpp`。
- `src/algorithms/`：真正调用算法/运行检测的地方，包含 HALCON、OCR、presence 检测、AI 检测。代表目录：`src/algorithms/presence/`、`src/algorithms/ocr/`、`src/algorithms/ai/`。
- `src/frame/`：相机和图像显示相关代码。代表文件：`src/frame/CameraFrameProvider.cpp`、`src/frame/FrameViewHelper.cpp`、`src/frame/MatImageConverter.cpp`。
- `ui/`：Qt Designer 生成界面的 `.ui` 文件。代表文件：`ui/MainWindow.ui`、`ui/LoginWindow.ui`、`ui/ObjectDetectionDialog.ui`。
- `resources/`：图片、图标、字体等 Qt 资源。资源清单在 `resources/resources.qrc`。
- `styles/`：界面样式表，主要是 `styles/app.qss`。
- `projects/`：运行时/业务方案数据，每个 `scheme_*` 目录通常有 `scheme.json` 和 `reference.png`。
- `smoke/`：冒烟测试目录，用来快速验证关键模块是否能跑。代表文件：`smoke/halcon_runtime_smoke.cpp`、`smoke/ai_detection_bridge_smoke.cpp`。
- `docs/analysis/`：已有分析、排查、迁移、修复报告集中存放的位置。后续分析和指令文档也建议继续放这里。
- `docs/patches/`：补丁文件目录，例如 `docs/patches/object_detection_ui_stage1_stage2_before_algorithm.patch`。
- `rk_ai_materials/`：AI/RKNN/YOLO 相关材料、模型、样例代码和测试图片。代表文件：`rk_ai_materials/model/yolov8_red_black.rknn`、`rk_ai_materials/yolo_demo/src/main.cc`。
- `backup/`：历史备份文件，不是主线源码，但排查旧版本行为时可能有用。
- `build/`、`build-release/`、`build-halcon-release/`、`debug/`：构建输出目录，不是主要源码目录。

## 4. 源码大概放在哪里？

主源码在 `src/`。

比较关键的源码入口如下：

- 程序入口：`src/main.cpp`
- 登录窗口：`src/LoginWindow.cpp`、`src/LoginWindow.h`
- 主窗口：`src/MainWindow.cpp`、`src/MainWindow.h`
- 方案保存/加载：`src/SchemeStore.cpp`、`src/SchemeStore.h`
- 相机取流：`src/frame/CameraFrameProvider.cpp`、`src/frame/CameraFrameProvider.h`
- 工具引擎：`src/toolcore/ToolEngine.cpp`、`src/toolcore/ToolEngine.h`
- 工具类型定义：`src/toolcore/ToolTypes.h`
- 检测工具适配器：`src/tooladapters/`
- HALCON/AI 算法实现：`src/algorithms/`

界面源码的一部分在 `ui/`，这些是 Qt Designer 的 `.ui` 文件，例如 `ui/MainWindow.ui`。编译时会生成类似 `ui_MainWindow.h` 的文件，根目录下已有一些生成产物，例如 `ui_MainWindow.h`，但通常不把它们当作手写源码。

另外，`rk_ai_materials/yolo_demo/` 下也有一套独立的 YOLO/RKNN 示例代码，例如 `rk_ai_materials/yolo_demo/src/main.cc`，它更像 AI 侧参考材料，不是 Qt 主程序的核心源码。

## 5. 测试大概放在哪里？

当前没有看到大型测试框架目录，例如 `tests/`。现有测试更像冒烟测试，集中在 `smoke/`：

- `smoke/halcon_runtime_smoke.cpp`：快速验证 HALCON 路径、OCR、模板/Blob/圆/边/线等算法 runner 是否能调用。
- `smoke/halcon_runtime_smoke.pro`：上面这个冒烟测试的 qmake 工程文件。
- `smoke/ai_detection_bridge_smoke.cpp`：验证 AI 检测解析、过滤、判断逻辑，以及远端 RKNN 桥接失败时是否能返回错误。
- `smoke/ai_detection_bridge_smoke.pro`：上面这个冒烟测试的 qmake 工程文件。

`docs/analysis/` 里有一些带 `regression`、`audit`、`report` 的文档，例如 `docs/analysis/v2_presence_algorithm_phase2_p1_p3_regression_report.md`，它们是分析/回归记录，不是可直接执行的测试代码。

## 6. 文档大概放在哪里？

文档主要在 `docs/`。

当前比较清晰的文档位置是：

- `docs/analysis/`：分析报告、排查报告、迁移记录、修复记录。例如 `docs/analysis/v2_presence_algorithm_audit.md`、`docs/analysis/ai_detection_remote_rknn_bridge_stage4_report.md`。
- `docs/patches/`：补丁文件，例如 `docs/patches/object_detection_ui_stage1_stage2_before_algorithm.patch`。

根目录暂时没有看到常见的 `README.md`。所以后续如果要继续写项目分析、排查结论、执行指令，建议统一放在 `docs/analysis/`，比如本文档：

- `docs/analysis/项目分析.md`

## 新手阅读建议

如果只是想快速理解项目，不建议一开始就读所有 `.cpp` 文件。可以按这个顺序看：

1. `qt_ui_test.pro`：先知道哪些文件参与编译。
2. `src/main.cpp`：看程序从哪里启动。
3. `src/LoginWindow.cpp`：看登录后如何进入主窗口。
4. `src/MainWindow.cpp`：看主流程，包括相机、方案、工具链运行。
5. `src/toolcore/ToolEngine.cpp`：看一个工具是如何被执行的。
6. `src/tooladapters/PatternPresenceAdapter.cpp` 或 `src/tooladapters/AiDetectionAdapter.cpp`：看界面配置如何转成算法调用。
7. `src/algorithms/presence/`、`src/algorithms/ai/`：最后再深入具体算法。

## 额外注意

`qt_ui_test.pro` 当前除了正常工程配置外，还夹杂了一段看起来不像 qmake 配置的文本和一个外部链接。这里没有做任何修改，但后续构建如果出现 qmake 解析问题，可以优先检查这个文件。
