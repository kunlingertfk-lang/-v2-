# V2 视觉工具开发 SOP

## 1. 文档目的

本文档是 V2 工业视觉工具开发、优化、测试和交付的统一操作规范，适用于开发人员、测试人员、技术负责人及后续接手人员。它同时承担两项职责：

1. 沉淀长期有效的工具开发流程、技术边界和验收门禁。
2. 记录当前 V2 工具族的证据化成熟度、主要缺口和推荐整改顺序。

本文覆盖以下工具：

- 有无工具：图案有无、Blob 有无、圆有无、边有无、线有无、轮廓有无。
- AI 工具：AI 目标检测、AI 分类以及 RK 设备推理桥接。
- 定位工具：相机/坐标系标定、模板定位、基准姿态标定、位置修正。
- 识别工具：字符识别、颜色比较、颜色识别、注册分类、注册目标检测。

本 SOP 不替代单功能设计。算法参数、UI 截图、字段清单、模型格式和专项测试应继续维护在 `docs/FID/<工具名>/`；问题分析和阶段回归报告放在 `docs/analysis/`。

### 1.1 规则优先级

发生冲突时按以下顺序执行：

1. 根目录 `AGENTS.md`：项目级最高约束。
2. `docs/FID/Function_Docs.md`：FID 工具公共约束。
3. 本 SOP：开发流程、门禁、工具族检查表及整改方法。
4. `docs/FID/<工具名>/`：单功能设计、字段和实施记录。
5. `docs/analysis/`：特定时间点的分析和回归证据。

历史文档只说明当时状态。当前功能是否完成，必须重新核对代码、构建、自动化测试和人工验收证据。

### 1.2 成熟度定义

| 等级 | 定义 | 最低证据 |
| --- | --- | --- |
| 未接入 | 没有可用入口或核心链路 | 代码审计记录 |
| 界面占位 | 有入口或 Dialog，但没有真实生产算法闭环 | UI 可打开；未实现能力有明确提示 |
| 部分可运行 | 部分路径能得到真实结果，但配置、异常、模型、位置修正或测试仍有明显缺口 | 至少一条真实运行路径和对应证据 |
| 闭环可运行 | 新建、保存、重开、编辑、运行、结果显示和主要异常路径均打通 | 构建、专项 smoke、配置回显及人工验收记录 |
| 生产就绪 | 在闭环基础上完成现场数据回归、性能和稳定性验证、模型与兼容策略、故障恢复及文档交付 | 发布候选构建、固定回归集、现场验收和风险关闭记录 |

成熟度按最弱环节判定。例如算法可运行但配置重开丢失，仍不能标为“闭环可运行”；只有 Dialog 的工具不得因为界面完整而标为“部分可运行”。

## 2. 总体技术架构

### 2.1 标准纵向闭环

所有视觉工具应保持同一条工程链路：

```text
ToolLibraryDialog / ToolsDialog
        ↓
功能配置 Dialog
        ↓
ToolConfig.params / judgeRule
        ↓
ToolAdapter
        ↓
HALCON Runner 或 AI Runner
        ↓
ToolResult / payload / overlays
        ↓
工具页、主界面和后序运行上下文
```

各层职责必须清晰：

| 层级 | 主要职责 | 禁止事项 |
| --- | --- | --- |
| 工具入口 | 展示分类、创建正确 `ToolType` | 用显示名称代替稳定类型 |
| Dialog | 参数编辑、ROI 交互、保存回显、测试展示 | 直接承载生产核心算法；普通按钮误触发关闭 |
| `ToolConfig` | 保存稳定、可迁移、可回显的配置 | 保存运行期临时句柄或显示对象 |
| Adapter | 解析配置、构造 Runner 输入、转换统一结果 | 静默吞掉无效字段；伪造算法成功 |
| Runner | 执行核心算法、管理底层资源、返回原始诊断 | 访问 UI；视觉算法绕过 HALCON 红线 |
| `ToolResult` | 区分执行成功与判断 OK/NG，携带诊断和 Overlay | 只返回一条不可定位的字符串 |
| `ToolEngine` | 注册 Adapter、顺序执行、传递前序上下文 | 通过 UI 文案解析依赖；沿用上一帧失败结果 |

### 2.2 必备知识点

#### Qt 与 UI

- Qt 5.15 对象所有权、信号槽、事件循环、线程边界和 `QObject` 生命周期。
- Qt Designer `.ui`、布局、尺寸策略、动态属性、应用级 QSS 及高 DPI 行为。
- `QButtonGroup` 管理 ROI、模式和结果判断等互斥状态。
- `FrameViewHelper` 的视图缩放、平移、scene 坐标与原图坐标转换。
- 异步测试的请求快照、代次编号、取消/关闭门禁和主线程 UI 更新。

#### HALCON

- `HObject`/image/region/XLD contour 的对象语义和释放规则。
- `gen_image1`、`gen_image_interleaved` 等图像桥接及通道、步长、位深和颜色顺序。
- `reduce_domain`、`difference`、区域生成和 ROI/Mask 有效域。
- shape model、metrology、measure、OCR、颜色空间与分类模型的适用边界。
- `vector_angle_to_rigid`、`hom_mat2d_invert`、`affine_trans_region`、`affine_trans_contour_xld` 等二维变换。
- `HalconRuntimePaths`、动态符号、license、tuple 和句柄清理。

#### AI 推理

- 模型、标签、输入尺寸、量化格式、类别数和后处理协议必须匹配。
- 本地进程或远程 SSH 调用的非交互认证、参数转义、超时、取消和临时文件生命周期。
- 推理输出协议、bbox 坐标系、ROI 裁剪后的坐标回填、置信度和 NMS 语义。
- RK 等边缘设备的版本探测、能力协商和可诊断兼容策略。

#### 配置、模型和测试

- JSON schema 版本、默认值、旧配置迁移、未知版本拒绝和稳定 `toolId` 引用。
- 模型包版本、输入签名、参数哈希、参考图哈希、`empty/stale/ready/invalid/unsupported` 生命周期。
- 合成图单元测试、固定图像回归、Dialog offscreen 测试、Runner smoke 和现场数据验收。

### 2.3 核心技术红线

- 除 `AiDetectionRunner` 等明确的 AI 桥接算子外，视觉核心算法必须使用本机 HALCON 已有算子、类或过程。
- OpenCV 只可用于采集、图像容器、显示或必要格式桥接，不得替代 HALCON 核心视觉算法。
- 实现新 Runner 前必须确认 HALCON runtime、license 和所需符号。能力缺失时停止算法实现并记录阻塞，不得静默换用其他算法。
- 算法输入必须是未绘制 Overlay 的原始图像。ROI 框、Mask 填充、文字、得分和 OK/NG 只属于显示层。
- HALCON 异常、AI 设备异常和配置错误必须通过稳定错误码返回，不得崩溃或伪装成普通 NG。

## 3. 标定、定位和位置修正

### 3.1 两层标定

本项目中的“标定”分为两层，两者组合使用但职责独立。

#### 相机/坐标系标定

目标是建立像素坐标、相机坐标或物理坐标之间的映射。开发前必须在功能专项文档中明确：

- 标定类型：像素当量、平面标定、相机内参/畸变、手眼标定中的哪一种。
- 输入物：标定板类型、点位、机械位姿、相机参数和图像数量。
- 输出物：映射或标定参数、坐标系名称、单位、版本、标定时间和质量指标。
- 精度标准：重投影误差、像素/毫米误差、工作平面范围及复验方式。
- 失效条件：相机、镜头、焦距、分辨率、安装位置或工作距离变化。

当前代码仅能看到相机参数界面的“快速标定”入口，没有独立 `ToolType` 和完整生产闭环。因此现阶段应把相机标定标为前置能力，不能在没有专项设计和验证的情况下声明已完成。

#### 基准姿态标定

目标是在参考图上执行同一个模板定位实例，保存基准位姿：

```text
referencePose = {x0, y0, angle0}
```

运行时由同一定位实例产生：

```text
runPose = {x, y, angle}
```

基准姿态必须绑定稳定的模板定位 `toolId` 和明确输出键，不得绑定工具序号或显示文字。

### 3.2 数据流与职责

```text
相机/坐标系标定
        ↓ 可选的像素/物理坐标映射
参考图 ──模板定位──> referencePose
当前帧 ─模板定位──> runPose
        ↓
位置修正
        ↓
referenceToRunHomMat2D / runToReferenceHomMat2D
        ↓
下游工具的 ROI、Region 或 XLD 变换
```

- 模板定位只负责建模、查找并输出当前目标位姿，不计算下游修正矩阵。
- 位置修正消费基准位姿和运行位姿，输出双向矩阵、平移量、角度差、来源 ID 和应用状态。
- 下游工具的 ROI 定义在基准图坐标系时，使用 `referenceToRunHomMat2D` 变换到当前帧。
- 每个消费工具第一版只选择一个最终位置修正来源，禁止重复叠加方案级全局修正与局部工具修正。
- 多匹配默认使用模板定位的显式主结果；若现场需要最近邻或编号跟踪，必须新增明确策略，不能随机选择。

### 3.3 失败传播

| 场景 | 要求 |
| --- | --- |
| 定位未找到或数量判定 NG | 位置修正返回来源无效，不沿用上一帧位姿 |
| 来源被删除、禁用或位于消费工具之后 | 返回稳定的来源错误，保留原 ID 供诊断，不静默回退 |
| 基准姿态未创建 | 返回基准缺失，不生成矩阵 |
| 矩阵方向不明或数据非有限 | 返回配置/计算错误，禁止下游标记已应用 |
| 下游变换失败 | 当前工具执行失败或按方案策略中止，不使用未修正 ROI 冒充成功 |

## 4. 标准开发流程与阶段门禁

每一阶段都必须记录输入、动作、输出、完成证据和阻断条件。未通过当前门禁不得进入下一阶段。

### 阶段 0：任务卡与信息对齐

**输入**：用户需求、截图、样例图、现场限制和已有功能状态。

**动作**：

1. 写清目标场景、输入、输出、边界、依赖和明确不做的内容。
2. 列出正常路径、异常路径和可复现验收标准。
3. 区分已知事实、待确认问题和可安全采用的假设。
4. 对跨工具任务拆成可独立验收的工作包。

**输出**：功能专项需求或设计草案。

**完成证据**：目标、输入、输出、边界和验收均能被第三方复述。

**阻断条件**：缺失信息会改变算法路线、配置合同、坐标系、模型格式或验收结果。

### 阶段 1：基线审计

**输入**：目标工具名、所属工具族和仓库当前状态。

**动作**：

1. 执行 `git status --short`，识别用户已有改动，不清理、不回退无关文件。
2. 检查 `ToolType`、工具库入口、创建/编辑分支和 Adapter 注册。
3. 检查 Dialog、配置保存回显、Runner、结果 Overlay、smoke 和功能文档。
4. 对照历史报告时标记日期，重新以代码和测试确认事实。
5. 列出现有可复用公共能力和必须保持的兼容行为。

**输出**：证据化现状表、差距清单和允许修改的文件范围。

**完成证据**：每项“已有/缺失”均能指向代码、测试或运行证据。

**阻断条件**：工作区改动与目标文件重叠且无法安全区分，或功能归属不明确。

### 阶段 2：算法和运行环境可行性

**输入**：预期输入、输出、精度、性能和异常要求。

**动作**：

**HALCON 工具动作**：

1. 列出候选算子、输入输出、坐标约定和资源句柄。
2. 通过 `HalconRuntimePaths` 验证 runtime 和动态库路径。
3. 用最小独立程序确认 license、关键符号和核心算子行为。
4. 验证空输入、无目标、参数边界和资源清理。

**AI 工具动作**：

1. 固化模型、标签、类别数、输入尺寸、量化格式和后处理协议。
2. 确认本地或远程设备、认证方式、脚本版本及超时预算。
3. 使用固定图片跑通命令行基线，记录原始 stdout/stderr 和结果文件。
4. 明确版本不匹配时是拒绝、能力降级还是临时兼容，并保证可诊断。

**输出**：算法接口表、可行性实验和已确认的技术路线。

**完成证据**：核心能力在当前环境得到真实结果，或形成明确的外部阻塞报告。

**阻断条件**：HALCON 所需能力缺失；AI 模型、协议或设备不一致；算法精度目标未定义。

### 阶段 3：功能专项设计

**输入**：已确认需求、基线审计和算法可行性。

**动作**：在 `docs/FID/<工具名>/` 固化以下合同：

- 工具类型、入口、Dialog 页面与交互状态。
- `ToolConfig.params`、`judgeRule`、版本与旧配置迁移。
- ROI、Mask、坐标系、归一化方式和位置修正来源。
- Runner 输入、算法链、结果字段、Overlay 和错误码。
- 模型创建、失效、导入、导出、删除和旧模型策略。
- 正常、异常、回归、性能和人工测试矩阵。

**输出**：可直接实施且无歧义的功能设计。

**完成证据**：Dialog、Adapter、Runner 和测试可以仅依据设计独立实现。

**阻断条件**：同一字段存在两个语义、矩阵方向不明、模型兼容策略未确定或错误状态不可区分。

### 阶段 4：测试先行与最小夹具

**输入**：功能设计和算法接口。

**动作**：

1. 先创建最小 Runner/Adapter smoke，使用合成图或固定测试图。
2. 首先验证测试在功能缺失时失败，避免无效断言。
3. 最小用例至少覆盖成功、无目标、空图、无效 ROI、参数错误和 runtime/license 异常。
4. 模型工具增加无模型、旧版本、损坏包、stale 和重建用例。
5. 位置修正工具增加来源缺失、基准缺失、方向、逆矩阵和失败传播用例。
6. AI 工具增加解析、超时、认证失败、设备离线和协议不兼容用例。

**输出**：可重复运行的失败基线和预期断言。

**完成证据**：测试能准确暴露尚未实现的目标行为，而不是因夹具错误失败。

**阻断条件**：只能依赖不可重复的相机现场，或预期结果无法量化。

### 阶段 5：最小纵向闭环实现

**输入**：已批准设计和失败测试。

**动作**：按以下顺序完成纵向闭环。

1. 完成 `ToolType`、分类和工具库入口。
2. 完成 Dialog 的最小配置、保存、取消和重新打开回显。
3. 完成 Adapter 的严格解析、默认值和错误转换。
4. 完成独立 Runner，不复用语义不同工具的核心算法。
5. 在 `ToolEngine` 注册 Adapter，并输出统一 `ToolResult`。
6. 显示 ROI、真实结果 Overlay、OK/NG、关键数值和耗时。
7. 让阶段 4 的测试通过，再扩展高级参数。

**输出**：一条真实、可保存、可重开的最小生产路径。

**完成证据**：工具可见、新建、保存、重开、编辑、运行并显示真实结果。

**阻断条件**：核心步骤仍用占位结果、硬编码假数据或其他算法静默代替。

### 阶段 6：UI、ROI 和异步交互完善

**输入**：最小纵向闭环。

**动作**：

- 对齐现有工具 Dialog 的标题栏、参数卡、预览区、工具栏和底部按钮。
- ROI/Mask 使用单一活动编辑状态；绘制状态与已保存几何数据分离。
- 所有坐标走 `view → scene → 原图像素 → 归一化` 合同。
- 结果 Overlay 与配置编辑 Overlay 分层，清理编辑态时不删除运行结果。
- 异步 worker 只捕获值快照；关闭、参数变化和新请求使旧结果失效。
- 连续运行只发布当前代次结果，失败帧清空上一帧临时结果。
- 纯图标按钮提供明确 tooltip，普通操作不得触发 `accept`、`reject` 或程序退出。

**输出**：稳定且与项目风格一致的交互闭环。

**完成证据**：offscreen UI smoke 与关键场景人工操作均无崩溃、误关闭、坐标漂移或旧结果覆盖。

**阻断条件**：算法输入来自带标注预览图；缩放后 ROI 改变；关闭窗口后回调仍写 UI。

### 阶段 7：模型与数据生命周期

本阶段适用于模板定位、颜色、OCR、注册类和 AI 模型工具。

**输入**：已经跑通的最小算法闭环、模型合同、参考数据和旧模型样本。

**动作**：

1. 为模型定义 schema 版本、算法、特征维度、输入签名和参数哈希。
2. 明确 `empty/stale/ready/invalid/unsupported` 状态及状态迁移。
3. 参考图、特征参数或输入格式变化时使模型 stale，禁止静默继续生产运行。
4. 导入时严格验证，导出时保证包完整；删除时清理缓存和引用。
5. 旧模型只按已验证策略迁移或要求重训，不新增未经证明的自动兼容分支。
6. 训练图、参考图、当前帧和预览缩略图保持来源可追踪，显示标注不写回模型输入。

**输出**：可诊断、可恢复、可迁移的模型生命周期。

**完成证据**：模型创建、重建、保存、重开、导入、导出、失效、损坏和删除均有测试。

**阻断条件**：模型状态与参数不一致仍可运行，或旧模型被无提示降级。

### 阶段 8：运行上下文和位置修正接入

**输入**：稳定的定位输出和消费工具 ROI 合同。

**动作**：

1. 使用稳定 `toolId` 和输出键建立前序依赖，禁止后向引用。
2. `ToolEngine` 按顺序把当前帧前序 `ToolResult` 放入运行上下文。
3. 位置修正失败时不发布 `positionCorrectionApplied=true`。
4. 消费工具使用 HALCON 变换 ROI/Region/XLD，并在 payload 中记录来源、矩阵方向和应用状态。
5. 增加删除、禁用、重排、复制、来源 NG 和当前帧缺失测试。

**输出**：可验证的“定位 → 修正 → 检测”链路。

**完成证据**：带已知平移/旋转的合成图中，下游 ROI 和结果按预期移动，来源失败时链路明确阻断。

**阻断条件**：使用工具序号、显示文案或上一帧缓存结果建立依赖。

### 阶段 9：异常、资源和性能收口

**输入**：功能闭环、异常矩阵、性能目标和运行环境约束。

**动作**：

- 区分“算法执行成功但判断 NG”和“执行失败”。
- 所有返回路径释放 HALCON 对象、模型句柄、文件、进程和临时目录。
- 设定超时和取消语义；AI 子进程或远程命令不可无限等待。
- payload 保留有效诊断，不记录密码、API Key 或其他敏感认证信息。
- 连续运行验证内存、句柄、线程和临时文件数量不会无界增长。
- 记录单帧耗时、模型加载耗时和必要的性能预算。

**输出**：稳定错误语义和资源管理证据。

**完成证据**：异常矩阵全部可复现，长时间运行无明显资源增长。

**阻断条件**：崩溃、死锁、无限等待、句柄泄漏、敏感信息进入日志或错误状态无法定位。

### 阶段 10：自动化构建与回归

**输入**：本次变更、专项 smoke、相邻工具回归清单和可用构建环境。

**动作**：

优先使用影子目录，避免污染源码：

```bash
mkdir -p build
cd build
/home/tt/Qt/5.15.2/gcc_64/bin/qmake ../qt_ui_test.pro
make -j$(nproc)
```

验证顺序：

1. Runner/Adapter 专项 smoke。
2. Dialog offscreen smoke。
3. 位置修正、模型生命周期或 AI 桥接专项测试。
4. 同工具族相邻功能回归。
5. 主工程 qmake 和 make。
6. `git diff --check`。

测试命令、环境变量、license 状态、退出码和关键输出必须写入验证记录。只写“测试通过”不构成证据。

**输出**：专项测试、回归测试、主工程构建和差异检查记录。

**完成证据**：所有必跑命令均有本次新鲜输出、退出码和失败数，且结果与功能文档一致。

**阻断条件**：专项用例失败、主工程无法链接、依赖工具回归失败或验证环境无法代表目标运行环境。

### 阶段 11：人工验收

**输入**：通过自动化验证的候选版本、代表性图像/模型和验收步骤。

**动作**：

至少检查：

- 工具入口可见，分类和名称正确。
- 新建、保存、取消、重新打开、编辑、复制、删除和重排。
- 基准图、当前图、相机连续运行和停止。
- 所有 ROI/Mask 类型、缩放、平移、重绘、切换和清理。
- OK/NG、类别、分数、数量、位姿、ROI、Overlay 和耗时。
- 空图、无效 ROI、无模型、来源失效、设备离线和超时。
- 关闭窗口、快速连续点击、切换工具和方案重载不崩溃。

人工验收应记录环境、操作步骤、期望、实际结果和截图或日志位置。

**输出**：逐项人工验收记录和未通过项清单。

**完成证据**：关键交互、结果显示和异常路径均由验收人员实际操作并留存结果。

**阻断条件**：关键操作崩溃、配置不能回显、结果不可解释，或现场数据与自动化结论冲突。

### 阶段 12：交付收口

**输入**：代码及文档差异、全部验证证据、成熟度结论和剩余风险。

**动作**：

- 更新对应 `docs/FID/<工具名>/` 的设计、实现状态和验证记录。
- 新工具登记到 `docs/FID/Function_Docs.md`。
- 分析/修复报告放入 `docs/analysis/`。
- 只有确需交接时更新对应功能目录下的 `HANDOFF.md`。
- 检查提交范围，不提交构建产物、日志、手工备份或无关文件。
- 把遗留问题写成可验证的下一动作，不能把未实现能力描述为已完成。

**输出**：范围收敛的交付差异、功能验证记录、更新后的专项文档和准确的成熟度结论。

**完成证据**：代码、测试、文档和成熟度结论一致，第三方能复现验证结果。

**阻断条件**：验证证据缺失、文档与代码矛盾、未实现能力被标记完成，或交付范围混入无关修改和构建产物。

## 5. 统一配置与结果合同

### 5.1 配置原则

- 字段命名稳定、语义单一，百分比、角度、像素、归一化坐标和物理单位必须明确。
- 新 schema 必须有版本；旧字段缺失时只使用文档化默认值。
- 未知版本默认拒绝或进入 `unsupported`，不得被一次保存悄悄改写成当前版本。
- 跨工具引用使用稳定 `toolId`；显示名称只用于 UI。
- 运行期数据、底层句柄、当前得分和临时 Overlay 不写入 `ToolConfig`。

### 5.2 `ToolResult` 最小语义

所有工具的 payload 至少应能表达：

```text
status
message
measurementValid
passed
roi / effectiveRegion
关键测量或识别结果
elapsedMs
errorCode
errorMessage
positionCorrectionRequested
positionCorrectionApplied
positionCorrectionSourceId
warnings
```

统一判断：

- 核心算法成功完成但没有目标、分数不足、类别不符或数量超限：`success=true`，由 `ok/passed` 表达 NG。
- 空图、配置错误、模型损坏、HALCON 异常、AI 调用失败：`success=false`、`ok=false`，并返回稳定错误码。
- 部分能力暂不支持时返回明确的 `unsupported` 信息，不切换到语义不同的算法。

## 6. 工具族专项 SOP

### 6.1 有无工具

适用：Pattern、Blob、Circle、Edge、Line、Contour Presence。

开发和优化时逐项确认：

- ROI 和 Mask 是否真正进入 HALCON 的 region/domain，而不只是显示。
- 方向、极性、边缘过渡、测量方向和角度坐标系是否与 UI 文案一致。
- “存在为 OK/不存在为 OK”、数量范围和最低分等判断是否独立于执行成功。
- 无目标是否是正常测量结果，空图和无效 ROI 是否是执行错误。
- Overlay 是否来自真实模型轮廓、测量区域、边缘点、拟合线或目标区域。
- 位置修正是否真实改变检测区域，并在 payload 中说明应用状态。
- 合成图是否覆盖横/竖、黑到白/白到黑、边界、多个目标和无目标。

优化顺序建议：先统一 ROI/Mask 与位置修正，再修各 Runner 参数语义，最后统一 Overlay 和 UI 回归。

### 6.2 AI 工具

适用：AI Detection、AI Classification 及其本地或 RK 推理桥接。

检查项：

- 模型、标签、类别数、输入尺寸、量化格式和设备 runtime 完全匹配。
- UI 参数必须明确哪些传给设备、哪些在 V2 后处理；未生效参数必须给 warning。
- stdout/stderr 解析使用版本化协议，不依赖容易变化的自然语言日志。
- ROI 裁剪后，bbox 必须按裁剪偏移映射回原图，并保留像素与归一化坐标。
- 阈值、NMS、类别、宽高、边界和最大数量过滤顺序固定并可测试。
- SSH 使用非交互认证，命令参数安全传递，超时后终止子进程并清理临时文件。
- 旧脚本兼容必须显式记录协议版本和告警；不能让旧协议长期静默成为默认生产路径。
- 设备离线、认证失败、模型缺失、输出损坏和结果图回传失败分别返回可定位错误。

### 6.3 字符识别

检查项：

- 字符 ROI、字符方向、行/列顺序、预处理和字符分割规则明确。
- OCR 分类器、字库或训练文件存在且版本匹配。
- 输出保留原始文本、规范化文本、逐字符置信度、整体得分和字符区域。
- 空字符串、低置信度、未支持字符与执行错误分开。
- 多行、旋转、低对比、字符粘连/断裂和 ROI 越界进入固定回归集。
- 补充独立 OCR Runner/Adapter smoke，不能只依赖主程序人工测试。

### 6.4 颜色比较

检查项：

- 使用原始颜色模式、像素格式、位深、白平衡等输入元数据，不能根据显示后的三通道图猜测来源。
- 模板 ROI/Mask 与检测 ROI/Mask 独立，`sync` 模式也要明确复用哪些几何。
- 参考图、提取参数和输入签名变化时模型进入 stale；测试运行不得隐式重建。
- 特征提取、直方图和评分全部使用已确认的 HALCON 算子链。
- 光照补偿有明确启用条件、范围、截断比例和失败诊断。
- 异步建模与检测使用独立代次；旧结果不得覆盖新模型或关闭后的 Dialog。
- 特征可视化只消费运行诊断，不写回模型或影响最终得分。

### 6.5 颜色识别

检查项：

- 标签、样本、ROI 图像、特征配置和模板包能保存、回显、导入和导出。
- 所有样本特征维度与运行查询一致；不一致时明确拒绝模型。
- 类别预测、相似度/分数、拒识和最终判断规则相互独立。
- 模板修改、参考图变化和特征参数变化触发正确的模型失效。
- 样本缩略图来自原始 ROI 裁剪，不能包含框线和文字。
- 固定回归集覆盖同类色差、异类相似色、亮度变化、Mask 和空样本。

### 6.6 注册分类

检查项：

- 训练会话保存注册图、类别、ROI 和名称，重开后可继续训练。
- 特征合同包含维度、归一化、有效值检查和版本。
- 模型包完整性、KNN/分类句柄、类别映射和统计文件一致。
- 旧 schema 只展示、导出、删除或重训；未经验证不得直接运行。
- 低相似度、候选差距不足和超出类内半径等拒识原因分别输出。
- 正常、拒识、异常和中途返回都只清理一次 HALCON 句柄。
- 位置修正字段只有在真实变换后才能标记已应用。

### 6.7 注册目标检测

当前应按“从占位到真实闭环”开发：

1. 先固定标注格式、类别、矩形/多边形 ROI、训练输入和模型包合同。
2. 完成真实训练或明确外部训练桥接，并保存可验证的模型元数据。
3. 新增独立 Adapter 和 Runner，不把注册分类结果包装成目标检测。
4. 输出每个目标的类别、得分、bbox/轮廓、数量和 Overlay。
5. 补齐无模型、空标注、损坏模型、无目标、多个目标和位置修正测试。
6. 只有入口、训练 Dialog 或模型管理界面时，成熟度保持“界面占位”。

### 6.8 模板定位与位置修正

检查项：

- 模板缓存签名包含参考图、模板 ROI 和所有建模参数。
- 自动/手动对比度、层级、角度、缩放、最大重叠和匹配数量语义清晰。
- 多匹配结果排序稳定，顶层主位姿和全部候选同时输出。
- `x=Column`、`y=Row`、角度单位和正方向在所有层一致。
- 双向矩阵名称、方向和用途明确，并用已知平移/旋转验证。
- 当前帧定位失败时立即阻断修正，不复用陈旧位姿。
- 下游 ROI、region 和 XLD 使用合适的 HALCON 变换接口。

## 9. 推荐实施路线

不要把全部工具合成一次超大改动。按以下五个工作包推进，每个工作包独立构建、测试、评审和交付。

### 工作包 A：公共合同与回归基线

- 统一 `ToolResult` 最小语义、错误分类和位置修正诊断字段。
- 建立固定回归图集、测试清单和证据模板。
- 审计各工具的 ROI/Mask、原始图与 Overlay 分层。
- 形成工具成熟度看板，不以 UI 完成度替代生产闭环。

### 工作包 B：标定、模板定位与位置修正

- 先完成位置修正运行上下文、稳定引用、矩阵方向和失败传播。
- 打通“模板定位 → 位置修正 → 一个代表性消费工具”的真实链路。
- 再把位置修正公共能力批量接入其他有无、颜色、OCR 和分类工具。
- 相机标定另立专项设计，不与基准姿态标定混用配置。

### 工作包 C：有无工具统一优化

- 统一 ROI/Mask、存在性/数量判定、位置修正和 Overlay 语义。
- 逐个复核 Pattern、Blob、Circle、Edge、Line、Contour 的 HALCON 参数方向。
- 每完成一个工具即运行同族回归，避免公共改动破坏其他 Runner。

### 工作包 D：识别工具收口

- OCR 先补自动化基线。
- 颜色比较保持 V2 合同，重点做位置修正和真实相机回归。
- 颜色识别先收敛唯一生产算法与模型合同。
- 注册分类完成现场拒识与重训验证。
- 注册目标检测作为独立开发任务补齐真实算法闭环。

### 工作包 E：AI 检测与分类

- 先版本化 RK 调用协议并验证真实 bbox、阈值和错误路径。
- 收敛远程临时文件、认证、超时和取消行为。
- AI 分类在模型与设备路线确定后，从最小 Adapter/Runner 闭环开始。
- 旧脚本兼容仅作为可观察的迁移期能力，并设退出条件。

推荐执行顺序为 `A → B → C → D → E`。位置修正先于批量工具优化，可减少每个消费工具重复实现坐标变换的风险；AI 设备协议独立性较高，可在人员允许时与 C/D 并行，但不能共享未稳定的公共接口。

## 10. 常见风险与禁止事项

- 不根据旧截图或旧报告直接宣布当前功能完成。
- 不为追求统一而重写无关公共 UI、配置结构或算法链路。
- 不复用语义不同工具的 Runner 充当新工具核心算法。
- 不把“没有目标”与“算法执行失败”混为同一状态。
- 不在来源失败后沿用上一帧位姿、bbox、类别或得分。
- 不把工具序号、名称或 UI 文案作为跨工具稳定引用。
- 不让训练图、参考图、检测图和带 Overlay 的预览图相互污染。
- 不让模型参数已变化时继续使用旧模型而不标记 stale。
- 不让 AI 兼容回退隐藏未生效的阈值、NMS 或标签协议。
- 不提交 `*.o`、`moc_*.cpp`、`ui_*.h`、Makefile、可执行文件、日志或备份文件。
- 不把单功能的临时实现细节继续堆入本 SOP；它们应回到对应 FID 文档。

## 11. SOP 自检清单

每次修改本 SOP 或依据它交付功能时检查：

- [ ] 目标工具已归入正确工具族。
- [ ] 当前成熟度有代码、测试和人工证据支撑。
- [ ] 阶段输入、动作、输出、证据和阻断条件完整。
- [ ] HALCON 红线及 AI 例外没有被弱化。
- [ ] 相机标定与基准姿态标定职责未混淆。
- [ ] 正常 NG 与执行失败语义分开。
- [ ] ROI/Mask、坐标系和矩阵方向可验证。
- [ ] 模型和异步生命周期有明确状态及测试。
- [ ] 构建、smoke、人工验收和现场数据均有记录。
- [ ] 文档、代码和当前成熟度结论一致。
- [ ] 交付范围不包含构建产物、日志、备份或无关改动。
