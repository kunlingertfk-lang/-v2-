# 非工具级窗口无黑屏切换修复清单

## 1. 问题说明

当前方案编辑流程中的相机参数、基准图、工具列表和输出页面分别以独立顶层 `QDialog` 运行。页面切换时，现有链路会创建新窗口、重新绑定父窗口、执行窗口适配与最大化、显示新窗口，再关闭旧窗口。

在新窗口完成第一次绘制之前，Linux 窗口管理器或合成器可能短暂显示尚未填充的原生窗口缓冲区，表现为整窗闪黑、黑屏一帧或窗口抖动。右侧预览控件默认使用黑色背景，会进一步放大视觉感受。

涉及的现有入口主要包括：

- `PlanDialogUtils::showWindowFromWidget()`
- `PlanDialogUtils::showDialogFromWidget()`
- `PlanDialogUtils::replaceDialog()`
- `MainWindow::openCameraParamsDialog()`
- `MainWindow::openToolsDialog()`
- 四个方案流程页面的左侧导航槽函数

## 2. 修复目标

- 打开方案设置时不出现整窗黑屏或普通窗口到最大化窗口的跳变。
- 在相机参数、基准图、工具列表和输出页面之间切换时不创建新的顶层窗口。
- 左侧流程栏、顶部标题栏和窗口外框在切换过程中保持固定。
- 切换页面时保留当前配置保存、回显、相机预览、工具链同步和输出设置逻辑。
- 不修改工具级对话框的打开方式、样式作用域和算法链路。
- 支持不同显示分辨率及系统缩放比例。

## 3. 范围边界

### 3.1 本次重构范围

- 方案编辑固定外壳窗口。
- 相机参数页面。
- 基准图页面。

- 输出页面。
- 左侧流程导航。
- 非工具级页面之间的状态保存与页面切换。

### 3.2 明确不修改

- 颜色识别、颜色比较、模板定位、圆有无等工具级页面。
- 颜色模板、训练、模型管理等工具内部弹窗。
- 工具级公共 QSS 和控件视觉规范。
- `ToolConfig` 字段语义。
- Adapter、Runner、HALCON 算法实现。
- 工具测试运行、ROI 和结果判断逻辑。

## 4. 推荐结构

新增一个长期存在的方案编辑外壳，外壳只创建一次并负责窗口状态、公共标题栏、公共流程导航和页面容器。

```text
SchemeSetupWindow / SchemeSetupDialog
├── 公共标题栏
├── 公共方案操作栏
├── 公共左侧流程导航
└── QStackedWidget
    ├── CameraParamsPage
    ├── ReferenceImagePage
    ├── ToolsPage
    └── OutputPage
```

页面切换统一使用：

```cpp
stackedWidget->setCurrentWidget(targetPage);
```

工具配置窗口继续使用独立模态 `QDialog`，由工具页面打开，不加入 `QStackedWidget`。

完成证据：任意导航入口的行为一致，保存失败不会错误切页，正常切页不丢失数据。

## 7. 风险与控制措施

| 风险 | 控制措施 |
| --- | --- |
| 切页后配置未保存 | 所有导航统一经过 `commitPageState()`，失败则禁止切页 |
| 工具链未同步到主界面 | 工具页提交成功后立即调用现有同步入口 |
| 相机信号重复连接 | 信号只在页面构造时连接一次，进入/离开仅控制刷新状态 |
| 隐藏页面继续高频刷新 | 页面离开时暂停预览重绘和定时任务 |
| 页面嵌入后 QSS 被误命中 | 不为外壳及流程页设置 `toolLevelStyle=true` |
| 工具级样式受到影响 | 工具配置对话框继续通过 `applyToolLevelStyle()` 独立打开 |
| 不同分辨率出现挤压 | 外壳固定导航宽度，内容区使用伸缩策略并执行三档分辨率验证 |
| 重构范围失控 | 分阶段提交，每阶段保持可构建、可运行、可回退 |

## 9. 回退策略

- 每个阶段单独提交，禁止将窗口外壳、页面业务重写和工具级修改混在同一提交。
- 新外壳完成前保留旧入口，但通过单一开关选择新旧流程，不允许两套流程同时工作。
- 若页面嵌入阶段出现阻塞，可回退到旧入口，不修改 `ToolConfig` 数据格式。
- 不通过删除或清空现有 QSS 的方式解决窗口闪黑。
- 不使用固定延时、强制 `processEvents()` 或将黑色背景改成白色来掩盖问题。

## 11. 实施记录（2026-08-05）

### 11.1 已完成

- 新增 `SchemeSetupWindow` 和对应 `.ui`，由单个长期存在的原生窗口承载四个流程页。
- 相机参数、基准图、工具列表、输出页面均作为 `QStackedWidget` 子页面创建；嵌入状态下不再设置 `Qt::Window`。
- 四个流程页的导航统一改为调用宿主 `showSetupPage()`，切换前继续执行各页面原有保存/提交逻辑。
- 四个流程页之间已移除直接创建下一流程对话框和 `replaceDialog()` 的切换路径。
- 主界面进入相机参数或工具流程时复用同一个 `SchemeSetupWindow`；关闭后仅隐藏，下一次打开继续复用，不销毁并重建原生窗口。
- 各页面增加 `prepareForDisplay()`，进入时刷新方案、基准图、工具快照或输出状态。
- 工具页面保存成功后通过 `toolStateCommitted` 立即同步主界面运行态，并继续保留保存失败不更新的约束。
- `PlanDialogUtils` 的嵌入判定仅允许四个流程页命中；工具配置对话框即使由工具页打开，仍保持独立顶层窗口。
- 新宿主未设置 `toolLevelStyle=true`，没有扩大工具级 QSS 的作用范围。

实现上保留了四个现有页面的 `.ui` 内容和对象名，没有在本轮物理拆除页面内部已有的标题栏、流程栏控件。这样可避免大范围重做布局；消除黑屏所依赖的关键条件是原生顶层窗口固定、页面仅在其内部切换。
