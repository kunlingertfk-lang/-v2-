# ROI 裁剪边界少一行或一列像素

## 基本信息

- 发现日期：2026-08-05
- 修复日期：2026-08-05
- 状态：已修复
- 影响模块：颜色识别模板样本、颜色比较模板预览、注册分类训练 ROI 预览、注册分类检测训练 ROI 预览
- 严重程度：中；颜色识别持久化的 GMM 原始 ROI 会直接受影响

## 问题现象

ROI 绘制坐标能正常按原图归一化保存，但当 ROI 的左上起点映射到非整数像素位置时，裁剪图片可能少包含右边界一列像素或下边界一行像素。

在当前 `projects/scheme_1` 中以 1448×1086 基准图校验，9 个已保存颜色 ROI 样本中有 6 个样本的保存尺寸比“完整覆盖 ROI 的像素外接矩形”少 1 行或 1 列。

## 根因

旧实现按以下方式计算裁剪矩形：

```text
left   = floor(roi.x * imageWidth)
top    = floor(roi.y * imageHeight)
width  = ceil(roi.width * imageWidth)
height = ceil(roi.height * imageHeight)
```

左上角和宽高被分别取整。当 `roi.x * imageWidth` 或 `roi.y * imageHeight` 带有小数时，宽高中没有计入左上边界向外扩展的部分，因此右边或下边可能少一个像素。

注册分类的两处预览还使用了 `qRound`，同样不能保证包含所有与连续 ROI 相交的边界像素。

## 影响范围

- 颜色识别：影响 `gmmRoiImagePngBase64` 和 `roiImagePngBase64`。GMM 建模及后续 HSV 特征重建会使用已裁剪的持久化 PNG，因此是实际训练输入问题。
- 颜色比较：影响模板原始 ROI 图的像素边界。
- 注册分类与注册分类检测：影响 ROI 预览卡片。注册分类实际训练仍传递完整原图与归一化 ROI，特征提取器原本已按端点正确取整，不受该预览缺陷影响。

## 修复方案

1. 在 `src/frame/RoiGeometry.h` 增加共享的 `coveringPixelRect(...)`，将连续归一化 ROI 转为完整覆盖它的半开像素矩形。
2. 统一边界语义：左/上端点使用 `floor`，右/下排他端点使用 `ceil`，最后裁剪到图像边界。
3. 颜色识别的 QImage 缩略图裁剪和 OpenCV 原始 GMM ROI 裁剪使用同一矩形，保证两份样本尺寸一致。
4. 颜色比较与两个注册训练预览入口同步改用共享转换。

修复后的计算合同为：

```text
left            = floor(roi.left * imageWidth)
top             = floor(roi.top * imageHeight)
rightExclusive  = ceil(roi.right * imageWidth)
bottomExclusive = ceil(roi.bottom * imageHeight)
width           = rightExclusive - left
height          = bottomExclusive - top
```

## 历史数据处理

本修复只保证新裁剪结果完整。旧样本中缺失的边界像素已不在持久化 ROI PNG 内，而完整外部样本图又未作为模板数据持久化，因此不能安全自动补回。

- 已有颜色识别样本如需严格保证边界完整，应从原始图重新采样。
- 重新采样后需重建 GMM/HSV 模型。
- 禁止将已裁剪 PNG 拉伸或补边冒充原始像素。
