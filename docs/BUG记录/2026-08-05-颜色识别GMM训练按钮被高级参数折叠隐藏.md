# 颜色识别 GMM 训练按钮被高级参数折叠隐藏

## 基本信息

- 发现日期：2026-08-05
- 修复日期：2026-08-05
- 状态：已修复
- 影响模块：颜色识别模板创建/编辑窗口
- 严重程度：高；用户可以保存未建立的 GMM 模板，但该模板不能用于检测

## 问题现象

颜色识别模板选择 `CIELAB GMM` 后，“高级参数”默认折叠。实际执行训练的“建立 GMM 模型”按钮位于折叠内容内，界面上看起来像训练能力已经消失。

用户直接点击窗口右下角“完成”时，只会进入模板保存流程。由于 GMM 尚未建立，程序提示“保存后暂不能用于检测”，但界面没有提前露出完成建模所需的入口。

## 根因

`ColorTemplateDialog` 从纯代码界面迁移到 Qt Designer `.ui` 后，`advancedContentWidget` 被设置为默认隐藏，`advancedCollapseButton` 被设置为已选中（折叠态）。

旧纯代码界面的高级参数卡片默认展开，因此此次迁移改变了关键操作的默认可见性。训练槽函数、HALCON GMM 建模链路和模板持久化逻辑没有被删除。

## 功能语义

- “建立 GMM 模型”：使用当前标签和 ROI 样本执行 HALCON GMM 建模，是 GMM 模板可检测的必经步骤。
- “重新提取 HSV 特征”：HSV 参数或公共样本变化后重建 HSV 派生特征。
- “完成”：保存当前模板并关闭窗口，不隐式执行训练；模型未就绪时仍保留原有确认提示。
- HSV 的敏感度和亮度参数参与 HSV 特征合同；GMM 模式仅使用“亮度参与”选择 `a/b` 或 `L/a/b`，敏感度不参与 GMM。

## 修复方案

1. 恢复高级参数卡片默认展开，与迁移前行为一致。
2. 增加统一的高级参数展开状态同步方法，确保按钮 checked 状态、箭头和内容显隐一致。
3. 打开或切换到 GMM 模板时自动展开高级参数，保证“建立 GMM 模型”始终可发现。
4. 保留用户手动折叠能力；若重新加载 GMM 模板，则再次露出必需的建模入口。
5. 在颜色识别 GMM 生命周期 smoke 中增加默认展开、手动折叠和加载 GMM 后自动展开断言。

## 验收标准

- 新建颜色模板时高级参数默认展开。
- 选择或加载 GMM 模板时，“建立 GMM 模型”可见且可点击。
- 高级参数仍可手动折叠。
- “完成”仍只保存模板，不改变现有训练和保存语义。
- HSV/GMM 模型失效、重建、保存和生产检测链路不发生回归。
- GMM 生命周期 smoke、Qt 主工程影子构建及 `git diff --check` 通过。
