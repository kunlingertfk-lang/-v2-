## SCH-20260803-01 2026-08-03（时刻未记录） — 方案保存后主界面工具链未立即生效

### 基本信息

- 发现日期：2026-08-03
- 状态：已修复
- 影响模块：方案编辑工具页、输出页、主界面工具链运行状态
- 相关功能：顶部“保存”、输出页“完成”

### 问题现象

在工具页修改、复制或删除工具后，点击顶部“保存”：

- 当前方案已成功写入 `scheme.json`；
- 但主界面仍使用保存前的工具链内存缓存；
- 必须进入输出页并点击“完成”，新工具链才会在主界面生效。

这会造成“保存按钮无效”的用户感知，并且主界面的工具表和实际落盘配置短暂不一致。

### 根因

`ToolsDialog::saveCurrentScheme()` 只通过 `SchemeStore` 更新配置并写盘，没有同步 `MainWindow::m_schemeToolConfigs` 和主界面工具表。

原有流程中，只有输出页“完成”的 `returnToSourceMainWindow()` 会调用 `MainWindow::setSchemeTools(...)`，因此“完成”意外承担了让已保存配置进入主界面运行态的职责。

### 修复方案

1. 在 `MainWindow` 增加 `applySavedSchemeTools(...)`，专门用于更新已落盘的工具配置、预览快照、工具表和预览状态，不再次写盘。
2. `ToolsDialog` 在保存成功后立即调用该接口，使顶部“保存”同时完成“落盘 + 运行态生效”。
3. `OutputDialog` 的顶部“保存”使用同一套即时同步逻辑。
4. 输出页“完成”改为只应用已保存状态并返回主界面，不重复写盘。
5. 保存失败时不更新主界面内存工具链，继续保持原有回滚语义。

### 修复后行为

- 点击工具页或输出页顶部“保存”后，方案文件和主界面运行工具链立即一致。
- 无需再点击输出页“完成”才让配置生效。
- “完成”仍保留流程结束和返回主界面的作用。

### 验证记录

- 主工程影子构建：通过。
- `tools_dialog_actions_smoke`：通过；新增断言验证保存后 `MainWindow` 工具表立即刷新。
- `scheme_transaction_smoke`：通过。
- `git diff --check`：通过。
- 无相机环境下主界面会返回明确的相机打开失败状态，不影响本次工具链同步验证。

## SCH-20260803-02 2026-08-03（时刻未记录） — 方案设置重复点击产生多个工具流程窗口

### 基本信息

- 发现日期：2026-08-03
- 状态：已修复
- 影响模块：主界面、方案设置导航、相机参数页、基准图页、工具页、输出页
- 相关入口：主界面“方案设置”、“工具设置”

### 问题现象

在主界面快速双击或连续多次点击“方案设置”后，程序会创建多个相机参数窗口。这些窗口可以分别继续导航到基准图、工具或输出页，最终导致同时存在多个工具流程窗口。

潜在影响：

- 多个窗口同时编辑同一方案，可能相互覆盖配置。
- 多个页面同时订阅相机帧和基准图信号，增加资源消耗和生命周期风险。
- 用户无法确定哪个窗口代表当前有效的方案编辑会话。

### 复现步骤

1. 登录并进入主界面。
2. 快速双击或连续多次点击“方案设置”。
3. 观察出现多个相机参数窗口。
4. 在不同窗口中点击“工具”，可继续生成多个工具流程窗口。

### 根因

1. `MainWindow::openCameraParamsDialog()` 每次都无条件执行 `new CameraParamsDialog(this)`。
2. `PlanDialogUtils::showDialogFromWidget()` 使用 `show()` / `showMaximized()` 非模态显示方案编辑页，主窗口仍可继续接收点击。
3. `MainWindow` 没有跟踪当前活动的方案编辑窗口，也没有重复入口防护。
4. 按钮信号只连接了一次，本问题不是重复 `connect` 导致。

### 修复方案

1. 在 `MainWindow` 中使用 `QPointer<QWidget>` 跟踪当前活动的方案编辑页。
2. 主界面的“方案设置”和“工具设置”入口创建窗口前，先检查已有页面；已存在时只执行置顶和激活。
3. `PlanDialogUtils` 在显示相机、基准图、工具或输出页时，将新页注册为当前活动页，保证导航后仍对整条流程生效。
4. 页面关闭、隐藏或销毁后清理活动状态，允许用户再次正常打开。
5. 保留原有 `WA_DeleteOnClose` 生命周期，不引入手工删除。

### 修复后行为

- 双击或连续点击“方案设置”时，始终只有一个方案编辑流程窗口。
- 若当前已经切换到基准图、工具或输出页，重复点击会激活该当前页，不会回到相机页或创建新页。
- 关闭方案编辑流程后，可以再次正常打开。

### 验证记录

- `tools_dialog_actions_smoke`：通过。
- 自动化覆盖：重复入口不新建窗口、导航后跟踪新页、隐藏页不再占用活动状态。
- 主工程影子构建：通过。
- `git diff --check`：通过。
- 无相机环境下会返回明确的相机打开失败信息，不影响本次窗口单实例验证。

## SCH-20260805-01 2026-08-05 11:23 CST — 方案流程导航多页面同时高亮

### 基本信息

- 发现时间：2026-08-05 11:23 CST（UTC+08:00）
- 修复时间：2026-08-05 11:26 CST（UTC+08:00）
- 状态：已修复
- 严重程度：中（不影响配置数据和算法运行，但会错误表达当前流程位置）
- 影响模块：方案编辑固定宿主、相机参数页、基准图页、工具页、输出页的左侧流程导航
- 关联改造：非工具级窗口由多个顶层 `QDialog` 切换改为单个 `SchemeSetupWindow` 内的 `QStackedWidget` 切换

### 问题现象

在相机参数、基准图、工具和输出页面之间多次切换后，左侧流程栏会同时出现多个橙色高亮项。

例如当前实际位于“工具”页，但“相机参数”“基准图”或“输出”也可能继续保持高亮。页面标题和内容已经切换正确，只有流程导航的视觉状态与当前页面不一致。

正确行为应为：

- 相机参数页只高亮“相机参数”。
- 基准图页只高亮“基准图”。
- 工具页只高亮“工具”。
- 输出页只高亮“输出”。
- 任意时刻只能存在一个高亮步骤。

### 复现步骤

1. 从主界面进入方案设置。
2. 从相机参数页依次点击基准图、工具或输出。
3. 再通过左侧流程栏往返切换页面。
4. 观察曾经点击过的导航项可能继续保持橙色选中状态。
5. 重复切换后，多个步骤会同时显示为当前步骤。

### 原因分析

#### 直接原因

四个流程页面各自拥有一套同名导航按钮：

- `cameraStepButton`
- `referenceStepButton`
- `toolsStepButton`
- `outputStepButton`

这些 `QToolButton` 均设置了 `checkable=true`，但没有通过统一的 `QButtonGroup` 或中央状态管理保证互斥。用户点击目标步骤时，按钮会先自动切换自己的 `checked` 状态；原先处于选中状态的按钮不会被自动取消。

QSS 又统一使用 `:checked` 表示当前步骤，因此每增加一个未清除的勾选状态，界面就多出现一个橙色高亮项。

#### 为什么固定窗口改造后问题变得明显

旧实现中，每次切换流程都会创建新顶层对话框并关闭旧页面。虽然导航按钮缺少严格的互斥状态管理，但旧页面很快被关闭或销毁，错误的 `checked` 状态没有机会长期累积。

改为 `SchemeSetupWindow + QStackedWidget` 后，四个页面只创建一次并长期复用。页面隐藏不会重置内部控件，所有错误勾选状态都会被保留，重新进入页面时便显示为多项高亮。

因此，本缺陷不是 QSS 颜色规则本身错误，而是页面生命周期从“一次性创建”变为“持久复用”后，原有的隐式状态清理假设失效。

#### 保存失败时的附加问题

导航按钮的点击会先改变 `checked` 状态，然后页面才执行保存或切页。如果保存失败、切页被拒绝，而代码没有恢复高亮，目标按钮仍可能显示为当前页，造成“内容停留在原页、导航却指向另一页”的状态分裂。

### 解决方案

在固定宿主 `SchemeSetupWindow` 中统一接管流程导航的视觉状态，不再信任各页面按钮自行保存的勾选结果。

具体处理如下：

1. 每次 `showSetupPage(pageId)` 成功设置 `QStackedWidget` 当前页后，统一调用 `updateStepHighlights(pageId)`。
2. 遍历四个持久页面中的四个导航按钮，只将与当前 `pageId` 对应的按钮设为 `checked=true`，其余全部设为 `false`。
3. 更新状态时使用 `QSignalBlocker`，避免程序修正勾选状态时再次触发业务信号或导航逻辑。
4. 为所有流程导航按钮增加点击后的延迟校正：等原页面的保存和导航槽执行完毕后，根据 `QStackedWidget::currentWidget()` 再次统一高亮。
5. 如果切换成功，目标页唯一高亮；如果保存失败或切换被拒绝，当前页重新恢复唯一高亮。
6. 高亮状态由宿主中的真实当前页面决定，不由“最后点击了哪个按钮”决定。

状态合同为：

```text
QStackedWidget 当前页
        ↓ 唯一事实来源
解析 camera/reference/tools/output
        ↓
四套页面导航按钮统一重置
        ↓
仅当前步骤 checked=true
```

### 修复后行为

- 当前位于哪个流程页，就只高亮对应步骤。
- 多次往返切换不会累积选中状态。
- 关闭方案设置后重新打开，高亮与实际显示页一致。
- 保存失败或导航被拒绝时，仍高亮原页面。
- 本修复只调整导航状态，不修改页面内容、配置保存、工具级弹窗、QSS 视觉规范和算法链路。

### 验证记录

- 主工程影子构建：`qmake ../qt_ui_test.pro` 与 `make -j$(nproc)` 通过。
- `git diff --check`：通过。
- 代码检查确认高亮更新由 `SchemeSetupWindow::showSetupPage()` 统一执行。
- 代码检查确认按钮点击完成后会根据真实 `currentWidget()` 再次校正，包括切换失败路径。
- 待真机交互回归：按“相机参数 → 基准图 → 工具 → 输出 → 相机参数”循环切换，确认每一步始终只有一个高亮项。

### 思维拓展

#### 1. 生命周期改变会暴露隐藏状态

把窗口从“每次创建销毁”改为“长期复用”，不仅改变性能和绘制行为，也会改变控件状态的存续周期。以前依赖销毁自动清空的文本、选择、展开状态、定时器和订阅关系，都会变成需要显式管理的持久状态。

后续进行类似重构时，应逐项检查：

- `checked`、`currentIndex`、选中行和滚动位置是否需要重置。
- 页面隐藏时定时器、相机刷新和耗时任务是否应暂停。
- 页面重新进入时数据是否需要从模型刷新。
- 信号是否只连接一次，避免页面复用后重复回调。

#### 2. 导航控件不应同时承担业务状态源

按钮的 `checked` 只适合作为视觉投影，不应作为当前页面的唯一业务依据。更稳定的设计是让 `QStackedWidget::currentWidget()` 或明确的页面枚举成为单一事实来源，再由它驱动按钮、标题和步骤编号。

推荐关系：

```text
页面状态模型 → 当前堆栈页 → 导航高亮/标题/步骤编号
```

不推荐关系：

```text
任意按钮 checked 状态 ↔ 页面状态互相推断
```

#### 3. 互斥按钮组只能解决一部分问题

使用独占 `QButtonGroup` 可以避免同一组按钮同时选中，但无法天然处理“点击后保存失败、页面没有切换”的情况。此时按钮组已经选择了目标按钮，而实际页面仍是原页面。

因此即使后续引入 `QButtonGroup`，仍应在导航事务结束后使用真实当前页回写视觉状态。

#### 4. 导航应被视为事务

完整导航过程应包含：

```text
请求目标页
→ 校验当前页
→ 保存/提交当前页
→ 保存成功后切换堆栈
→ 刷新目标页
→ 根据真实当前页更新导航视觉
```

失败时应停留原页，并回滚所有提前产生的视觉反馈。这样不仅适用于流程栏，也适用于页签、向导步骤、树形菜单和设置中心。

#### 5. 回归测试需要覆盖序列而非单次点击

此类状态累积问题通常无法通过“打开一次、点击一次”的测试发现。后续 UI 生命周期测试应至少覆盖：

- 全流程正向切换。
- 反向切换。
- 同一页面重复点击。
- 快速连续点击。
- 保存失败后继续切换。
- 关闭并重新打开宿主窗口。
- 循环切换 20 次后检查唯一高亮和顶层窗口数量。

## SCH-20260805-02 2026-08-05 14:56 CST — 方案配置按 Esc 后嵌入页面持续空白

### 基本信息

- 发现日期：2026-08-05
- 修复日期：2026-08-05
- 状态：已修复，构建通过，待手工交互复测
- 严重程度：高
- 影响模块：方案配置外壳、相机参数页、基准图页、工具页、输出页
- 关联改造：`SchemeSetupWindow + QStackedWidget` 嵌入式页面
- 来源任务：排查颜色识别 ROI 不全 BUG（019fcfba-e665-7811-84d6-4499935942db）

### 问题现象

进入方案配置后按 Esc，窗口顶部标题栏仍然存在，但中间内容区域完全空白。退出该页面后再次进入方案配置，仍会复用同一个空白界面。

### 复现步骤

1. 从主界面进入方案配置。
2. 停留在相机参数、基准图、工具或输出任一子页。
3. 按 Esc。
4. 观察方案配置外壳没有关闭，当前内容页消失。
5. 退出并再次进入，内容仍为空白。

### 根因

1. `SchemeSetupWindow` 使用 `QStackedWidget` 嵌入四个页面。
2. 四个子页面本身仍继承 `QDialog`。
3. 焦点位于子页面时按 Esc，Qt 默认执行子 `QDialog::reject()`，只隐藏子页面，不关闭外层 `SchemeSetupWindow`。
4. 主窗口会复用已有的方案配置实例。
5. `showSetupPage()` 原先只调用 `setCurrentWidget(target)`。当目标已经是当前页但已被 `reject()` 隐藏时，该调用不会重新显示页面。

### 修复方案

1. 在 `SchemeSetupWindow` 注册窗口级 Esc 快捷键。
2. 使用 `Qt::WindowShortcut`，将 Esc 统一连接到外壳 `close()`。
3. 阻止用户只隐藏嵌入式子 `QDialog` 而留下空壳。
4. `showSetupPage()` 在切换目标页后显式调用 `target->show()` 和 `target->raise()`，兼容已经进入隐藏状态的旧实例。

### 修复后行为

- 无论焦点位于哪一个嵌入页，Esc 都关闭整个方案配置窗口。
- 再次进入方案配置时，当前目标页会恢复可见。
- 正常的相机、基准图、工具、输出步骤切换不受影响。

### 验证记录

- `git diff --check`：通过。
- 主工程 `qmake`：通过。
- `make -j4`：编译和链接成功。
- 历史会话只检查了 `smoke/dialog_lifecycle_smoke.cpp`，没有实际运行该 smoke。
- 仍需手工验证四个子页的 Esc、重新进入和正常步骤切换。
