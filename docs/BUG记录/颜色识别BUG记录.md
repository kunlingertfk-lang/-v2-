## CR-20260805-01 2026-08-05 10:23 CST — 颜色识别模板 ROI 列表固定高度导致显示不全

### 基本信息

- 发现日期：2026-08-05
- 修复日期：2026-08-05
- 状态：已修复，构建通过，待手工视觉复测
- 严重程度：中
- 影响模块：颜色识别、模板训练列表
- 来源任务：排查颜色识别 ROI 不全 BUG（019fcfba-e665-7811-84d6-4499935942db）

### 问题现象

颜色识别方案中已经添加多个模板 ROI 样本，但主配置页的“模板训练”列表只显示前两条和下一条的一部分。列表右侧出现狭小的内部滚动条，用户容易误判为 ROI 没有成功添加或保存不完整。

### 数据完整性结论

现场方案摘要显示“样本 4”，实际模板样本数组也有 4 条记录：

- 4 条样本均已写入模板数组；
- 4 条样本均带有 `roiImagePngBase64`；
- 添加成功后使用 `append` 保存样本；
- 列表重建和配置序列化均遍历全部样本，没有数量截断。

因此该问题属于显示区域裁切，不是样本数据丢失。

### 根因

- `ColorRecognitionDialog` 中模板列表可视高度约为 232 px；
- 每个 ROI 列表项高度约为 104 px；
- 一屏只能显示约 2.2 条 ROI；
- 模板列表又位于左侧外层滚动区域中，形成“外层页面滚动 + 内层列表滚动”的双层滚动。

### 修复方案

1. 新增模板列表高度计算逻辑，遍历全部列表项并累加实际行高。
2. 列表最小高度设为 118 px，保证至少一条 ROI 完整显示。
3. 列表最大高度设为 560 px，常见数量的 ROI 可直接展开。
4. 内容未超过上限时关闭列表内部纵向滚动条；超过上限后才启用。
5. ROI 卡片改为横向扩展并跟随列表宽度，不再固定为 260 px。

### 修复后行为

- 常见的 1 至 4 条 ROI 可完整展开，不再出现半条内容。
- 样本较多时列表高度不会无限增长，超过 560 px 后仍可通过内部滚动访问。
- 样本保存、序列化和算法链路未改变。

### 验证记录

- `git diff --check`：通过。
- 主工程影子构建 `qmake`：通过。
- `make -j4`：编译和链接成功。
- 历史会话未记录修复后的手工界面截图，仍需在真实界面复测不同样本数量下的高度与滚动行为。

## CR-20260805-02 2026-08-05 11:03 CST — 颜色识别 ROI 缩略图二次裁切导致形状显示不完整

### 基本信息

- 发现日期：2026-08-05
- 修复日期：2026-08-05
- 状态：已修复，构建通过，待手工视觉复测
- 严重程度：中
- 影响模块：颜色模板编辑、颜色识别模板列表
- 来源任务：排查颜色识别 ROI 不全 BUG（019fcfba-e665-7811-84d6-4499935942db）

### 问题现象

用户在原图上框选的 ROI 内包含完整圆形，但 ROI 缩略图只显示圆形的一部分。原图中的裁剪区域和样本数据均完整，只有缩略图显示发生裁边。

### 根因

缩略图目标框为横向比例，例如 72 × 48，而部分 ROI 原图的宽高比与目标框不一致。旧实现使用 `Qt::KeepAspectRatioByExpanding`：

1. 图像先等比放大到完全铺满目标框；
2. 超出目标框的部分被再次裁掉；
3. 圆形、六边形等接近边缘的内容因此显示不完整。

这是显示缩放造成的二次裁切，不是 ROI 像素裁剪错误，也不影响保存的 `roiImagePngBase64`。

### 修复方案

1. `ColorTemplateDialog::roiThumbnailForSample()` 改用 `Qt::KeepAspectRatio`。
2. 在 72 × 48 缩略框四周增加 3 px 安全边距。
3. 缩放后的图像在内容区域内居中绘制。
4. `ColorRecognitionDialog` 中的模板图标和 ROI 卡片同步改为完整等比显示。
5. 模板层级背景调整为浅灰，当前选中态使用浅橙色，避免深黑或系统蓝色块干扰缩略图查看。

### 与“ROI 裁剪边界少一行或一列像素”的区别

`ROI公共能力BUG记录.md`（ROI-20260805-01） 记录的是归一化 ROI 转像素矩形时的端点取整错误，会影响实际裁剪像素。

本问题发生在完整 ROI 图像生成之后，只影响缩略图缩放与显示。两者根因和影响范围不同。

### 修复后行为

- 圆形和其他完整轮廓在缩略图中按原比例完整显示。
- 宽高比不一致时允许留白，不再为了铺满而裁掉图像边缘。
- 原始 ROI 坐标、训练样本和算法输入保持不变。

### 验证记录

- `git diff --check`：通过。
- `qmake`：通过。
- 首次增量链接因影子目录中的旧 `ColorRecognitionDialog.o` 异常出现未定义符号；单独强制重建该对象后重新链接成功。
- `make -j4`：最终成功。
- 历史会话未记录修复后的手工截图，仍需视觉确认圆形、六边形及窄长 ROI。

## CR-20260805-03 2026-08-05 14:33 CST — 颜色模板亮度复选框误命中全局深色样式

### 基本信息

- 发现日期：2026-08-05
- 修复日期：2026-08-05
- 状态：已修复，构建通过，待手工视觉复测
- 严重程度：低
- 影响模块：颜色模板编辑、CIELAB GMM 高级参数
- 来源任务：排查颜色识别 ROI 不全 BUG（019fcfba-e665-7811-84d6-4499935942db）

### 问题现象

在颜色模板编辑窗口的 CIELAB GMM 模式下，“亮度参与（CIELAB L）”显示为整条深色控件，与周围浅色参数卡片明显不一致。正常、选中和禁用状态的视觉层级也不清晰。

### 控件识别

- 控件类型：`QCheckBox`
- 对象名：`brightnessEnabledCheckBox`
- GMM 模式文案：亮度参与（CIELAB L）

该控件只负责控制亮度通道是否参与识别，不是深色操作按钮。

### 根因

`brightnessEnabledCheckBox` 命中了作用域过宽的全局 `QCheckBox` 样式。全局规则的背景、边框或禁用态覆盖了颜色模板窗口应使用的浅色参数控件样式。

### 修复方案

为该控件增加严格作用域：

`QDialog#ColorTemplateDialog[toolLevelStyle="true"] QCheckBox#brightnessEnabledCheckBox`

并分别定义：

- 正常态：浅灰白背景、深色文字、浅灰边框；
- 选中态：橙色勾选 indicator；
- 禁用态：降低背景、边框和文字对比度。

### 修复后行为

- 控件与颜色模板参数卡片的浅色层级一致。
- 橙色只用于表达勾选状态。
- 不影响其他工具或全局 `QCheckBox`。
- 配置字段和 GMM 算法语义没有变化。

### 验证记录

- `git diff --check`：通过。
- 主工程 `qmake`：通过。
- `make -j4`：编译和链接成功。
- 尚需手工确认正常、选中和禁用三种状态。

## CR-20260805-04 2026-08-05 14:33 CST — 颜色识别 PC 导入测试图绘制 ROI 时切回基准图

### 基本信息

- 发现日期：2026-08-05
- 修复日期：2026-08-05
- 状态：已修复，构建通过，待手工交互复测
- 严重程度：高
- 影响模块：颜色识别、PC 导入测试、ROI 编辑
- 来源任务：排查颜色识别 ROI 不全 BUG（019fcfba-e665-7811-84d6-4499935942db）

### 问题现象

在颜色识别对话框中通过“PC 导入图片”加载测试图后，画布能够显示导入图；但点击矩形 ROI、圆形 ROI、整图或屏蔽区编辑入口时，画布立即切回方案基准图，导致用户在错误图像上继续编辑。

### 复现步骤

1. 打开颜色识别工具配置。
2. 从 PC 导入一张测试图。
3. 确认画布显示导入图。
4. 点击任一 ROI 编辑入口。
5. 观察画布被替换为基准图。

### 根因

`ColorRecognitionDialog::showFrameForRoiEditing()` 原先无条件按“基准图优先”重新选择图像，没有检查：

- `m_liveTestSource` 当前是否为 PC 导入测试；
- `m_liveTestFrameSnapshot` 是否保存了导入图或锁定的相机测试帧。

因此每次进入 ROI 编辑都会丢失当前测试来源的显示状态。

### 修复方案

ROI 编辑前的图像选择顺序改为：

1. 当前 PC 导入测试图快照；
2. 当前锁定的相机测试帧；
3. 方案基准图；
4. 当前相机图像。

PC 导入和相机测试帧通过 `MatImageConverter::matToDisplayImage()` 转换后继续显示；只有非测试态才回退到基准图或当前相机图。

### 修复后行为

- 在 PC 导入测试态绘制或调整 ROI 时，画布始终保持当前导入图。
- 在相机测试态编辑 ROI 时，保持锁定的测试帧。
- 非测试态仍维持原有“基准图优先、当前相机图兜底”的行为。
- 矩形、圆形、整图和屏蔽区入口使用同一来源优先级。

### 验证记录

- `git diff --check`：通过。
- 主工程 `qmake`：通过。
- `make -j4`：编译和链接成功。
- 历史会话没有记录完整的手工状态切换回归，仍需覆盖 PC 导入、相机测试、退出测试及无基准图场景。

## CR-20260805-05 2026-08-05（时刻未记录） — 颜色识别 GMM 训练按钮被高级参数折叠隐藏

### 基本信息

- 发现日期：2026-08-05
- 修复日期：2026-08-05
- 状态：已修复
- 影响模块：颜色识别模板创建/编辑窗口
- 严重程度：高；用户可以保存未建立的 GMM 模板，但该模板不能用于检测

### 问题现象

颜色识别模板选择 `CIELAB GMM` 后，“高级参数”默认折叠。实际执行训练的“建立 GMM 模型”按钮位于折叠内容内，界面上看起来像训练能力已经消失。

用户直接点击窗口右下角“完成”时，只会进入模板保存流程。由于 GMM 尚未建立，程序提示“保存后暂不能用于检测”，但界面没有提前露出完成建模所需的入口。

### 根因

`ColorTemplateDialog` 从纯代码界面迁移到 Qt Designer `.ui` 后，`advancedContentWidget` 被设置为默认隐藏，`advancedCollapseButton` 被设置为已选中（折叠态）。

旧纯代码界面的高级参数卡片默认展开，因此此次迁移改变了关键操作的默认可见性。训练槽函数、HALCON GMM 建模链路和模板持久化逻辑没有被删除。

### 功能语义

- “建立 GMM 模型”：使用当前标签和 ROI 样本执行 HALCON GMM 建模，是 GMM 模板可检测的必经步骤。
- “重新提取 HSV 特征”：HSV 参数或公共样本变化后重建 HSV 派生特征。
- “完成”：保存当前模板并关闭窗口，不隐式执行训练；模型未就绪时仍保留原有确认提示。
- HSV 的敏感度和亮度参数参与 HSV 特征合同；GMM 模式仅使用“亮度参与”选择 `a/b` 或 `L/a/b`，敏感度不参与 GMM。

### 修复方案

1. 恢复高级参数卡片默认展开，与迁移前行为一致。
2. 增加统一的高级参数展开状态同步方法，确保按钮 checked 状态、箭头和内容显隐一致。
3. 打开或切换到 GMM 模板时自动展开高级参数，保证“建立 GMM 模型”始终可发现。
4. 保留用户手动折叠能力；若重新加载 GMM 模板，则再次露出必需的建模入口。
5. 在颜色识别 GMM 生命周期 smoke 中增加默认展开、手动折叠和加载 GMM 后自动展开断言。

### 验收标准

- 新建颜色模板时高级参数默认展开。
- 选择或加载 GMM 模板时，“建立 GMM 模型”可见且可点击。
- 高级参数仍可手动折叠。
- “完成”仍只保存模板，不改变现有训练和保存语义。
- HSV/GMM 模型失效、重建、保存和生产检测链路不发生回归。
- GMM 生命周期 smoke、Qt 主工程影子构建及 `git diff --check` 通过。

### 验证记录

- `color_recognition_gmm_b2_lifecycle_smoke`：通过；覆盖高级参数默认展开、手动折叠、加载 GMM 模板后自动展开，并继续覆盖 HALCON GMM 建模与生产检测生命周期。
- Qt 主工程影子构建：`qmake ../../qt_ui_test.pro` 与 `make -j$(nproc)` 通过。
- `git diff --check`：通过。
