# 颜色模板 GMM 建模反馈与参数显隐设计

日期：2026-07-16  
状态：已确认，待实施

## 1. 问题

颜色模板选择 `cielab_gmm` 后仍显示 HSV 专属“特征类型”，容易让用户误以为二维 H/S 直方图参与 GMM。点击“建立 GMM 模型”后，当前同步建模直到结束前没有及时刷新界面；成功时只更新窗口底部状态文字，没有明确成功提示，现场表现接近“点击无反应”。

## 2. 目标与边界

- GMM 模式隐藏整个 HSV 特征类型行，切回 HSV 时恢复并保留原选择。
- 建模开始、成功、警告和失败均在建模按钮附近显示明确状态。
- 建模成功后弹出完成提示，失败继续弹出错误提示。
- 保持现有 HALCON 同步建模链，不在本次修改中引入后台线程或改变模型合同。
- 不修改颜色比较、颜色识别生产判定和 HSV/GMM 算法实现。

## 3. UI 结构

`ColorTemplateDialog` 保存特征类型行的容器指针，而不只保存下拉框指针。`updateAlgorithmUi()` 根据活动后端控制整行显隐：

```text
hsv_histogram → 显示“特征类型”标签和下拉框
cielab_gmm    → 隐藏整行
```

GMM 建模按钮下方或同行增加专用状态标签。状态颜色沿用现有 UI style role/QSS，不使用散落的硬编码业务样式：

```text
idle/building  → 中性或橙色
ready          → 绿色
warning        → 橙色
failed/invalid → 红色
stale          → 橙色
```

## 4. 建模反馈流程

点击按钮后按以下顺序执行：

1. 完成类别、sampleId、原始 ROI 和图像元数据校验；校验失败时更新按钮附近状态并弹出错误提示。
2. 设置 `m_gmmBuildInProgress=true`，禁用建模、保存和样本修改控件。
3. 按钮显示“建模中…”，状态标签显示“正在建立 GMM 模型，请稍候…”。
4. 主动刷新一次 Qt 待处理绘制事件，使同步 HALCON 调用开始前状态能够显示。
5. 同步调用现有 `buildGmmTemplateModel()`。
6. 成功时持久化现有模型字段，状态标签显示“模型已建立”或“模型已建立，样本偏少”，并弹出成功提示。
7. 失败时状态标签显示失败原因，弹出错误提示。
8. 所有结束路径恢复按钮和样本控件状态。

成功弹窗至少显示：模型状态、类别数、通道模式和建模耗时。诊断详情仍保留在现有 GMM diagnostics 区域。

## 5. 错误与状态一致性

- 预校验失败不能保留旧的“建模中”状态。
- 建模失败必须写入 `gmmModel.state=failed`、status 和 message，并立即刷新按钮附近状态。
- `ready_with_warning` 视为建模成功，但使用警告颜色和“样本偏少”文案。
- 模型参数或公共样本变化后，状态标签同步显示 stale，不弹出成功提示。
- 成功或失败弹窗关闭后，按钮附近状态继续保留，便于用户确认结果。

## 6. 验证

1. GMM 模式不显示 HSV 特征类型行，HSV 模式恢复显示且原选择不丢失。
2. 点击建模后立即看到“建模中…”和按钮禁用状态。
3. 建模成功出现成功弹窗，按钮附近保留绿色成功状态。
4. `ready_with_warning` 出现成功弹窗和橙色样本不足状态。
5. 缺类别、重复 sampleId、缺原始 ROI、解码失败和 HALCON 失败均出现红色状态与错误弹窗。
6. 建模完成后保存、样本编辑和重新建模按钮恢复正确可用性。
7. GMM B1/B2/B3 smoke、HSV Phase A 和 Qt 主工程构建继续通过。
