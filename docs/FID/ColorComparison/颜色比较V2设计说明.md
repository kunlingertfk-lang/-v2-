# 颜色比较 V2 设计说明

## 1. 文档状态

- 状态：已确认，作为颜色比较后续实现的当前有效设计。
- 确认日期：2026-07-13。
- 适用范围：颜色比较的输入契约、模板模型、HALCON 算法、配置、UI、结果、迁移与验证。
- 历史实现记录继续保留在 `color_comparison_function_implementation.md`；凡历史记录与本文冲突，以本文为准。
- 位置修正本阶段不实现，仅保留接口。
- 色谱特征本阶段不实现真实算法，仅保留不可选的产品入口和明确的 unsupported 状态。

## 2. 设计目标

颜色比较 V2 要解决以下问题：

- 修复 `histo_2dim` H/S 轴解释颠倒导致的确定性错误。
- 删除名为 Bhattacharyya、实际却是主峰覆盖率的错误语义。
- 删除 C++ Gaussian kernel、主峰经验权重和 OpenCV `compareHist` 生产旁路。
- 使完全相同的模板与检测颜色分布稳定得到 100 分。
- 支持多颜色区域的完整 H/S 联合分布比较，而不是只判断单一主色是否存在。
- 建立严格、可迁移、可诊断的 V2 模型合同。
- 将“亮度使能”明确改为“光照补偿”，不再把 V 差异直接作为扣分项。
- 使基础/全部切换成为纯显示行为，不再改变配置或销毁模板。
- 对灰度来源、错误位深、无效 ROI、坏模型和 HALCON 异常返回明确状态。

## 3. 范围

### 3.1 本阶段实现

- `CV_8UC3` 和 `CV_8UC4` 彩色输入。
- 模板区域“与检测区域同步”和“自定义”两种模式。
- 矩形、圆形检测 ROI，以及模板/检测屏蔽多边形。
- 固定 32×32 的 H/S 二维联合直方图。
- HALCON 直方图交集相似度。
- 高/中/低三档颜色容差。
- 可选光照补偿及完整诊断。
- V2 模型状态、签名、严格校验和 V1 重建流程。
- 真实 H/S/V 统计展示。
- 异步测试运行、统一结果 payload 和错误状态。

### 3.2 本阶段不实现

- 位置修正的坐标变换和旋转 ROI。
- 色谱特征的真实算法。
- 颜色识别算法迁移或其历史模型修复。
- 非 8-bit 彩色输入的隐式转换。
- 宣称复刻海康未公开的内部颜色比较数学。

## 4. 产品语义

### 4.1 直方图特征

“直方图特征”表示模板有效区域与检测有效区域的 H/S 联合颜色分布相似度。它比较完整分布，颜色类别和面积比例变化都会影响分数。

正式算法名称固定为：

```text
featureType = "histogram_hs_2d"
algorithm = "histogram_intersection"
scoreDirection = "higher_is_better"
```

UI 和 payload 不再出现 `Bhattacharyya`、`dominant_hue_coverage`、`soft_kernel` 或伪造的 distance 字段。

### 4.2 色谱特征

海康公开手册未给出“色谱特征”的数学定义。本阶段 UI 显示“色谱特征（待实现）”并禁用；旧配置请求该类型时返回：

```text
success = false
status = "unsupported_feature"
```

后续可单独评估基于 HALCON `class_2dim_sup` 的二维允许色域覆盖率，但不能把该候选实现描述成海康算法复刻。

### 4.3 光照补偿

“光照补偿”表示在颜色特征提取前，将检测 ROI 的亮度受限地归一到模板亮度基准。它不表示把 V 通道差异加入相似度扣分。

- 默认关闭。
- 模板记录有效 ROI 的 V 均值和标准差。
- 检测时计算 `scale = templateMeanV / detectMeanV`。
- 使用经现场数据标定的上下限限制 scale。
- 对 RGB 三通道应用相同的 HALCON `scale_image` 变换，再重新转换 HSV 并提取 H/S 特征。
- 输出补偿前后亮度、实际 scale 和截断比例。
- 过暗、过曝、分母接近零或截断比例超限时返回 NG，状态为 `invalid_illumination`。

V2 初始安全常量为：有效 V 均值 `[8,247]`、补偿倍率 `[0.75,1.3333333333]`、最大截断比例 `0.02`。这些数值属于待现场曝光序列复核的版本化合同；若现场验证要求修改，必须同步改变 `extractParamsHash` 并重新取样、重新验证，不能只在代码中静默调参。

### 4.4 灵敏度

UI 文案固定为：

```text
高（严格）
中（标准）
低（宽松）
```

底层直方图始终为 32×32。灵敏度只控制允许的 H/S 偏移范围，不改变模型维度：

- 高：只比较 `deltaH=0, deltaS=0`。
- 中：比较 `deltaH=-1..1, deltaS=-1..1`。
- 低：比较 `deltaH=-2..2, deltaS=-2..2`。

H 轴必须环形回绕，S 轴不得回绕。偏移后的交集与最大值计算必须通过 HALCON tuple 算子完成，不能恢复 C++ Gaussian kernel 或经验权重。以上范围作为 V2 初始固定合同；现场验证若要求修改，必须升级提取/评分参数签名并重新验证。

## 5. 输入契约

运行前按以下顺序检查：

1. 图像非空。
2. 原始来源必须是彩色模式。
3. 正式支持 `CV_8UC3` 和 `CV_8UC4`；其他位深或通道返回明确状态，不做隐式 `convertTo(CV_8U)`。
4. 模板和检测 ROI 数值有限、几何有效并落在 `[0,1]`。
5. 圆形半径必须大于 0，屏蔽多边形必须具有非零面积。
6. 扣除屏蔽区后必须保留足够有效像素。
7. 模型必须为 `ready`，版本、维度、顺序、归一化和提取参数签名均正确。

灰度来源遵循智能相机手册的 NG 语义：

```text
success = true
ok = false
measurementValid = false
passed = false
status = "unsupported_color_input"
```

### 5.1 原始像素格式元数据

当前 CameraFrameProvider、ReferenceImageProvider 和方案基准图加载会把灰度图提前转换成三通道 BGR。Runner 仅检查 `cv::Mat::channels()` 无法区分“原始 Mono8 后扩成 BGR”和真正彩色图。

V2 必须在归一化前保留并传递以下来源元数据：

```json
{
  "colorMode": "color | mono | unknown",
  "pixelFormat": "BGR8 | BGRA8 | Mono8 | ...",
  "originalChannels": 3,
  "originalDepth": 8,
  "source": "camera | reference | file"
}
```

运行时通过 `ToolRequest.runtimeContext.input` 传入。方案基准图还必须持久化 reference input metadata，否则重新加载方案后会丢失原始 Mono/Color 信息。`colorMode=mono` 固定 NG；`unknown` 必须产生 warning，不能伪装成已确认彩色输入。

仅用“三个通道数值相等”推断灰度是错误的，因为真实彩色相机也会拍摄白、灰、黑目标。

## 6. HALCON 算法

### 6.1 必要接口

本机 HALCON 24.11.1 已确认存在以下能力：

- `gen_image_interleaved`
- `decompose3` / `compose3`
- `trans_from_rgb`
- `gen_rectangle1`
- `gen_circle`
- `gen_region_polygon_filled`
- `difference`
- `area_center`
- `histo_2dim`
- `intensity`
- `scale_image`
- `tuple_select`
- `tuple_min2`
- `tuple_sum`
- `tuple_div`
- `clear_obj`

动态加载时只解析当前路径实际需要的符号。runtime、license 或必要符号缺失时不得降级到 OpenCV 或自写核心算法。

### 6.2 特征提取

```text
BGR/BGRA 8-bit
→ HALCON RGB 通道
→ 可选光照补偿
→ trans_from_rgb(..., "hsv")
→ 生成显式有效 Region
→ H/S 量化到 0..31
→ histo_2dim(Region, H, S)
→ 读取 32×32 频数
→ 除以有效像素数归一化
→ hue_major 1024 维模型
```

HALCON `histo_2dim(Region, ImageCol, ImageRow)` 的第一个图像值映射到输出行，第二个映射到输出列。因此调用 `histo_2dim(Region, H, S)` 时：

```text
row = Hue
column = Saturation
flattenIndex = hueBin * 32 + saturationBin
layout = "hue_major"
```

UI 二维图的横轴显示 Saturation，纵轴显示 Hue。任何 `[S][H]` 解释都属于错误。

### 6.3 相似度

模板 T 与检测 D 都满足非负且总和为 1：

```text
similarity = sum(min(T[i], D[i]))
score = clamp(similarity * 100, 0, 100)
passed = score >= minScore
```

逐元素最小值和求和使用 HALCON `tuple_min2` 与 `tuple_sum`。完全相同分布必须得到 100 分，不再混入“颜色纯度”或主峰覆盖经验项。

## 7. 模板区域与 ROI

`templateRegionMode` 支持：

- `sync`：参考图上的模板有效区域使用当前检测区域的形状和归一化几何；检测区为圆形时模板也使用同一圆形。检测 Mask 同步作用于参考图模板 Region，之后再叠加模板专用 Mask。
- `custom`：使用独立矩形 `templateRoiNormalized`。

模板屏蔽区始终作用在最终模板 Region 内。检测屏蔽区始终作用在当前检测 Region；仅在 `sync` 模式下，它还以相同归一化坐标同步作用于参考图模板 Region，`custom` 模式不使用检测屏蔽区建模。

当前检测图只绘制检测 ROI、检测屏蔽区和结果 overlay。模板 ROI 与模板屏蔽区只能显示在参考图/模板预览中，禁止叠加到当前相机图。

`judgeRule` 继续使用：

```json
{
  "mode": "min_score",
  "minScore": 80

```

模型严格校验：

- `values.size() == 1024`。
- `valueHistogram.size() == 32`，只用于 V 统计展示和光照诊断，不进入 H/S 相似度扣分。
- 每个值有限且非负。
- 总和在数值容差内等于 1。
- `hueBins == 32`、`saturationBins == 32`。
- `layout == "hue_major"`。
- `featureType`、`algorithm`、`colorSpace` 为受支持枚举。
- `effectivePixelCount` 达到最低有效像素要求。
- `extractParamsHash` 与当前模板提取参数一致。

## 9. 模型状态与失效

状态固定为：

```text
empty        尚未取样
stale        参考图或提取参数已变化
ready        可运行
invalid      模型内容损坏
unsupported  版本或特征不支持
```

以下变化使模型变为 `stale`：

- 参考图变化。
- 模板区域模式变化。
- 模板 ROI 或模板屏蔽区变化。
- `sync` 模式下检测区域类型、检测 ROI、检测圆形或检测屏蔽区变化。
- 特征类型、色彩空间、bin、layout 变化。
- 光照补偿建模参数变化。

以下变化不得清空或失效模板：

- 基础/全部视图切换。
- `custom` 模式下检测 ROI、检测圆形或检测屏蔽区变化。
- 灵敏度变化。
- 最小得分变化。
- 测试运行状态变化。

只有显式“重新取样/完成取样”可以从 stale 生成新的 ready 模型。

## 10. V1 迁移

V1 裸特征受到轴解释和评分语义错误影响，不允许直接转置或继续运行：

- 有参考图：加载为 `stale`，提示“旧模型需要重新取样”。
- 无参考图：加载为 `unsupported`，状态 `model_rebuild_required`。
- 用户显式重新取样后生成 V2 模型。
- 未知版本返回 `unsupported_model_version`。
- 禁止用默认值静默把未知算法映射到 V2。

## 11. UI 契约

- 模板区域提供“与检测区域同步/自定义”。
- 模型区显示真实 H、S、V 统计、模型状态、版本、有效像素数和参考图状态。
- “亮度使能”改名为“光照补偿”，默认关闭。
- “直方图特征”可选；“色谱特征（待实现）”禁用。
- 灵敏度显示“高（严格）/中（标准）/低（宽松）”。
- 位置修正分组保留但禁用，标注“接口预留，暂未实现”。
- 基础/全部只控制显隐，保存内容不得依赖当前视图。
- 参考图变化后立即将 ready 模型标记 stale。
- 测试运行使用异步任务，连续运行不得阻塞 UI 线程。
- 错误显示同时展示 status 和 message。

## 12. 位置修正预留接口

配置保留：

```text
positionCorrection.enabled
positionCorrection.sourceId
positionCorrection.interfaceVersion
```

本阶段行为：

- 新建配置默认 false。
- UI 控件不可操作。
- V1 配置若为 true，仍按原始检测 ROI 运行颜色比较。
- payload 输出 `requested=true`、`applied=false`。
- warnings 添加 `position_correction_not_implemented`。
- 不因该预留请求阻断普通颜色比较，也不能声称已完成修正。

## 15. 验证

### 15.1 无 license 契约测试

- 空图、灰度来源、不支持位深。
- ROI 越界、零面积圆、退化多边形、屏蔽后为空。
- 模型状态、维度、有限值、归一化、签名和 V1 重建。
- 基础/全部纯显隐。
- `custom` 模式下检测 ROI/圆形/检测屏蔽区、灵敏度和阈值不使模型失效。
- `sync` 模式下检测 ROI/圆形/检测屏蔽区变化使模型 stale。
- 参考图、模板 ROI/Mask 和提取参数使模型 stale。
- 色谱和位置修正预留行为。

### 15.2 HALCON licensed 测试

- 真实 `histo_2dim` 行=H、列=S。
- 同图比较得到 100 分。
- 红色色相跨 0/255。
- H/S 边缘分布相同但联合配对不同的图像可以区分。
- 多颜色面积比例变化使分数下降。
- 矩形、圆形、模板/检测屏蔽区。
- 光照补偿前后、倍率、截断和异常曝光。
- 不同分辨率、相同颜色分布。
- runtime、符号和 license 异常状态。

显式设置 `RUN_HALCON_LICENSED_SMOKE=1` 后，license 缺失必须使测试失败，不能再以“跳过”返回成功。

### 15.3 现场数据

按采集批次拆分模板/标定集、正样本验证集、近似负样本集、明确负样本集、曝光扰动集和异常集。连续视频相邻帧不能随机拆到不同集合。

位置修正未实现期间，移动/旋转样本必须预先对齐，或确保目标完整落在检测 ROI 内；否则测到的是 ROI 偏移和背景污染，不是颜色算法本身。

## 16. 验收门槛

- 同一图像重复比较为 100 分。
- 所有异常输入零崩溃且有稳定错误码。
- 当前验证集中的 NG 样本不得被判为 OK。
- 正样本通过率初始目标不低于 99%，最终按现场误判成本调整。
- 开启光照补偿后，曝光变化正样本通过率不得下降。
- 保存、重新打开及基础/全部切换后，模型哈希和评分保持一致。
- 新建、取样、保存、回显、运行形成完整闭环。
- 不改变颜色识别现有配置和评分行为。

当前本机 HALCON licensed smoke 受 license `#2036` 阻塞。在该验证恢复并通过前，不得宣称 V2 算法数值验证完成。
