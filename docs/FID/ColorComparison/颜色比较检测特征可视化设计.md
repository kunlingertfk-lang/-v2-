# 颜色比较检测特征可视化设计

## 1. 状态与目标

- 日期：2026-07-15。
- 状态：用户已确认。
- 适用范围：颜色比较“全部”页的模板/检测直方图对比、二维 H/S 联合分布、点击放大与关闭交互。
- 目标：在不改变现有 HALCON 特征提取、评分和最低分判定语义的前提下，让用户直观看到模板与当前检测区域在哪些 bin 上重合较少，用于现场调整最低分阈值和排查颜色、饱和度及亮度差异。

本设计扩展现有 `docs/FID/ColorComparison/颜色比较V2设计说明.md`。两者冲突时，算法、模型和输入合同仍以 V2 设计说明为准；本文只定义检测特征诊断和 UI 展示增量。

## 2. 已确认的产品设计

采用“方案 A：H/S/V 横排，二维 H/S 联合图在下”的布局：

```text
模型与检测色彩特征
■ 模板   □ 检测   ▧ 重合

+-----------+ +-----------+ +-----------+
| H      放大| | S      放大| | V      放大|
| 双柱叠加   | | 双柱叠加   | | 双柱叠加   |
+-----------+ +-----------+ +-----------+

+-------------------+ +------------------+
| HS 二维联合差异图  | | HS 联合重合      |
| S ↑           放大 | | 当前得分         |
|              H →  | | 判定阈值         |
+-------------------+ +------------------+
```

现有模板显示不是 256 根柱，也不是图像像素值：

- 模型保存 32×32、共 1024 维的 H/S 联合直方图。
- UI 将联合直方图投影为 32 个 H bin 和 32 个 S bin。
- V 使用 32 维直方图。
- HSV 量化前的 8-bit 值域为 0..255，每个显示 bin 汇总约 8 个原始等级。
- 图表控件的像素宽高只决定绘制清晰度，不改变 bin 数。

## 3. 一维直方图叠加语义

H、S、V 每张图在相同 bin 位置绘制模板与检测值：

- 模板：通道色实心柱。
- 检测：空心描边柱。
- 重合：`min(template[i], detect[i])` 对应的公共高度，以斜纹或加亮区域表示。
- H、S、V 继续使用现有橙、蓝、绿通道色；模板/检测身份通过实心、空心和图例区分，不再增加容易混淆的来源颜色。

同一张图中的模板和检测必须使用共同纵轴：

```text
axisMax = max(max(template), max(detect))
barHeight = value / axisMax
```

禁止分别按模板峰值和检测峰值缩放，否则会把幅度不同的分布画成相似高度。三个通道之间不强制共用纵轴，因为 H、S、V 是不同诊断维度。

H/S 边缘分布由 1024 维 `hue_major` 联合直方图计算：

```text
hue[h]        = sum(hs[h * 32 + s], s=0..31)
saturation[s] = sum(hs[h * 32 + s], h=0..31)
```

V 使用独立的 32 维 `valueHistogram`。V 图只用于亮度和光照补偿诊断，不直接解释颜色相似度得分。

## 4. 二维 H/S 联合差异图

二维图直接使用模板和检测的 32×32 联合直方图，不从 H/S 一维边缘图反推：

- 横轴：Hue，bin 0..31，从左向右。
- 纵轴：Saturation，bin 0..31，从下向上。
- 模型索引继续遵循 `index = hueBin * 32 + saturationBin`。
- 绘制坐标使用 `x = hueBin`、`y = 31 - saturationBin`，不改变模型的 `hue_major` 合同。

每个 cell 分解为：

```text
overlap        = min(template, detect)
templateExcess = max(template - detect, 0)
detectExcess   = max(detect - template, 0)
```

合成图使用固定语义：重合为绿色，模板超出为橙色，检测超出为青色。亮度按模板和检测的共同二维峰值归一化，空 cell 保持深色背景。这样可以同时定位“模板有而检测少”和“检测新增”的 H/S 组合区域。

左侧小图默认显示该联合差异合成图。旁边显示：

- `HS 联合重合`：Runner 已计算的原始 32×32 直方图交集 `rawIntersection * 100%`。
- `当前得分`：实际用于 OK/NG 的 `ToolResult.score`。
- `判定阈值`：当前 `judgeRule.minScore`。

H/S 一维边缘图可能在联合分布不同的情况下仍看起来相似，因此它们只用于定位单轴差异；联合重合和最终得分不得由三个一维图的重合率平均得到。

## 5. 点击放大与关闭交互

H、S、V 和二维 H/S 小图都具有一致交互：

- 鼠标悬停时显示橙色描边和手形光标。
- 右上角显示放大图标。
- 点击小图后，在当前 `ColorComparisonDialog` 内显示遮罩式放大层。
- 同一时刻只允许一个放大层；点击另一图时复用并更新现有放大层。
- 放大层标题明确显示 `H/S/V 直方图对比（32 bins）` 或 `HS 二维联合直方图（32×32）`。
- 放大层保留模板、检测、重合图例，共同纵轴和当前诊断数值。

放大层支持三种关闭方式：

1. 点击右上角“× 关闭”。
2. 按 `Esc`。
3. 点击内容卡片外的深色遮罩。

关闭只隐藏放大层，不退出颜色比较对话框，不触发 `accept()`、`reject()`、保存配置或停止连续测试。切换到“基础”页、退出测试模式、加载其他配置或关闭颜色比较对话框时，放大层必须自动关闭。

连续测试期间若放大层保持打开，它跟随最新通过 generation 门禁的有效结果刷新；旧异步结果不得覆盖新帧。当前帧测量失败、模型失效或检测特征维度非法时，检测柱和二维检测层立即清空并显示“检测特征不可用”，不得继续展示上一帧数据造成误判。模板有效时可继续保留模板分布。

## 6. 数据链路与字段

现状：`ColorComparisonHalconRunner::run()` 已生成 1024 维检测 H/S 特征并保存到 `ColorComparisonHalconResult::detectFeature`，但 Adapter 映射时没有将其放入 `ToolResult`；检测 V 直方图已在内部提取，却没有进入结果结构。

目标链路：

```text
HALCON extractFeature
  ├── detect H/S 32×32
  └── detect V 32
          ↓
ColorComparisonHalconResult
          ↓
ColorComparisonAdapter / ToolResult.payload
          ↓
ColorComparisonDialog
          ↓
一维双柱 + 二维联合差异 + 放大层
```

Runner 结果增加检测 V 特征，并在成功且 `measurementValid=true` 时输出诊断对象：

```json
{
  "histogramDiagnostics": {
    "available": true,
    "hueBins": 32,
    "saturationBins": 32,
    "layout": "hue_major",
    "detectHsHistogram": [1024 values],
    "detectValueHistogram": [32 values],
    "rawIntersection": 0.724
  }
}
```

模板 H/S 和 V 继续从 Dialog 当前的严格校验后 `m_model` 读取，避免每帧在 payload 中重复复制模板模型。检测直方图只属于运行期诊断，不写入 `ToolConfig`、方案 JSON 或模板模型。

失败或测量无效时，`histogramDiagnostics.available=false`，数组为空或不出现；Dialog 必须按 `available`、维度、有限非负和归一化条件再次防御性校验后才绘制。诊断字段损坏只影响特征展示，不得改变 Runner 已给出的 OK/NG 结论，但 UI 状态栏应追加可定位的“检测特征不可用”提示。

## 7. 组件职责

- `ColorComparisonHalconRunner`：继续只用 HALCON 提取检测 H/S/V，提供检测直方图和原始联合交集；不负责 UI 投影和绘制。
- `ColorComparisonAdapter`：把强类型 Runner 诊断结果稳定映射到 `ToolResult.payload`；不重新计算图像特征。
- 颜色比较特征绘制组件：接收已经归一化的模板/检测向量，计算一维边缘、共同轴尺度、cell 差异颜色并绘图；发出点击放大信号。
- 放大遮罩组件：复用绘制组件，管理标题、关闭按钮、Esc 和遮罩点击；不得参与工具保存和测试状态切换。
- `ColorComparisonDialog`：维护最近一次有效检测特征，响应异步 generation，控制清空/刷新/放大层生命周期。

绘制组件应从 `ColorComparisonDialog.cpp` 中隔离为颜色比较专用类，避免继续扩大已经承担配置、ROI、异步执行和生命周期管理的 Dialog 文件；本次不抽成跨工具公共组件，也不重构其他对话框。

## 8. 错误和边界处理

- 模型非 ready：清空模板与检测图，关闭放大层，沿用现有模型状态提示。
- 尚未运行检测：显示模板柱和二维模板分布，检测图例保持可见但检测层为空，提示“等待测试运行”。
- 空图、无效 ROI、有效像素不足、HALCON runtime/license/符号失败：清空检测层，不保留旧帧。
- 检测 H/S 不是 1024 维、V 不是 32 维、包含 NaN/Inf/负数或归一化不合法：不绘制该检测结果，并提示诊断字段无效。
- 模板和检测均为零分布：保持空背景，避免除零；严格模型和 Runner 合同正常情况下不应产生该状态。
- 小尺寸控件：仍固定显示 32 bins；宽度不足时允许多 bin 映射到相邻像素，但不得减少或重采样模型维度。
- 亮度补偿开启：展示 Runner 实际参与诊断的补偿后检测 H/S/V 特征，并继续显示现有补偿 diagnostics。
- 基础/全部切换：只影响特征卡显隐，不改变模型和评分；切到基础页时关闭放大层。

## 9. 明确不在本次范围

- 不改变 32×32 H/S 模型维度、`hue_major` 顺序或 HALCON 提取接口。
- 不改变灵敏度、平滑、光照补偿、最终 score 或 `minScore` 判定公式。
- 不新增逐 bin 的可保存阈值，也不让用户在图上编辑模型。
- 不把检测直方图持久化到方案配置。
- 不修改颜色识别及其他算子的直方图 UI。
- 不实现位置修正或色谱特征。

## 10. 验证要求

### 10.1 Runner 与 Adapter

- 有效检测返回 1024 维 H/S、32 维 V、有限非负且归一化的诊断数组。
- payload 的 bins、layout 和 `rawIntersection` 与 Runner 当前结果一致。
- 空图、无效 ROI、无模型、无 license 和缺符号路径不携带可用检测特征。
- 检测特征来自 HALCON 现有提取结果，不引入 OpenCV 或 C++ 核心算法旁路。

### 10.2 绘制与 Dialog

- 模板和检测按共同纵轴绘制，32 个 bin 不被误画成 256 个值。
- H/S 边缘投影与 1024 维 `hue_major` 输入一致。
- 二维图横轴 H、纵轴 S，低 S 在下方；模板超出、检测超出和重合颜色正确。
- 点击 H/S/V/HS 均打开对应放大层。
- “× 关闭”、Esc 和遮罩点击均只关闭放大层，不关闭主对话框。
- 连续运行只显示最新 generation 的特征；失败帧、退出测试、模型 stale 和切换基础页会清空或关闭正确状态。
- 重新打开方案时不回显历史检测特征，只回显模板模型。

### 10.3 工程验证

- 重新执行颜色比较 Runner、Model 和 Dialog smoke。
- 有有效 HALCON license 时运行颜色比较 licensed smoke；无效 license 路径仍返回明确错误。
- 在影子 `build/` 中重新执行 qmake 和 make。
- 手工检查 1920×1080 主界面下左侧参数区的高度、滚动、图例清晰度、四图点击目标、连续刷新和三种关闭方式。

## 12. 2026-07-15 显示增强增量设计

本节是用户确认的直方图重合显示、放大缩放和颜色比较图片浏览增量。它不改变前述 32-bin/32×32 数据合同、HALCON 特征、最终得分或最低分判定。

### 12.1 重合区域高对比显示

一维 H/S/V 图仍按 `min(template[i], detection[i])` 计算真实重合高度，但绘制语义调整为：

- 重合区域使用高亮亮绿色实心填充，并增加深色边界或斜纹，使其与 H/S/V 通道色模板柱形成明显差异。
- 模板超过检测的部分继续保留原通道色；检测继续使用高对比白色空心轮廓。
- 重合颜色只增强视觉辨识度，不放大柱高、不修改 bin 数值，也不参与分数计算。
- 小图和放大图使用同一套来源图例与颜色语义，禁止出现同一颜色在两处表达不同来源的情况。

二维 H/S 联合图继续按 `overlap/templateExcess/detectExcess` 合成，但提高重合绿色的亮度、饱和度和不透明度。允许对低强度 cell 使用仅影响显示的亮度映射，使少量重合可见；该映射不得回写数据、改变 `rawIntersection` 或制造不存在的非零 cell。模板超出保持橙色，检测超出保持青色。

### 12.2 放大直方图等比例缩放

放大层继续位于当前 `ColorComparisonDialog` 遮罩内，采用响应式大尺寸内容卡：

- 初次打开时，内容卡约占对话框可用区域的 85%，并始终给遮罩和关闭操作保留可见空间。
- 一维直方图保持固定宽高比；二维 H/S 绘图区保持正方形，不随宿主窗口比例拉伸。
- 放大图支持鼠标滚轮按 `100% / 125% / 150% / 175% / 200%` 五档等比例缩放，以图表中心为缩放基准。
- 标题、关闭按钮和底部诊断说明不参与缩放；仅图表画布缩放。
- 图表超过可见区域时由内部滚动区域承载，关闭按钮不得随内容滚出视口。
- 点击另一张 H/S/V/HS 小图时恢复为 100%；同一张放大图在连续检测刷新时保持当前缩放档位和滚动位置。
- 左侧参数区中的小图不响应滚轮，避免与参数滚动区争抢滚轮事件。
- 缩放达到上下限后继续滚轮不产生变化。窗口过小时使用滚动区域，不裁掉图表，也不让弹窗超出宿主窗口。

关闭方式仍为“× 关闭”、`Esc` 和点击遮罩。关闭只隐藏直方图放大层，不退出颜色比较 Dialog，不触发保存、取消或测试状态变化。

### 12.3 颜色比较图片视图启用方式

图片缩放、平移和 ROI 坐标处理遵循 `docs/FID/Function_Docs.md` 的“公共图像视图缩放、平移与 ROI 坐标规范”，能力实现于公共 `FrameViewHelper`。本次仅由 `ColorComparisonDialog` 显式启用，不默认改变颜色识别、字符识别和其他已有工具的交互。

颜色比较中的具体交互为：

| 当前状态 | 图片缩放 | 图片平移 | 普通左键 |
| --- | --- | --- | --- |
| 未启用模板/检测/屏蔽区绘制 | 鼠标滚轮 | 左键按压拖动 | 平移图片 |
| 任一模板/检测/屏蔽区绘制按钮高亮 | `Ctrl + 鼠标滚轮` | `Ctrl + 左键按压拖动` | 绘制当前区域 |

矩形、圆形、多边形以及模板/检测屏蔽区均继续保存为原图坐标派生的归一化数据。缩放和平移不得改变已有 ROI 的坐标、宽高、半径或多边形顶点；临时平移不得把模型标记为 stale，也不得触发重新测试。

### 12.4 组件边界与错误处理

- `FrameViewHelper`：提供可选浏览能力、手势状态判断、倍率边界、适应窗口和坐标保护；不感知颜色比较的模板或检测语义。
- `ColorComparisonDialog`：显式启用公共浏览能力，并继续只负责当前 ROI 编辑目标和业务状态。
- `ColorComparisonFeatureView`：负责重合颜色、放大图尺寸、五档缩放和滚动承载；不修改诊断数据与判定。

无图片时忽略图片缩放和平移。无有效直方图时放大层沿用既有空状态，不因缩放产生伪数据。ROI 绘制过程中不切换为平移，只有新的鼠标按下事件重新判断操作模式。图片分辨率改变时恢复适应窗口；同尺寸连续帧和放大直方图数据刷新均保持用户观察状态。

### 12.5 方案比较与范围选择

已比较以下方案：

1. 在现有 `FeatureChart`、遮罩层和 `FrameViewHelper` 上增量增强。改动集中，沿用现有归一化 ROI 链路，确认采用。
2. 将直方图和图片统一重做为新的 `QGraphicsView` 场景。缩放能力完整，但需要重做已经稳定的特征图，范围过大，未采用。
3. 只增大弹窗并调整颜色。不能满足真实缩放和图片浏览要求，未采用。

公共图片浏览能力采用“公共实现、显式启用”：颜色比较先启用和验证，其他功能后续按需接入。直方图显示规则保持颜色比较专用，不进入公共视图规范。

### 12.6 验证要求

- 一维图检查重合高亮与模板通道色、检测白色轮廓明显可区分，且柱高仍等于真实共同纵轴结果。
- 二维图检查重合、模板超出、检测超出三类 cell 颜色清晰，显示增强不改变 `rawIntersection` 和 score。
- H/S/V/HS 四图均检查初始大尺寸、五档滚轮缩放、宽高比、超出区域滚动和切换图表恢复 100%。
- 连续检测刷新时检查当前直方图缩放档位和滚动位置不抖动。
- 图片视图检查非绘制态滚轮/左拖，以及绘制态 `Ctrl+滚轮`/`Ctrl+左拖`。
- 在适应窗口、放大和平移后分别绘制矩形、圆形、多边形、模板屏蔽区和检测屏蔽区，验证归一化坐标与原图像素尺寸一致。
