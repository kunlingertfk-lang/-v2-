# 颜色比较交接说明

> 更新时间：2026-07-16
>
> 交接范围：仅“颜色比较（ColorComparison）”
>

## 1. 三十秒结论

颜色比较已经形成从取样建模、配置保存与回显、基准图测试、单次/连续检测到结果显示的完整链路。当前实现使用 HALCON 提取 HSV 特征，以模板与检测区域的 32 × 32 H/S 联合直方图为核心比较特征，同时保留 32 bins 的 V 直方图用于诊断显示；这里不是 256 个像素值，也不是颜色识别使用的 GMM 分类模型。

截至 2026-07-16，颜色比较整体功能已由用户确认验证通过；当前工作树同时记录了以下近期修复的自动验证证据：

- 模板和检测直方图同图叠加、H/S/V 一维图及 HS 二维联合图；
- 点击直方图放大、关闭和等比例缩放；
- 图像缩放和平移时 ROI 使用原图、scene、归一化坐标转换，不随视图导航漂移；
- 原始 ROI 裁剪与橙色框、Mask、结果文字等显示层分离；
- 得分不再因饱和度不匹配固定停在 40.0；
- 亮度补偿 scale 或截断比例超限时回退到原始特征继续测量；
- 绘制图标采用“点击进入、再次点击退出”的 toggle 交互，保存的 ROI 类型不再导致图标长期高亮；
- 下拉弹出项和颜色比较专用控件接入公共样式角色，避免局部 QSS 被应用级样式覆盖。

注意：上述最后一批修复已经在当前工作树验证，但其中部分源码尚未形成独立提交。接手时必须先查看 git status 和目标文件差异，不要只根据 HEAD 判断最终状态，也不要清理或覆盖颜色识别等其他未提交工作。

## 2. 功能边界

颜色比较回答的是：“当前检测 ROI 的颜色分布与已取样模板有多相似？”

- 输入：原始彩色帧、模板模型、检测 ROI/Mask、灵敏度、最低得分等配置。
- 输出：0~100 连续得分、OK/NG、诊断字段、ROI/结果 overlay。
- 模板：从一张参考图的有效区域提取 H/S 和 V 直方图并保存到配置。
- 判定：最终得分大于等于 judgeRule.minScore 时通过。

颜色识别回答的是类别识别问题，使用另一套训练、模型包和 GMM 生命周期。修改颜色比较时不要引入 ColorRecognitionDialog、颜色识别 GMM backend 或分类模型字段。

## 4. 主链路

### 4.1 取样与建模

1. Dialog 从未绘制 overlay 的参考原图中确定模板有效区域。
2. `templateRegionMode=custom` 时使用独立模板矩形；`sync` 时只复用检测区域的类型和归一化几何，不复用检测 Mask。
3. 模板有效区域只扣除模板 Mask，检测有效区域只扣除检测 Mask；两侧 Mask 永远独立，互不影响模型或检测特征。
4. Adapter 严格校验输入签名、归一化几何、Mask 和模型版本。
5. Runner 将原始 BGR/BGRA 图像桥接为 HALCON 图像，使用 HALCON Region/Mask 提取 HSV 特征。
6. 生成 V2 模型并保存参考图哈希、提取参数哈希和输入签名；这些合同变化时模型进入 stale/rebuild 状态。

模板缩略图只允许从原始参考图裁剪。橙色边框、Mask 填充、顶点和文字属于独立显示层，既不能进入缩略图像素，也不能进入 HALCON 特征输入。

### 4.2 保存与重新打开

Dialog 的 toToolConfig() 将颜色比较配置放在：

~~~text
ToolConfig.params.colorComparison
ToolConfig.judgeRule
~~~

重新打开时恢复保存的数据，但活动绘制状态必须为 EditState::None。已保存矩形、圆形或 Mask 只表示业务配置，不表示用户当前正在绘制。

### 4.3 测试与生产运行

1. Dialog/ToolEngine 构造 ToolRequest，提供原始目标帧和保存配置。
2. Adapter 校验模型、输入格式、ROI/Mask、灵敏度和阈值。
3. Runner 提取检测 H/S 联合直方图和 V 直方图，计算诊断及最终得分。
4. Adapter 映射为统一 ToolResult；UI 显示 OK/NG、得分、检测特征、诊断文字和 overlay。
5. 连续检测只接收通过 generation 门禁的最新结果；无效结果必须清空检测特征，不能残留上一帧数据。

## 5. 算法合同

### 5.1 模型结构

当前 V2 模型固定合同：

- featureType = histogram_hs_2d
- algorithm = histogram_intersection
- colorSpace = hsv
- hueBins = 32
- saturationBins = 32
- layout = hue_major
- H/S 联合特征长度：1024
- V 诊断直方图长度：32
- normalized = true
- 最小有效像素数：4

HALCON histo_2dim(Region, H, S) 的坐标读取与对外 hue_major 布局有专门转换合同。不要凭图像行列直觉修改 H/S 轴；相关回归覆盖红色 Hue 回绕与非对称 H/S 峰值。

### 5.2 得分语义

最终分数不是单纯的原始柱形重合率：

1. 计算原始 H/S histogram intersection，输出 rawIntersection；
2. 按灵敏度对 H/S 联合直方图进行 HALCON 平滑，得到 smoothedIntersection 和 hsScore；
3. 根据模板/检测亮度差计算 brightnessFactor，低饱和区域还会使用灰度得分加权；
4. 灰色与有色差异使用连续 saturationFactor 乘法惩罚；
5. 得到 finalScore，并与 minScore 比较。

“得分总是 40”曾由固定饱和度封顶造成，现在已改成连续系数。若再次出现平台分，优先检查 baseScoreBeforeSaturationPenalty、saturationMismatchProgress、saturationFactor 和 finalScore，不要直接改 UI 显示或阈值掩盖问题。

### 5.3 亮度补偿

亮度补偿默认关闭。开启时的安全范围为：

- 模板/检测 V 均值：[8, 247]
- 缩放比例：[0.75, 1.3333333333]
- 最大预计截断比例：0.02

处理分两类：

- V 均值无效、过暗或过曝：测量无效，返回 invalid_illumination；
- scale 超限或预计截断比例过高：不再失败，跳过补偿并使用原始 H/S/V 特征继续测量，输出 brightness_compensation_skipped warning，同时给出 fallbackReason=scale_out_of_range 或 clip_ratio_exceeded。

因此看到 invalid_illumination 时应先看亮度均值；看到 fallback warning 时测量仍然有效，不能在 UI 中当成失败或清空检测直方图。

## 6. UI 与交互合同

### 6.1 特征图

- H/S/V 三张一维图与 HS 二维图同时显示模板和最新有效检测特征。
- 模板、检测、重合必须有明确图例；重合使用高对比亮绿色，只改变显示，不修改直方图数据或得分。
- 点击四张图中的任意一张可打开大图；大图支持关闭按钮、Esc、遮罩点击关闭及等比例缩放。
- 当前检测无效、模型失效或特征维度错误时立即清空检测层并显示不可用原因；模板有效时可保留模板层。

### 6.2 图像导航与绘制

- 非绘制状态：滚轮缩放，左键按压拖动平移。
- 绘制状态：普通左键用于绘制；Ctrl + 滚轮缩放，Ctrl + 左键拖动平移。
- ROI 必须保存在归一化原图坐标中；适应窗口、缩放、平移、双击复位均不得改变保存坐标与区域大小。

绘制按钮统一使用 toggle 语义：

1. 第一次点击进入对应绘制模式并高亮；
2. 保持高亮时允许连续重绘；
3. 再次点击同一按钮退出绘制并取消高亮，但保留最后一次有效几何；
4. 点击另一绘制按钮直接切换；任一时刻最多一个绘制状态活动；
5. 点击全图、完成或退出相关流程时退出绘制状态；
6. checked 只能由 ColorComparisonDialog::EditState 推导，不能由保存的 ROI 类型、ROI 是否有效或 Mask 是否存在推导。

公共视图、原图/overlay 分离和绘制 toggle 规范在 docs/FID/Function_Docs.md；颜色比较直方图的专用合同在颜色比较检测特征可视化设计.md。

### 6.3 样式

不要在颜色比较控件上临时堆叠字体、文字色或背景色的内联 QSS。控件应设置稳定的 objectName、role、panelRole 或 actionRole，由 styles/app.qss 统一渲染。

Qt QComboBox 的弹出列表可能位于私有顶层容器中，单靠父 Dialog 选择器或应用 QSS 不一定命中。使用 UiStyleRoles.h 中的公共下拉样式辅助入口，并同时覆盖 popup view、viewport、item 的前景、背景、选中和 disabled 状态。若再次出现“灰底黑字看不清”，先检查实际 popup 对象和 palette，不要只提高局部选择器优先级。

## 8. ToolResult 与诊断字段

| 字段 | 用途 |
| --- | --- |
| status、message | 机器状态和可读原因 |
| measurementValid、passed | 是否得到有效测量、是否超过阈值 |
| score、similarity、threshold | 0~100 得分、0~1 相似度、判定阈值 |
| effectiveTemplatePixels、effectiveDetectionPixels | 模板/检测有效像素数 |
| rawIntersection、smoothedIntersection、hsScore | 原始与平滑 H/S 比较诊断 |
| brightnessDifference、brightnessFactor | 亮度差及评分系数 |
| grayScore、grayWeight | 低饱和区域的灰度评分诊断 |
| baseScoreBeforeSaturationPenalty | 饱和度惩罚前的基础分 |
| saturationMismatchProgress、saturationFactor | 连续饱和度惩罚 |
| finalScore | 最终得分，应与 score 一致 |
| histogramDiagnostics | H/S=1024、V=32 的最新检测特征及布局信息 |
| brightnessCompensation | requested/applied/fallback/reason/均值/scale/clippedRatio |
| detectionRoi | 结果区域几何 |
| warnings、elapsedMs | 非致命退化信息和耗时 |

常见错误状态包括 unsupported_model_version、model_empty、model_stale、model_rebuild_required、unsupported_color_input、unsupported_pixel_format、invalid_template_roi、invalid_template_mask、invalid_detect_roi、invalid_detect_mask、invalid_illumination、halcon_so_not_found、halcon_symbol_missing 和 halcon_load_failed。

## 11. 常见问题定位

### 得分总是 40

先查看评分分解字段。当前源码应保留不同基础分，并通过连续 saturationFactor 形成不同最终分；若仍固定 40，检查是否运行了旧 binary、旧工作树或旧配置模型，而不是先改阈值。

### invalid_illumination

检查模板与检测 V 均值是否在 [8,247]。scale 超限和截断比例超限在当前版本应走 fallback warning 而不是 invalid_illumination；若行为不符，优先排查 binary 和源码版本。

### 缩略图出现橙色框或 Mask 颜色

说明裁剪使用了已经绘制 overlay 的显示图。必须回到原始参考帧裁剪；overlay 只能在显示层合成。自动回归会逐像素检查固定 BGR 源图。

### 下拉列表灰底黑字

检查是否通过 UiStyleRoles 同时设置 popup view、viewport 和 item palette/QSS。Qt popup 是独立顶层容器时，父 Dialog 选择器无法可靠覆盖它。

### 绘制图标一直高亮

检查按钮 checked 是否仍由 m_detectRegionType、ROI 有效性或配置回显驱动。正确实现只能由 m_editState 驱动；配置加载后必须是 None，再次点击活动图标必须退出而不清空几何。

### 检测直方图停留在上一帧

检查失败分支和 generation 门禁。测量无效、模型失效或维度错误时必须清空检测层；旧异步结果不能覆盖较新的帧。
