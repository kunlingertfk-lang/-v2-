# 颜色识别提示词规范

本文档用于规范后续基于颜色识别功能继续开发时的提示词写法。目标是让提示词清晰、有边界、有验证要求，并**与当前真实代码结构对齐**，避免提示词描述的分层与实际代码脱节，导致新代码放错位置。

> 使用前提：写提示词前，先阅读第 2 节「真实代码结构与分层契约」和第 3 节「字段注册表」，这是与代码对齐的事实基础。规范描述的分层若与代码不符，以代码为准并在本规范中修订。

## 1. 写提示词的基本原则

一条好的开发提示词应包含六类信息：

```text
背景上下文
  -> 当前功能已经实现到什么程度（引用第 2 节真实结构，不要凭印象）

目标
  -> 这次明确要新增、修复或整理什么

范围
  -> 哪些文件/模块允许改，哪些不允许改

约束
  -> 技术路线、兼容要求、分层归属、禁止事项

验收
  -> 怎么证明做完了

输出
  -> 需要代码、文档、计划、测试还是只要分析
```

不建议只写：

```text
帮我优化颜色识别。
```

建议写成：

```text
基于当前颜色识别实现（见 docs/FID/ColorRecognition/颜色识别提示词规范.md 第 2 节），
在不改变现有模板 JSON 兼容字段的前提下，新增 XXX。
按第 2 节分层契约确定改动落点：UI 控件改 ColorRecognitionDialog，
配置字段按第 3 节字段注册表登记并在 Adapter 解析，
算法核心改 ColorRecognitionHalconRunner，必须用 HALCON 算子。
完成后运行 smoke、qmake、make，并说明修改文件和验证结果。
```

## 2. 真实代码结构与分层契约

> 这是当前代码的真实职责分布，不是理想设计。后续开发必须按此契约落点，避免职责进一步串味。若需调整分层（如把配置序列化从 Dialog 抽到 Adapter），应作为独立重构任务单独立项，不在功能开发提示词中顺带做。

### 2.1 文件清单与规模

| 文件 | 行数级 | 职责 |
|---|---|---|
| `src/ColorRecognitionDialog.h/.cpp` | ~2000 | 主对话框，当前承担 UI 构建 + ROI 交互 + 测试运行调度 + 配置序列化 + 模板管理（偏大，改动需谨慎定位） |
| `src/ColorTemplateDialog.h/.cpp` | ~1100 | 模板样本创建/编辑对话框 |
| `src/tooladapters/ColorRecognitionAdapter.h/.cpp` | ~270 | `ToolConfig → ColorRecognitionHalconConfig` 解析 + 调用 Runner；**只读配置，不写配置** |
| `src/algorithms/recognition/ColorRecognitionHalconRunner.h/.cpp` | ~1500 | HALCON 直方图特征提取与识别；纯算法，不依赖 Qt UI |

### 2.2 分层契约（改动落点判定表）

新增/修改某类逻辑时，按下表确定改哪个文件：

| 逻辑类型 | 落点文件 | 说明 |
|---|---|---|
| UI 控件、布局、显隐、文案 | `ColorRecognitionDialog` | `setupUiState()` / `connectControls()` 区域 |
| ROI 绘制交互、状态机 | `ColorRecognitionDialog` | `startRectangleRoiEditing` / `startMaskEditing` 等方法族 |
| 测试运行调度（连续/单次/基准图） | `ColorRecognitionDialog` | `runTest` / `performTestRun` / `rerunLiveTest` / `m_testRunWatcher` |
| 模板增删改查、导入导出 | `ColorRecognitionDialog` + `ColorTemplateDialog` | Dialog 管列表，TemplateDialog 管单条编辑 |
| **配置写入（ToolConfig 序列化）** | `ColorRecognitionDialog::toToolConfig()` | **当前在 Dialog，不在 Adapter**；新增 `params`/`judgeRule` 字段必须在此登记 |
| **配置读取（ToolConfig → Runner Config）** | `ColorRecognitionAdapter::run()` | Adapter 把 `params` 解析成 `ColorRecognitionHalconConfig` |
| 算法核心（特征提取、判别） | `ColorRecognitionHalconRunner` | 必须 HALCON 算子；缺符号返回错误，不 fallback |
| payload / overlay 输出 | `ColorRecognitionHalconRunner` | 字段名按第 3 节注册表，UI 侧只读不造 |
| HALCON runtime / license / so 路径 | `HalconRuntimePaths` | 不在 Runner 里硬编码路径 |

### 2.3 关键提醒：配置读写分离

当前配置层职责是**分裂**的，这是最容易放错位置的地方：

- **写配置**（UI 状态 → `ToolConfig.params` JSON）：在 `ColorRecognitionDialog::toToolConfig()`（约 476 行起）。
- **读配置**（`ToolConfig.params` JSON → `ColorRecognitionHalconConfig` 结构体）：在 `ColorRecognitionAdapter::run()`（用 `intParam`/`boolParam`/`stringParam`/`rectFromJson` 等工具函数）。

**新增字段必须两头都改**：Dialog 的 `toToolConfig()` 写入 + `loadFromConfig()` 回显，Adapter 的 `run()` 解析。只改一头会导致保存了读不出，或读出了没保存。规范第 5 节模板已强制要求两边都列。

### 2.4 已实现功能（固定上下文）

```text
当前颜色识别已实现：
- 主界面 ColorRecognitionDialog（UI + ROI 交互 + 测试调度 + 配置序列化 + 模板管理，单文件约 2000 行）。
- 模板创建/编辑对话框 ColorTemplateDialog。
- 配置保存/回显在 Dialog 的 toToolConfig() / loadFromConfig()；Adapter 只做 ToolConfig → ColorRecognitionHalconConfig 解析。
- ColorRecognitionHalconRunner 负责 HALCON 直方图特征提取和识别。
- 支持矩形检测 ROI、圆形检测 ROI、屏蔽多边形。
- 支持主颜色占比 dominant_ratio 和整体相似度 histogram_intersection。
- 支持 brightnessEnabled=false 的 H/S 优先比较，以及 brightnessEnabled=true 的 H/S/V 比较。
- 支持 H/S 与 H/S/V 历史样本兼容对齐。
- 位置修正占位链路：enablePositionCorrection、positionCorrectionSource 保存/回显/透传，runner payload 输出 positionCorrectionApplied=false 和 positionCorrectionReason=not implemented。
- K 值和 KNN 距离只保留历史字段，不参与当前计算。
- 色谱特征和 HALCON 颜色分割/聚类只保留接口，暂未实现。
```

## 3. 字段注册表（单一事实源）

> 新增字段后必须更新此表。UI、Adapter、Runner 三处用到的字段名必须与此表一致，避免拼写漂移。

### 3.1 `params` 字段（ToolConfig.params JSON）

| 字段名 | 类型 | 默认值 | 写入处 | 解析处 | 说明 |
|---|---|---|---|---|---|
| `paramMode` | string | — | Dialog::toToolConfig | Adapter::run | 基础/全部 |
| `detectRegionType` | string | `rectangle` | Dialog | Adapter | rectangle/circle/global |
| `detectCircleNormalized` | object | — | Dialog | Adapter | 圆形 ROI 外接矩形 |
| `detectMaskType` | string | — | Dialog | Adapter | 屏蔽类型 |
| `detectMaskPolygon` | array | — | Dialog | Adapter | 屏蔽多边形归一化点 |
| `detectMaskApplied` | bool | false | Dialog | Adapter | 屏蔽是否生效 |
| `detectMaskReason` | string | — | Dialog | Adapter | 屏蔽未生效原因 |
| `enablePositionCorrection` | bool | false | Dialog | Adapter | 位置修正开关 |
| `positionCorrectionSource` | string | — | Dialog | Adapter | 位置修正来源 |
| `colorDecisionMode` | string | `dominant_ratio` | Dialog | Adapter | dominant_ratio / histogram_intersection |
| `colorModel` | string | — | Dialog | Adapter | 颜色模型 |
| `featureType` | string | `histogram` | Dialog(来自模板) | Adapter | 特征类型 |
| `sensitivity` | string | `medium` | Dialog(来自模板) | Adapter | low/medium/high → bins |
| `brightnessEnabled` | bool | true | Dialog(来自模板) | Adapter | 亮度是否参与比较 |
| `knnK` | int | 3 | Dialog(来自模板) | Adapter | 历史保留，不参与计算 |
| `knnDistance` | string | `halcon_default` | Dialog(来自模板) | Adapter | 历史保留 |
| 模板样本字段 | — | — | Dialog(模板序列化) | Adapter | 见 `color_recognition_function_implementation.md` |

### 3.2 `judgeRule` 字段

| 字段名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `mode` | string | `min_score` | 判别模式 |
| `minScore` | int | 80 | 最低得分阈值 |
| `expectedLabel` | string | — | 目标类别 |

### 3.3 `payload` 字段（Runner 输出）

| 字段名 | 说明 | 是否位置修正相关 |
|---|---|---|
| `enablePositionCorrection` | 透传开关 | 是 |
| `positionCorrectionSource` | 透传来源 | 是 |
| `positionCorrectionApplied` | 是否实际应用，当前固定 `false` | 是 |
| `positionCorrectionReason` | 未应用原因，当前固定 `not implemented` | 是 |
| `predictedLabel` / `predictedClassId` | 识别类别 | 否 |
| `score` / `rating` | 得分 | 否 |
| `elapsedMs` | 耗时 | 否 |
| 其余特征/直方图字段 | 见实现文档 | 否 |

## 4. 必须写清楚的约束

### 4.1 算法约束

```text
算法核心必须使用 HALCON 已有算子、类或过程。
实现前必须先确认所需 HALCON 算子可用，并列出算子链。
不允许使用 OpenCV、自写算法或第三方库替代核心算法。
OpenCV 只允许作为图像容器、采集、显示或格式桥接。
HALCON runtime、license 或符号缺失时必须返回明确错误，不允许 fallback。
```

### 4.2 分层约束（新增）

```text
按第 2 节分层契约确定改动落点，不得跨层：
- UI 与交互逻辑放 ColorRecognitionDialog，不得下沉到 Adapter 或 Runner。
- 配置写入只在 Dialog::toToolConfig() / loadFromConfig()，配置读取只在 Adapter::run()。
  新增字段必须两头都改，并在第 3 节字段注册表登记。
- 算法核心只在 ColorRecognitionHalconRunner，Adapter 不写算法，Dialog 不调 HALCON。
- payload / overlay 字段名以第 3 节注册表为准，UI 侧只读不造新名。
- HALCON runtime / so 路径走 HalconRuntimePaths，不在 Runner 硬编码。
功能开发中不顺带做跨文件重构；如需调整分层，单独立项。
```

### 4.3 UI 约束

```text
UI 必须遵守当前颜色识别界面布局：
- 左侧白底黑字参数区。
- 右侧图像预览区。
- 基础 / 全部 分段切换。
- 配置项按卡片分区。
- 控件颜色保持白底黑字。
- 检测 ROI、模板样本 ROI、屏蔽区域的交互状态不能互相污染。
```

### 4.4 兼容约束

```text
必须兼容旧模板和旧 ToolConfig。
不得删除已有 params / judgeRule 字段。
新增字段必须给默认值和旧配置回退策略。
ToolConfig.roiNormalized 继续保存通用 ROI 或圆形 ROI 外接矩形。
payload 中新增结果字段必须名称稳定，方便 UI 和日志读取，并登记到第 3 节注册表。
```

### 4.5 位置修正约束

```text
颜色识别已按 FID 公共规范接入位置修正占位链路。
UI 文案必须保持：
- 独立位置修正使能 ⓘ
- 位置修正
- 默认来源 1 基准图.位置修正信息
配置字段必须保持：
- params.enablePositionCorrection
- params.positionCorrectionSource
Adapter 必须解析并透传到 ColorRecognitionHalconConfig。
Runner payload 必须输出：
- enablePositionCorrection
- positionCorrectionSource
- positionCorrectionApplied
- positionCorrectionReason
当前尚未实现实际位置补偿时，必须固定输出：
- positionCorrectionApplied=false
- positionCorrectionReason=not implemented
不允许开关开启后静默忽略，也不允许假报已应用。
```

## 9. 常见反例

### 9.1 需求太泛

```text
优化颜色识别算法。
```

问题：没有目标、没有验收、没有范围。

### 9.2 缺少约束

```text
加一个颜色分割功能，怎么方便怎么做。
```

问题：可能导致 OpenCV 或自写算法进入核心链路，违反 HALCON 前置规则。

### 9.3 缺少兼容

```text
把亮度逻辑改成新的。
```

问题：没有说明旧 H/S、H/S/V 样本如何处理，容易造成旧模板无结果。

### 9.4 缺少验证

```text
改完告诉我。
```

问题：没有测试命令和验收标准，无法判断是否真的完成。

### 9.5 分层错位（新增）

```text
在 Adapter 里加个新控件，顺便把算法也写了。
```

问题：Adapter 不写算法、不造 UI 控件；控件归 Dialog，算法归 Runner。按第 2 节分层契约，跨层改动会让 2000 行的 Dialog 进一步失控。

### 9.6 配置只改一头（新增）

```text
新增 params.xxx 字段，在 Adapter 解析一下。
```

问题：只改读取侧（Adapter），没改写入侧（Dialog::toToolConfig）和回显（loadFromConfig），导致字段保存不了或读不到。新增字段必须两头都改并登记注册表。
