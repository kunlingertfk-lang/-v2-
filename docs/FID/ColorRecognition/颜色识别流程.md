# 颜色识别流程

本文档按当前代码已复现的颜色识别功能整理整体工作流程。文档重点把 UI 设计布局、控件接口实现、配置数据流和 HALCON 算法实现分离描述，便于后续新增功能时按层接入。

配置兼容规则：

- 如果 `colorModel.templates` 存在，优先使用当前 `activeTemplateId` 对应模板。
- 如果是旧配置，没有 templates，则按旧字段构造 `legacy_template`。
- `detectRegionType=circle` 时读取 `detectCircleNormalized`；否则按矩形 ROI。
- `ToolConfig.roiNormalized` 继续保存圆形 ROI 外接矩形，保证旧链路可读取。
- `knnK` 和 `knnDistance` 保留在配置中，但当前算法不使用。

## 5. 算法实现

### 5.1 HALCON 算子链

颜色识别核心算法必须走 HALCON runner，不允许使用 OpenCV 或自写算法替代核心识别。

```text
cv::Mat
        |
        v
图像预处理和桥接
  - 灰度图转三通道
  - 四通道转 BGR
  - BGR 桥接为 HALCON image
        |
        v
HALCON 图像链
  - gen_image_interleaved
  - decompose3
  - trans_from_rgb(..., "hsv")
        |
        v
检测 region
  - rectangle: gen_rectangle1
  - circle: gen_circle
  - mask: gen_region_polygon + difference
        |
        v
有效 domain
  - reduce_domain
        |
        v
直方图特征
  - gray_histo_range(H)
  - gray_histo_range(S)
  - gray_histo_range(V, brightnessEnabled=true)
        |
        v
归一化并拼接特征
```

### 5.2 特征维度

```text
sensitivity=low     -> 每通道 8 bins
sensitivity=medium  -> 每通道 16 bins
sensitivity=high    -> 每通道 32 bins

brightnessEnabled=false
  -> H + S
  -> lightingNormalizationMode=hue_saturation_priority

brightnessEnabled=true
  -> H + S + V
  -> lightingNormalizationMode=include_value_channel
```

当前 runner 支持 H/S 与 H/S/V 之间的兼容对齐：

```text
当前查询特征 H/S     + 历史样本 H/S/V -> 截取样本 H/S 前缀比较
当前查询特征 H/S/V   + 历史样本 H/S   -> 截取查询 H/S 前缀比较
当前查询特征同维度    + 当前样本同维度 -> 直接比较
其他维度不匹配        -> 过滤样本
```

### 5.3 判别方式

#### 主颜色占比

`colorDecisionMode=dominant_ratio` 是当前新版默认模式。

```text
queryFeature
        |
        v
遍历可用样本
        |
        v
计算 query 与 sample 的直方图交集相似度
        |
        v
按 classId 聚合每类最大覆盖量
        |
        v
classCoverage / sum(classCoverage)
        |
        v
labelAreaRatios
        |
        v
选择占比最大的类别作为 predictedLabel
```

输出规则：

- `rating = dominantColorRatio`。
- `score = dominantColorRatio * 100`。
- `comparisonMethod=dominant_color_ratio`。
- `scoreFormula=dominant_color_ratio_x100`。

说明：当前主颜色占比是基于直方图覆盖量的面积占比近似，不是逐像素真实分割面积。后续若要升级为真实颜色区域面积统计，应接入 HALCON 颜色分割或聚类接口。

#### 整体相似度

`colorDecisionMode=histogram_intersection` 是旧版兼容模式。

```text
queryFeature
        |
        v
遍历每个样本
        |
        v
similarity = sum(min(queryFeature, sampleFeature))
             / min(sum(queryFeature), sum(sampleFeature))
        |
        v
选择 similarity 最大的样本
        |
        v
样本 classId -> predictedLabel
```

输出规则：

- `rating = similarity`。
- `score = similarity * 100`。
- `comparisonMethod=histogram_intersection`。
- `scoreFormula=histogram_intersection_similarity_x100`。

### 5.4 OK/NG 判断

```text
runner 得到 predictedLabel 和 score
        |
        v
judgeRule.mode
        |
        +-- min_score
        |     +-- score >= minScore -> OK
        |     +-- score < minScore  -> NG
        |
        +-- category
              +-- predictedLabel == expectedLabel -> OK
              +-- predictedLabel != expectedLabel -> NG
```

类别判断模式下，分数仍会输出并显示，但 OK/NG 只看预测类别是否等于目标类别。

### 5.5 异常与边界

| 场景 | 返回状态 |
| --- | --- |
| 色谱特征 | `unsupported_feature` |
| 空图像 | 明确错误，不崩溃 |
| 无效 ROI | `invalid_roi` |
| 无模板样本 | `no_model_samples` |
| 样本维度不可比较 | `invalid_model_samples` |
| 屏蔽区域完全覆盖检测 ROI | `masked_roi_empty` |
| 目标类别为空 | `invalid_expected_label` |
| HALCON runtime 加载失败 | `halcon_load_failed` |
| HALCON 符号缺失 | `halcon_symbol_missing` |

## 7. 兼容与预留接口

### 7.1 已保留兼容

- `histogram_intersection` 保留旧版整体相似度逻辑。
- 旧配置没有 `colorModel.templates` 时，会按 legacy 字段恢复模板。
- 圆形 ROI 使用 `ToolConfig.roiNormalized` 保存外接矩形，新增圆形字段保存真实圆参数。
- K 值和 KNN 距离字段仍保存和读取，但 payload 标记 `knnDistanceApplied=not_used_histogram_intersection`。
- 亮度开关导致的 H/S 与 H/S/V 特征差异会自动对齐到 H/S 前缀比较。

### 7.2 预留但未实现

- `featureType=spectrum` 色谱特征。
- `colorDecisionMode=halcon_color_segmentation` HALCON 颜色分割/聚类模式。
- 真实逐像素颜色面积统计。
- 模板样本圆形 ROI。

## 8. 后续功能接入指引

新增颜色识别后续功能时建议按以下层次处理，避免把界面逻辑和算法逻辑混在一起：

```text
1. UI 层
   - ColorRecognitionDialog
   - ColorTemplateDialog
   - FrameViewHelper 交互能力

2. 配置层
   - ToolConfig.params
   - ToolConfig.judgeRule
   - 模板 JSON
   - 导入导出兼容

3. Adapter 层
   - ColorRecognitionAdapter::toRunnerConfig()
   - ToolResult 字段映射

4. HALCON Runner 层
   - ColorRecognitionHalconConfig
   - extractFeature()
   - run()
   - payload 和 overlays

5. 验证层
   - smoke test
   - qmake
   - make
   - git diff --check
```

后续接入规则：

- 新增算法能力前，先确认 HALCON 24.11 是否存在对应算子或过程。
- 算法核心只能写在 HALCON runner 链路中。
- UI 新控件必须先写入 `ToolConfig.params` 或 `judgeRule`，再由 Adapter 映射到 runner。
- runner 输出给 UI 的新增结果字段必须进入 payload，并尽量保持名称稳定。
- 对旧模板、旧配置和旧样本特征必须给出明确兼容策略。
- 新功能至少补一个 smoke 覆盖成功路径和一个异常路径。
