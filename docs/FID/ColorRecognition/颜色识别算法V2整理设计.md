# 颜色识别算法 V2 整理设计

## 1. 状态与目标

- 日期：2026-07-15。
- 状态：阶段 A（HSV 后端可靠性修复）、HSV-C1 类级 Top-N 分类器、GMM B1 核心建模、B2 模型生命周期和 B3 生产检测闭环均已实施。
- 范围：颜色识别工具，不改动颜色比较 `ColorComparison` 链路。
- 目标：清理当前无效的 KNN 运行时参数，保留已修复的 HSV H/S 直方图作为可选生产后端，并新增 HALCON CIELAB GMM 颜色模板分类后端；两者允许由用户显式选择和对比，但模型、评分和错误状态相互隔离，不自动 fallback。

V2 不在旧的 `dominant_ratio` 相似度公式上继续调参。当前“类别最佳样本相似度 / 所有类别相似度之和”既不是严格的模板相似度，也不是像素面积占比。V2 必须分开“预测颜色类别”、“分类得分”和“像素面积诊断”三种语义。

## 2. V2 边界和整理结论

### 2.0 独立实现边界

当前颜色识别与颜色比较保持相互独立：

- 颜色识别只在 `ColorRecognitionDialog` / `ColorRecognitionAdapter` / `ColorRecognitionHalconRunner` / 颜色识别模型链内实现 V2。
- 颜色比较继续使用 `ColorComparisonDialog` / `ColorComparisonAdapter` / `ColorComparisonHalconRunner` / `ColorComparisonModelV2`。
- 本轮不抽取公共 HALCON 动态加载器、tuple/object RAII、图像桥接、ROI/mask 构造或直方图工具。
- 不允许颜色识别调用颜色比较 Runner，也不允许颜色比较调用颜色识别 Runner 作为生产链依赖。
- 即使两边存在相同的 HALCON 算子或少量重复代码，本阶段也优先保证各自功能闭环、模型语义和回归稳定。

公共底座只在后期优化阶段单独立项。立项前必须先确认两个工具的模型 schema、算子链、错误状态、线程模型和测试均已稳定；抽取范围仅限无业务语义的基础设施，不合并颜色识别与颜色比较的模型、评分和 payload。

### 2.1 KNN 参数

`knnK` 和 `knnDistance` 从算法与持久化合同中删除，因为当前 Runner 没有调用 HALCON KNN，这两个字段对结果没有任何影响。

删除范围：

- 从 `ColorRecognitionHalconConfig` 删除 `knnK` / `knnDistance`。
- Adapter 不再解析两个字段。
- Dialog 不再将两个字段写入新的 `ToolConfig` / 模板 JSON。
- Runner payload 删除具有误导性的 `knnDistanceApplied`。
- 读取旧 JSON 时允许出现这两个字段，但忽略且不再回写，保持向后读取兼容。

UI 接口保留原则：

- 当前代码没有可操作的 K 值/距离控件，只有模板数据字段和摘要中的 `K=3`；V2 必须删除该摘要文案，避免伪报 KNN 已生效。
- 在 `ColorTemplateDialog` 高级参数卡中保留命名清晰的 KNN UI 扩展槽位/接入函数，便于未来单独实现 HALCON KNN；本轮不创建可见的假控件。
- 如后续为设计展示创建 KNN 控件，在算法实现前必须 disabled 并标注“预留，当前不参与计算”。
- 预留 UI 值不进入 `ToolConfig`、Adapter 或 Runner，不得显示伪的“HALCON 默认 KNN”应用状态。
- 未来实现 KNN 时需单独升级模型 schema，重新建立 UI 到 HALCON classifier 的完整闭环，不得直接复活历史 JSON 字段。

### 2.2 位置修正接口

位置修正本轮不实现算法，只保留可以在未来接入上游位姿结果的合同。

不新建颜色识别专用的位置修正结构，直接复用已有 `src/toolcore/PositionCorrection.{h,cpp}` 的公共合同：

```text
PositionCorrectionConfig
  enabled: bool
  sourceId: string           # 稳定 toolId
  source: string             # 显示文案/旧配置兼容
```

配置继续使用项目统一字段：

```text
enablePositionCorrection
positionCorrectionSourceId
positionCorrectionSource
```

当前阶段行为固定为：

- Dialog 和 Adapter 通过 `PositionCorrection::writeParams(...)` / `fromParams(...)` 读写，不手写另一套字段。
- `enabled=false`：正常运行，payload 由 `writeNotAppliedPayload(...)` 写入 `positionCorrectionApplied=false`。
- `enabled=true`：在进入颜色分类前返回明确的 `unsupported_position_correction`，不得继续使用未修正 ROI 并伪装功能已开启。
- UI 可保留开关和来源选择接口，但在未实现前默认 disabled 并显示“待实现”。
- 来源配置必须保存稳定 `positionCorrectionSourceId`，界面文案只保存到 `positionCorrectionSource` 用于显示和旧配置兼容。

### 2.3 HSV 与 GMM 双后端长期共存

颜色识别新增稳定后端选择字段：

```text
recognitionBackend = hsv_histogram | cielab_gmm
```

两套后端均属于颜色识别内部实现，不与颜色比较共享 Runner 或模型。基本规则：

- `hsv_histogram` 使用阶段 A 已修复的 `hs_joint_histogram_v2`/HSV 特征签名和直方图类别相似度。
- `cielab_gmm` 使用 CIELAB a/b 或 L/a/b 像素级 GMM、rejection 和真实类别面积诊断。
- 用户选择哪个后端，生产 `run()` 就只执行该后端；所选模型缺失、stale 或运行失败时返回该后端的明确错误，不自动切换另一后端。
- 两套后端不得读取或解释对方的派生模型。HSV `feature[]` 不能训练 GMM，GMM serialized item 也不能转成 HSV 模板。
- 公共样本只限原始无损 ROI 图、标签、classId、ROI 和输入元数据；HSV 特征与 GMM 产物分别保存在各自 `backendModels` 节点。
- 切换后端不删除另一套已就绪模型；切回时只要其签名仍匹配即可继续使用。

以下字段只属于 HSV 后端：

```text
featureType
sensitivity
brightnessEnabled
colorDecisionMode
classifierVersion
classifierParamsHash
```

#### 2.3.1 HSV `histogram_2dim_hs` 收口合同

- 新建颜色模板默认使用 `featureType=histogram_2dim_hs`，UI 显示“二维 H/S 直方图（推荐）”。
- 旧 `featureType=histogram` 继续映射为“一维 H/S(/V) 直方图（兼容）”，不自动升级成二维特征。两者的 schema、长度和签名不同，用户切换后必须重新采样。
- 二维模式只使用 H/S 联合分布，`brightnessEnabled` 固定为实际 `false`；UI 禁用亮度控件。即使旧配置请求 `brightnessEnabled=true`，Runner 也将其规范化为实际 `false`，且该无效请求不进入二维特征签名。
- payload 中 `brightnessEnabled` 表示实际是否使用亮度，`requestedBrightnessEnabled` 仅记录配置请求值。不得用请求值冒充实际特征合同。
- Hue 使用循环强平滑，Saturation 使用非循环弱平滑；不再对二维矩阵做 V 轴或无业务含义的第三维平滑。
- `spectrum` 只保留禁用的预留入口，不参与保存和运行。

#### 2.3.2 HSV-C1 类级 Top-N 分类合同

- 新模板默认使用 `classifierVersion=hsv_category_topn_intersection_v1`。检测 ROI 与每个样本仍通过 HALCON 直方图交集计算相似度，不引入 OpenCV 或自写距离。
- 按 `classId` 分组后，每类取相似度最高的最多 3 个 ROI，使用等权均值作为类别分数：`classScore = mean(top3(sampleSimilarity)) * 100`。样本不足 3 个时使用该类全部样本，不跨类别补齐。
- 类别排序固定为：Top-N 均值、Top-N 最差相似度、最佳样本相似度、标签声明顺序。`matchedSampleIndex` 仅指获胜类别中最相似的诊断样本，不再代表最终类别分数来源。
- 输出第二名分数和 `classMargin=bestScore-secondClassScore`；当前 margin 仅用于诊断，不参与 OK/NG。最低得分仍是唯一 HSV 置信度门槛。
- 分类器合同与 HSV 特征合同分离。`classifierVersion/classifierParamsHash` 改变不要求重提直方图；未知版本或 hash 不匹配必须明确报错，禁止仅凭特征长度运行。
- 缺少分类器字段的旧模板迁移为 `hsv_category_best_sample_v2`，保持历史“每类最佳单样本”结果；用户显式“重新提取 HSV 特征”后升级到当前 Top-N 分类器。
- 固定 Top-N 不是 KNN：没有跨类别邻居投票，没有可调 K/距离，也不恢复已删除的 `knnK/knnDistance`。

整理规则改为：

- 旧配置没有 `recognitionBackend` 且存在上述字段时，迁移为 `hsv_histogram`，保持当前可运行行为。
- 新 JSON 将 HSV 参数写入 `backendConfigs.hsvHistogram`；GMM 参数写入 `backendConfigs.cielabGmm`，禁止使用同名扁平字段表达两种含义。
- `brightnessEnabled=true` 不映射为 GMM 的 `L/a/b`，因为 HSV V 与 CIELAB L 不是同一特征。
- 从 HSV 切到 GMM 时，仅检查 GMM 模型状态；没有 GMM 模型则提示“建立 GMM 模型”，不得把 Ready 的 HSV 模型整体标坏。
- 修改 HSV bins、亮度参与或平滑合同，只将 HSV 模型标为 stale；修改 GMM 通道、采样或训练参数，只将 GMM 模型标为 stale。
- 修改公共标签、classId、ROI 样本图或输入签名时，两套后端模型都进入 stale。

### 2.4 手册产品语义对齐

参考 `docs/智能相机客户端_用户手册_V3.2.2_20260127.pdf` PDF 第 274–278 页（手册印刷页 265–269），颜色识别的产品合同是：

- 使用 1–10 张图像和标签 ROI 训练多类颜色模板。
- 对检测 ROI 做整体颜色分类，输出颜色名称、最佳分数和相似度语义的结果。
- 判定方式为最低分数或目标类别。
- 亮度参与可关闭以提高光照变化下的稳定性。

因此 GMM 的主产品语义必须保持“颜色模板分类”。每类像素面积可作为可解释的得分来源、诊断和高级判定，但不将本工具重定义为“颜色面积”工具。

### 2.5 HSV 生产后端特征合同

HALCON `histo_2dim(Region, ImageCol, ImageRow)` 将第一个图像值映射到输出行，第二个图像值映射到输出列。阶段 A 的唯一规范布局为：

```text
HALCON output row    = Hue
HALCON output column = Saturation
feature index        = hueBin * saturationBins + saturationBin
```

平滑使用各向异性 3×3 核，不扩大到 5×5：

```text
hueKernel        = [0.25, 0.50, 0.25]  # ±1 bin，循环
saturationKernel = [0.15, 0.70, 0.15]  # ±1 bin，不循环
smoothingKernelVersion = hs_anisotropic_3x3_v2
```

Hue 的首尾 bin 互为相邻项；Saturation 越界权重不得用 `qBound` 重复叠加到边界，只保留合法邻居并重新归一化。`minSaturationForHue`、轴顺序、展平顺序、bin 数和平滑核版本全部进入特征签名，任一变更都进入 `StaleNeedsResample`。

## 3. 工业场景推荐算法

### 3.1 结论

推荐新增并默认用于新建复杂颜色模板的算法是 **HALCON CIELAB 像素级 GMM 监督颜色模板分类**。已修复的 HSV H/S 直方图后端继续作为轻量、少样本和纯色场景的可选生产算法。用户应基于现场验证选择后端，系统不自动决定“更优算法”。

默认特征使用 CIELAB `a/b` 两通道：

- `a/b` 主要表示色彩，比直接使用 RGB 更适合颜色类别分离。
- 不存在 HSV Hue 在 0/255 处的环形断点问题。
- 默认不使用 `L`，降低照明强度波动对颜色分类的影响。
- 仅当业务需要区分同色的深浅/明暗时，才切换到 `L/a/b` 三通道模型，切换后模型必须重建。

GMM 适合当前“每个标签包含多个 ROI 样本”的产品结构，可学习同一颜色在正常光照、表面和批次波动下的分布，也能通过 rejection threshold 将不确定像素留为未分类，避免强制归入最接近颜色。

后端推荐边界：

| 场景 | 优先建议 | 原因 |
|---|---|---|
| 类别是单一纯色、每类仅 1–3 个 ROI、算力敏感 | HSV H/S 直方图 | 建模轻、解释直接、少样本即可建立模板 |
| 同类存在批次波动、表面反光、颜色分布多峰 | CIELAB GMM | 可学习类内分布并拒绝未知像素 |
| 需要真实类别像素覆盖率和未分类占比 | CIELAB GMM | GMM 分类 region 可直接做面积统计 |
| Hue 首尾附近的红色类别 | 两者均可 | HSV 已实现 Hue 环绕；GMM 没有 Hue 环断点 |
| 需要区分同色深浅 | GMM L/a/b 或 HSV 开启亮度后实测 | 两种得分语义不同，必须用现场独立验证集比较 |

输入支持 8-bit 和 16-bit 三/四通道彩色图，统一通过 HALCON 映射到 RGB `real [0,1]` 后再做颜色空间转换。16-bit 必须提供 `validBits` 和 `bitShift`，不许用 OpenCV `convertTo(CV_8U)` 截断或饱和。Mono 图像没有颜色信息，返回 `unsupported_mono_for_color_recognition`，不伪转 BGR。

16-bit 容器的规范化合同固定为：

```text
1 <= validBits <= 16
0 <= bitShift <= 15
validBits + bitShift <= 16
code = floor(raw / 2^bitShift)
maxCode = 2^validBits - 1
0 <= code <= maxCode
normalized = code / maxCode
```

Runner 先用 HALCON `bit_rshift` 完成右对齐（`bitShift=0` 时跳过），用 `min_max_gray` 校验 `code`，再 `convert_image_type(...,'real')` 并按 `1/maxCode` 执行 `scale_image`；不在 C++ 像素循环中自写颜色处理。`raw` 不符合声明的有效位范围时返回 `pixel_value_out_of_range`，不静默 clamp。8-bit 固定为 `validBits=8, bitShift=0`。RGBA 的 alpha 通道只在图像桥接阶段明确丢弃，不进入 CIELAB/GMM 特征；RGB/BGR/RGBA/BGRA 顺序必须由 `pixelFormat` 决定并进入输入签名。

```text
8/16-bit RGB
  → HALCON RGB real [0,1]
  → trans_from_rgb(..., 'cielab')
  → a/b 或 L/a/b
  → GMM
```

### 3.1.1 固定建模参数

V2 首版不将 GMM 训练细节暴露给普通 UI，使用可复现的固定默认值：

| HALCON 参数 | 所属调用 | a/b 模式 | L/a/b 模式 | 说明 |
|---|---|---:|---:|---|
| `NumDim` | `create_class_gmm` | 2 | 3 | 与颜色通道数一致 |
| `NumCenters` | `create_class_gmm` | 按每类 ROI 数分级 | 按每类 ROI 数分级 | 每类 1–4 ROI 为 `[1,1]`；5–9 ROI 为 `[1,2]`；不少于 10 ROI 为 `[1,3]` |
| `CovarType` | `create_class_gmm` | `full` | `full` | 学习通道相关性 |
| `Preprocessing` | `create_class_gmm` | `none` | `none` | 避免隐式改变通道语义 |
| `NumComponents` | `create_class_gmm` | 0（忽略） | 0（忽略） | `none` 时不参与计算，按 HALCON 示例显式传 0 |
| `RandSeed` | `create_class_gmm` | 42 | 42 | 固定中心初始化随机种子，保证训练可复现 |
| `Randomize` | `add_samples_image_class_gmm` | 0.0 | 0.0 | CIELAB 训练特征已是 HALCON real，不再对规范化实数特征添加整型量化噪声 |
| `MaxIter` | `train_class_gmm` | 100 | 100 | EM 最大迭代次数 |
| `Threshold` | `train_class_gmm` | `1e-4` | `1e-4` | EM 终止阈值 |
| `ClassPriors` | `train_class_gmm` | `uniform` | `uniform` | 避免各类样本像素数不均造成先验偏置 |
| `Regularize` | `train_class_gmm` | `1e-4` | `1e-4` | 防止协方差矩阵奇异 |

`gmmRejectionThreshold` 是 HALCON `classify_image_class_gmm` 的 K-sigma 像素拒识概率阈值，不是 0–1 线性置信度。默认 `0.0001`，放在“全部”页高级参数中；数值越高拒识越严格，达到 `0.01` 时 UI 必须提示高拒识风险。其他 GMM 参数仅写入模型签名和诊断，不在首版 UI 开放。

`NumCenters` 按 `classIdOrder` 为每类生成 `[min,max]`，最终传入长度为 `2 * NumClasses` 的 tuple；不得用样本最多类或最少类的分级覆盖所有类。这与 HALCON `create_class_gmm` 针对每类分别指定中心数上下界的合同一致。

### 3.1.2 备选方案取舍

| 方案 | 结论 | 原因 |
|---|---|---|
| 已修复 HSV H/S 直方图类别相似度 | 保留 | 少样本和纯色场景成本低；不提供 GMM 的真实分类面积语义 |
| HSV H/S + `class_2dim_sup` | 不作首选 | 需维护每类二维特征区，Hue 环形边界处理和多类区域重叠规则更复杂 |
| HALCON 像素级 KNN | 本轮不采用 | 需重新定义 K/距离/样本平衡和性能合同，与清理当前伪 KNN 字段的目标冲突 |
| HALCON MLP | 本轮不采用 | 少量独立 ROI 时更易过拟合，且对训练分布之外的颜色可能给出很高置信度，通常还需拒绝类和更多参数 |
| CIELAB a/b GMM | 采用 | 能直接从 ROI 样本训练多类像素分布，支持 rejection，并输出可用 `area_center` 统计的类别 region |

### 3.3 模型建立

```text
每个标签的样本图 + 样本 ROI
        ↓
HALCON image
        ↓
trans_from_rgb(..., 'cielab')
        ↓
compose2(A, B) 或 compose3(L, A, B)
        ↓
按 classId 生成互不重叠的 ClassRegions
        ↓
create_class_gmm
        ↓
add_samples_image_class_gmm（可多图多次追加）
        ↓
train_class_gmm
        ↓
serialize_class_gmm + model signature/hash
```

样本合同：

- 每个样本必须保存稳定 `sampleId`、`classId`、无损 ROI 彩色图、尺寸、图像 SHA-256 和输入签名。
- 新 GMM 样本保存无损 RGB/RGBA ROI 图和完整像素元数据；8-bit 和 16-bit 样本都先用 HALCON 映射到统一 `real [0,1]` 域。缺图、元数据缺失、解码失败或 hash 不一致时模型为 `Invalid`。
- 旧 `feature` 直方图数组不是 GMM 训练数据；迁移后只保存在 `backendModels.hsvHistogram.samples`。公共样本节点不写派生特征，新的 HSV 特征仍写入 HSV 后端模型节点。
- 稳定 `classId` 不要求从 0 开始或数值连续。Runner 以 `classIdOrder` 中的下标作为 HALCON `classIndex`，建立 `classId ↔ classIndex` 显式映射。
- 对每张单类 ROI 样本图，`add_samples_image_class_gmm` 的对应 `classIndex` 位置传入该 ROI 的确定性子采样 region，其他类传空 region；多张样本通过多次调用追加。
- 每类硬性最少 1 个有效 ROI 且累计不少于 256 像素；1–2 ROI 只可进入 `ReadyWithWarning`，3 ROI 是工程最低值，5–10 ROI 是常规推荐，反光/纹理/批次差异明显时建议 10–20 ROI。
- 同一 ROI 内像素高度相关，不得用像素数代替独立工况样本数。每类训练像素数取 `min(所有类可用像素数, 10000)`，保证类间等量；类内按 `sampleId` 排序并尽量均分到各 ROI，剩余配额按排序顺序分配，小 ROI 不足的配额继续向本类其他 ROI 重分配。
- 单个 ROI 通过 HALCON `get_region_points` 取得稳定行扫描点序列，以等间索引选取无重复点，再用 `gen_region_points` 构造子采样 region。抽样算法版本、每类实际像素数和 10,000 上限必须写入模型签名；不依赖非确定的 UI 列表顺序。
- 样本 ROI 必须尽量只包含当前标签颜色；边缘背景、高光、文字或其他颜色会被作为该类训练像素，UI 应在添加样本时给出纯净 ROI 提示。
- 同一个 `classId` 必须唯一映射到一个非空标签；类别顺序写入 `classIdOrder`，不依赖 UI 列表当前排序。

首版不隐式创建“背景类”或“其他类”。非已知颜色由 GMM rejection 保留为未分类；如用户确实需要背景作为可报告类别，必须显式创建标签和样本。

模型签名至少包含：

```text
modelSchemaVersion
algorithmVersion = halcon_cielab_gmm_classification_v1
featureSchemaVersion = cielab_gmm_pixel_classification_v1
colorSpace = cielab
channels = ab | lab
classIdOrder
gmmCenters
covarianceType
samplingAlgorithmVersion
samplesPerClass
maxSamplesPerClass
halconVersion
trainingDataHash
```

签名或样本发生变化时将模型标记为 `StaleNeedsResample`，不允许仅凭特征长度、类别数或数组尺寸自动对齐。

### 3.4 检测、模板分类与面积诊断

```text
检测图像
  → HALCON CIELAB a/b（或 L/a/b）
  → 检测 ROI - 屏蔽区 = effectiveRegion
  → reduce_domain
  → classify_image_class_gmm
  → 各 ClassRegion 与 effectiveRegion 取 intersection
  → area_center 统计每类真实像素面积
```

面积与得分定义：

```text
effectiveArea      = 有效检测 ROI 面积
classArea[i]       = 类别 i 的分类区域面积
classifiedArea     = sum(classArea[i])
unclassifiedArea   = max(effectiveArea - classifiedArea, 0)
classRatio[i]      = classArea[i] / effectiveArea
classifiedCoverage= classifiedArea / effectiveArea
predictedClass      = argmax(classArea[i])
predictedClassRatio = max(classRatio[i])
categoryConfidence  = predictedClassArea / max(classifiedArea, 1)
bestScore           = predictedClassRatio * 100
```

分母必须是 `effectiveArea`，不能是 `classifiedArea`。否则当大量像素被 rejection 拒绝时，剩余少量像素仍可以伪造 100% 的预测类占比。

`ToolResult.text` 和主类别输出使用 `predictedClass`，`ToolResult.score` 使用 `bestScore`。`scoreMeaning` 固定为 `accepted_predicted_class_pixel_ratio`，表示有效 ROI 内被模型可靠接受为预测颜色的像素比例；它不是 GMM 后验概率，也不得标注为颜色面积工具的测量结果。

为对齐手册的“最佳分数 / 相似度”输出名称，V2 对外保留 `similarity`，首版定义为 `bestScore` 的兼容别名，同时输出 `similarityAliasOf=bestScore` 和相同的 meaning。它不是另一个 GMM 后验概率；如后续要提供独立的模板相似度，必须另行定义算法、标定阈值并升级 schema。

`predictedClassRatio`、`categoryConfidence` 和 `classifiedCoverage` 是三个独立可解释指标：分别表示预测类在整个有效 ROI 中的接受比例、已分类像素中的类别纯度、以及整个 ROI 的模型覆盖程度。不将三者混成不透明的加权分数。

`classify_image_class_gmm` 只返回与 `classIdOrder` 顺序对应的 `NumClasses` 个 region，不额外返回“未分类” region。`unclassifiedArea` 必须由 `effectiveArea - classifiedArea` 得到，且因区域计算误差对结果做 `[0,effectiveArea]` 边界夹紧。

## 4. UI 语义整理

结果判断区保持手册的“最低分数 / 类别判断”产品语义。算法后端与业务判定分成两个控件，不再把旧 `dominant_ratio` 和“整体相似度”作为顶层算法名称：

```text
识别算法：HSV 直方图 | CIELAB GMM
HSV 参数：H/S | H/S/V、敏感度（仅 HSV 时显示）
GMM 颜色特征：a/b | L/a/b（仅 GMM 时显示）
最低分数：0..100
最低类别置信度：0..100（仅 GMM）
最低有效分类覆盖率：0..100（仅 GMM）
目标类别：<label>
```

后端默认规则：读取旧配置和新建模板均默认 `hsv_histogram`；用户可显式切换到 `cielab_gmm`，但在 GMM 模型尚未建立前不得静默运行 HSV。

展示结果至少包含：

- 预测颜色名称。
- 最佳分数及其 `scoreMeaning`。
- 类别置信度（已分类像素中的类别纯度）。
- 有效分类覆盖率。
- 未分类占比。
- 每个类别的接受像素面积和占比（诊断）。
- ROI、屏蔽区、耗时和模型状态。

### 4.1 模板编辑与建模交互

`ColorTemplateDialog` 保持当前样本和标签编辑职责。保存时只构建当前选中且 stale 的后端模型，另一后端的 Ready 模型保持不变。GMM 建模闭环为：

```text
点击保存
  → 校验标签、classId、每类样本数和 PNG 完整性
  → UI 进入 Building，禁用样本增删、保存和参数修改
  → QtConcurrent 异步调用 Adapter::buildGmmTemplateModel
  → generation 门禁丢弃旧任务结果
  → Ready：写入新模型并 accept
  → 失败：保留在当前窗口，显示可定位错误，不覆盖上一个 Ready 模型
```

公共样本或标签变化会同时使 HSV/GMM 模型 stale；仅 `colorChannels` 或 GMM 建模参数变化只使 GMM stale；仅 HSV 特征参数变化只使 HSV stale。`gmmRejectionThreshold`、最低分数、最低类别置信度和最低覆盖率是检测/判定参数，修改它们不需重建模型。

### 4.2 主界面控件

- 删除模板摘要中的 `K=...`。
- 增加“识别算法”下拉框：`HSV 直方图` / `CIELAB GMM`，保存稳定值 `hsv_histogram` / `cielab_gmm`。
- 后端切换只控制对应参数卡、模型状态和测试入口，不删除另一后端模型，不做自动 fallback。
- 增加“后端对比测试”开发/调试入口：冻结同一帧和同一 effective ROI，顺序运行两套后端并并列展示；不把对比模式保存为生产 `recognitionBackend`。
- 原“判别方式”改为“判定依据”：`minimum_score` / `expected_class`。
- 保留“最低得分”文案，其实际语义由 `scoreMeaning=accepted_predicted_class_pixel_ratio` 明确报告。
- `expected_class` 时显示稳定 `expectedClassId` 对应的目标类别。
- “全部”页增加 `gmmRejectionThreshold`、“最低类别置信度”和“最低有效分类覆盖率”。
- 模型为 Empty/StaleNeedsResample/Invalid/Unsupported 时禁止测试运行；ReadyWithWarning 允许测试但必须持续显示“样本覆盖不足”。
- 位置修正保留现有统一 UI；未实现时显示“待实现”，不允许给用户造成已生效的印象。

UI 改动继续遵守 `.ui` + Dialog 代码双写约束，互斥判定方式使用 `QButtonGroup` 或单一 `QComboBox`，不用多个独立 checked 状态。

首版 UI 默认值：

```text

新建配置 recognitionBackend = cielab_gmm
colorChannels = ab
gmmRejectionThreshold = 0.0001   # 范围 0..1，UI 6 位小数，步长 0.0001；越高越严格

```

### 4.3 结果与 overlay

- 默认 overlay 只绘制检测 ROI/圆形 ROI、预测颜色名、最佳分数、类别置信度、有效覆盖率和 OK/NG，不把每个分类像素转成大量 `ToolOverlay`。
- 每类面积占比在结果区/诊断 payload 展示；如后续需要像素级伪彩色图，应作为颜色识别专用诊断图单独设计，不改变算法结果。
- 当帧失败或 measurement 无效时立即清空上一帧类别数据和结果 overlay，不得残留旧占比。
- 所有结果必须显示 `recognitionBackend` 和后端对应的 `scoreMeaning`。HSV 的类别相似度与 GMM 的接受像素比例不能直接比较数值大小。

### 4.4 后端对比测试

对比测试用于决定现场采用哪种算法，不参与正式 OK/NG 输出：

```text
冻结同一输入帧、输入元数据、ROI 和 mask
  → 校验 HSV 模型 Ready
  → 校验 GMM 模型 Ready/ReadyWithWarning
  → 分别运行 hsv_histogram 与 cielab_gmm
  → 并列记录预测类别、各自 scoreMeaning、耗时、错误状态
  → 在标注验证集上统计准确率、拒识率、帧间抖动和 P95 耗时
```

不得用单张图“谁分数高”判断后端优劣，因为两套 score 定义不同。建议至少按每类 20 张独立检测图、覆盖正常光照/偏暗/偏亮/反光/批次变化，比较类别准确率、NG 误报率、未知色拒识率和连续 30 帧结果抖动。

### 5.2 GMM 产物持久化

V2 首版将 HALCON GMM 序列化产物内联到模板 JSON，不引入外部绝对路径：

```text
serialize_class_gmm
  → get_serialized_item_ptr
  → 立即拷贝到 QByteArray
  → SHA-256
  → Base64
  → serializedGmmBase64
  → clear_serialized_item
```

加载时使用已确认存在的 `create_serialized_item_ptr(Pointer, Size, 'true', Handle)` 复制 `QByteArray` 数据，随后调用 `deserialize_class_gmm`；完成后通过 `clear_serialized_item` 释放 serialized item。不引入临时文件或自定义 GMM 格式。

内联产物校验规则：

- Base64 解码前检查长度，解码后不得超过 8 MiB。
- `serializedSize` 必须与解码字节数一致，`serializedSha256` 必须匹配。
- 产物损坏返回 `model_artifact_invalid`，不得自动重训或 fallback。
- 序列化产物只有在完整验证通过后才可进入 `ReadyWithWarning` 或 `Ready`。

### 5.4 `judgeRule` 和 score 语义

V2 保留手册中的两种业务判定。公共条件是最低分数和可选目标类别；类别置信度/有效覆盖率仅适用于 GMM：

```text
mode = minimum_score
  HSV score = mean(top3 sampleHistogramIntersection within predicted class) * 100
  GMM score = predictedClassRatio * 100
  ok = score >= minScore
       && (backend != GMM || categoryConfidence * 100 >= minCategoryConfidence)
       && (backend != GMM || classifiedCoverage * 100 >= minClassifiedCoverage)

mode = expected_class
  score = backend-specific score above
  ok = predictedClassId == expectedClassId
       && score >= minScore
       && (backend != GMM || categoryConfidence * 100 >= minCategoryConfidence)
       && (backend != GMM || classifiedCoverage * 100 >= minClassifiedCoverage)
```

新配置：

```json
{
  "mode": "expected_class",
  "minScore": 80,
  "minCategoryConfidence": 80,
  "minClassifiedCoverage": 90,
  "expectedClassId": 1
}
```

使用 `expectedClassId` 作为稳定判定键，`expectedLabel` 只用于显示和旧配置迁移。这样标签重命名不会改变判定类别。

`ToolResult.score` 是后端相关结果：HSV 为最佳类别直方图交集相似度百分比，GMM 为预测类接受像素占有效 ROI 的百分比。`categoryConfidence` 是 GMM 已分类像素中的预测类纯度。UI 必须同时读取 `recognitionBackend` 和 `scoreMeaning`，不能跨后端直接比较 score。

### 5.6 模型状态机

```text
每个后端无模型/无样本                       → Empty
该后端 schema、签名或训练数据已改变          → StaleNeedsResample
GMM 校验通过但任一类仅 1–2 ROI              → ReadyWithWarning
HSV 签名完整，或 GMM 每类至少 3 ROI           → Ready
该后端 JSON/hash/产物损坏                     → Invalid
该后端 schemaVersion 高于当前可读版本         → Unsupported
```

状态转换规则：

- HSV 仅在严格特征签名和全部样本校验通过后进入 Ready；GMM 仅在 `buildGmmTemplateModel()` 成功后进入 ReadyWithWarning/Ready。
- 状态按后端分别保存和判断；一个后端 Invalid/Stale 不阻止用户显式选择另一个 Ready 后端。
- GMM ReadyWithWarning/Ready 的训练数据或建模参数变化后，丢弃内存 GMM handle；可保留旧序列化字节用于诊断，但不得继续运行该 GMM。
- Invalid 和 Unsupported 不得自动转换为 StaleNeedsResample/Ready；用户必须重新采样或使用支持该 schema 的程序。
- 模型读取不触发隐式训练，避免打开方案时卡顿或悄然改变模型。

### 5.7 组件职责和公开接口

```text
ColorRecognitionModel.{h,cpp}
  - 强类型模型、JSON、hash、state 和严格验证

ColorTemplateDialog
  - 编辑标签/样本/通道，调度异步建模，不调 HALCON

ColorRecognitionDialog
  - 模板列表、检测 ROI、judgeRule、测试调度和结果展示

ColorRecognitionAdapter
  - ToolConfig → 强类型 config
  - buildGmmTemplateModel(request)
  - run(request)，按 recognitionBackend 精确派发
  - Runner result → ToolResult

ColorRecognitionHalconRunner
  - buildGmmTemplateModel(samples, buildConfig)
  - runHsvHistogram(image, hsvConfig)
  - runCielabGmm(image, gmmConfig)
  - HSV 与 CIELAB/GMM 的唯一 HALCON 实现位置，内部逻辑不互相 fallback

ColorRecognitionHalconRuntimeCache
  - 按规范化 so 路径缓存 dlopen handle
  - 按 Common / HsvHistogram / Gmm profile 延迟解析符号
  - 同一路径、同一 profile 只解析一次
```

`ColorRecognitionHalconRuntimeCache::acquire(path, profile)` 使用 mutex/once 语义保证线程安全，handle 保留到进程退出，不在每帧 `dlopen/dlsym/dlclose`。缺少 GMM 符号不得阻断 HSV 后端，缺少 HSV 专用符号也不得阻断 GMM；选择缺符号的后端时返回 `halcon_symbol_profile_missing`。该缓存只属于颜色识别，本轮不抽取颜色比较公共底座。

HSV 的特征提取保留为颜色识别内部后端接口；`compareHistogramBhattacharyya()` 不作为颜色识别判定接口，并在颜色比较 smoke 完成独立迁移后删除。颜色比较生产链始终不依赖颜色识别 Runner。

HALCON 函数指针表可跨线程共享，GMM handle 不跨线程共享。V2 首版在每次 Runner 调用所在线程内完成反序列化、分类和 `clear_class_gmm`；先用 smoke/连续测试量化耗时，如确实不达标再单独设计按 `serializedSha256 + threadId` 索引的颜色识别内部模型缓存。

missing_pixel_format_metadata

pixel_value_out_of_range

feature_signature_mismatch
invalid_roi
masked_roi_empty
model_empty

model_invalid
model_unsupported
model_artifact_invalid

halcon_symbol_missing

halcon_error

```

分类已成功但业务条件不满足时，返回 `success=true` / `measurementValid=true` / `ok=false` / `status=ng`，并在 payload 的 `judgeFailureReasons` 数组写入：

```

不得把“有效分类覆盖率不足”当作 HALCON 运行错误，也不得在该情况下沿用上一帧的结果或 overlay。

## 6. 兼容和迁移

- 旧配置缺少 `recognitionBackend` 时迁移为 `hsv_histogram`；满足阶段 A 严格签名的 HSV 模型继续运行，缺签名的更早模型只将 HSV 状态标为 `model_stale_needs_resample`。
- 旧直方图样本不能冒充 GMM 模型。切换到 GMM 后若没有 GMM 产物，提示“建立 GMM 模型”；即使旧 `roiImagePngBase64` 可解码，也不在打开方案时自动训练。
- 旧 `dominant_ratio` / `histogram_intersection` 映射到 HSV 后端内部兼容模式；新 UI 统一显示“HSV 类别相似度”，不再显示“主颜色占比”。
- 任一所选后端失败均不得 fallback 到另一后端；用户可以在修复失败原因后重试，或手动切换到另一个 Ready 后端。
- 旧 `knnK` / `knnDistance` 读取时忽略，新保存时不回写。
- 旧 `featureType` / `sensitivity` / `brightnessEnabled` / `colorDecisionMode` 读取后迁移到 `backendConfigs.hsvHistogram`；新保存不再写顶层同名字段。
- 旧 `featureType=histogram` 保持一维兼容语义；新建模板才默认 `histogram_2dim_hs`。从一维手动切换二维时将 HSV 模型标为 stale 并要求重新采样。
- 旧模板缺少 `backendConfigs.hsvHistogram.classifierVersion` 时绑定 `hsv_category_best_sample_v2`，不隐式改变历史分类结果；新模板和显式 HSV 重建使用 `hsv_category_topn_intersection_v1`。
- 旧 `minScore` 保留为 `minScore`；旧类别判断仅在 `expectedLabel` 能唯一映射到 `classId` 时迁移为 `expected_class`，否则标记配置需人工确认。
- 旧位置修正显示文案只有在能唯一匹配合法节点时才补齐 `positionCorrectionSourceId`；无法解析时保持来源失效，不默认绑定基准图。

## 8. 验证要求

算法 smoke 至少覆盖：

- HSV 后端用已知 H/S 像素验证输出行是 H、列是 S；Hue 首尾 bin 可相互平滑，Saturation 首尾不得环绕，平滑后总和仍为 1。
- 修改 H/S bins、轴顺序、平滑核、位深元数据或特征版本后必须返回 `model_stale_needs_resample`，不自动截断或降采样。
- 同一线性彩色场景的 8-bit 与正确编码 16-bit 输入得到一致类别；缺 `validBits/bitShift`、非法位组合或像素超出声明范围时返回对应明确错误。
- RGB/BGR/RGBA/BGRA 在元数据正确时产生一致的 RGB 特征；四通道 alpha 不参与建模和分类。
- Mono 图返回 `unsupported_mono_for_color_recognition`，不进入 HALCON 颜色转换。
- 连续运行只对同一 so/profile 执行一次符号解析；缺 Gmm 符号不得阻断 HsvHistogram，反之亦然。
- 生产源码不得存在 `cv::compareHist` 或 OpenCV Bhattacharyya 调试调用。
- 纯色红/绿/蓝 ROI 的 GMM 预测类别、最佳分数和面积诊断。
- 两色按 25/75、50/50、75/25 已知面积拼接；对未被 rejection 的理想色块，每类占比绝对误差不超过 2 个百分点。
- 背景、屏蔽多边形和未分类像素不被错误归入预测颜色。
- a/b 模型对合理明暗波动的稳定性。
- L/a/b 模型能区分需要区分的深浅样本。
- 同一训练数据在固定 `RandSeed=42` 下重复建模，分类结果和面积统计一致；不强制序列化字节完全一致。
- GMM 序列化 → Base64 → 反序列化前后，相同输入的 `classIdOrder`、每类面积和判定结果一致。
- 旧配置无 `recognitionBackend` 时选择 HSV；新配置保存后两套 `backendModels` 可独立回显和恢复。
- HSV Ready/GMM Stale 时可运行 HSV、禁止运行 GMM；GMM Ready/HSV Stale 时行为相反。
- 后端切换不删除另一后端模型；失败不自动 fallback；同帧对比测试不写入正式后端配置。
- 对比报告不得直接比较两套原始 score，必须比较有标注验证集上的准确率、误报率、拒识率、抖动和耗时。
- 1/3/5/10 个独立 ROI 时分别得到预期的 ReadyWithWarning/Ready 状态和 1/[1,2]/[1,3] 中心数策略。
- 样本、通道、类别顺序或模型签名改变时返回 `model_stale_needs_resample`，不自动降维。
- 最佳分数、类别置信度、有效覆盖率和目标类别可分别触发对应 NG reason。
- 位置修正开启时返回 unsupported，关闭时正常运行。
- 空图、Mono 图、缺失位深元数据的 16-bit 图、无效 ROI、空模型、缺 license、缺 runtime 和缺当前模式符号均返明确错误。

Qt 闭环验证：

- 新建、保存、重新打开、编辑、`StaleNeedsResample/ReadyWithWarning` 提示和测试运行。
- KNN 预留控件不会写入配置或影响结果。
- 位置修正预留控件不会对用户伪报“已应用”。
- 完整执行影子构建下的 `qmake qt_ui_test.pro` 和 `make`。

## 9. 明确不做

- 不将 OpenCV 颜色转换、分类或形态学引入核心算法。
- 不在 GMM 失败时自动回退 HSV，也不在 HSV 失败时自动切换 GMM；仅允许用户显式选择。
- 不将 MLP 加入本轮可选模型；只有后续积累充足独立样本且 GMM 在明显非线性重叠上失败时才单独评估。
- 不把颜色识别改造成颜色面积工具；面积占比仅作为分类得分来源、诊断或高级判定。
- 不复用颜色比较 V2 模型代替颜色识别的多类模型。
- 不在本轮抽取颜色识别/颜色比较公共 HALCON 底座；该工作留待后期优化时单独立项。
- 不在本轮顺带实现位置修正或 KNN。
