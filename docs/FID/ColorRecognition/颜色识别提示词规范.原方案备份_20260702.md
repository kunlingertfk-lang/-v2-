# 颜色识别提示词规范

本文档用于规范后续基于颜色识别功能继续开发时的提示词写法。目标是让提示词清晰、有边界、有验证要求，避免只描述“想要什么”，却没有说明“基于什么实现、不能改什么、怎样算完成”。

## 1. 写提示词的基本原则

一条好的开发提示词应包含六类信息：

```text
背景上下文
  -> 当前功能已经实现到什么程度

目标
  -> 这次明确要新增、修复或整理什么

范围
  -> 哪些文件/模块允许改，哪些不允许改

约束
  -> 技术路线、兼容要求、禁止事项

验收
  -> 怎么证明做完了

输出
  -> 需要代码、文档、计划、测试还是只要分析
```

不建议只写：

```text
帮我优化颜色识别。
```

建议写成：

```text
基于当前已实现的颜色识别功能，在不改变现有模板 JSON 兼容字段的前提下，
新增 XXX 功能。UI 层、配置层、Adapter 层、HALCON Runner 层要分离实现。
算法核心必须使用 HALCON 算子，不允许用 OpenCV 或自写算法替代。
完成后运行 smoke、qmake、make，并说明修改文件和验证结果。
```

## 2. 基于颜色识别功能的固定上下文

后续提示词中可以直接声明以下上下文：

```text
当前颜色识别功能已经实现：
- 主界面 ColorRecognitionDialog。
- 模板创建/编辑对话框 ColorTemplateDialog。
- ToolConfig.params / judgeRule 配置保存和回显。
- ColorRecognitionAdapter 将 ToolConfig 映射到 ColorRecognitionHalconConfig。
- ColorRecognitionHalconRunner 负责 HALCON 直方图特征提取和识别。
- 支持矩形检测 ROI、圆形检测 ROI、屏蔽多边形。
- 支持主颜色占比 dominant_ratio 和整体相似度 histogram_intersection。
- 支持 brightnessEnabled=false 的 H/S 优先比较，以及 brightnessEnabled=true 的 H/S/V 比较。
- 支持 H/S 与 H/S/V 历史样本兼容对齐。
- 支持位置修正占位链路：`enablePositionCorrection`、`positionCorrectionSource` 保存/回显/透传，runner payload 输出 `positionCorrectionApplied=false` 和 `positionCorrectionReason=not implemented`。
- K 值和 KNN 距离只保留历史字段，不参与当前计算。
- 色谱特征和 HALCON 颜色分割/聚类只保留接口，暂未实现。
```

可以引用的文档：

```text
AGENTS.md
docs/FID/Function_Docs.md
docs/FID/ColorRecognition/颜色识别流程.md
docs/FID/ColorRecognition/color_recognition_function_implementation.md
```

后续颜色识别开发提示词必须明确：开发前先阅读并遵守 `AGENTS.md` 和 `docs/FID/Function_Docs.md`，单功能实现细节再以本目录功能文档为准。

## 3. 必须写清楚的约束

### 3.1 算法约束

颜色识别及后续视觉算法提示词中应明确：

```text
算法核心必须使用 HALCON 已有算子、类或过程。
实现前必须先确认所需 HALCON 算子可用，并列出算子链。
不允许使用 OpenCV、自写算法或第三方库替代核心算法。
OpenCV 只允许作为图像容器、采集、显示或格式桥接。
HALCON runtime、license 或符号缺失时必须返回明确错误，不允许 fallback。
```

### 3.2 UI 约束

涉及界面修改时应明确：

```text
UI 必须遵守当前颜色识别界面布局：
- 左侧白底黑字参数区。
- 右侧图像预览区。
- 基础 / 全部 分段切换。
- 配置项按卡片分区。
- 控件颜色保持白底黑字。
- 检测 ROI、模板样本 ROI、屏蔽区域的交互状态不能互相污染。
```

### 3.3 兼容约束

涉及配置或算法字段时应明确：

```text
必须兼容旧模板和旧 ToolConfig。
不得删除已有 params / judgeRule 字段。
新增字段必须给默认值和旧配置回退策略。
ToolConfig.roiNormalized 继续保存通用 ROI 或圆形 ROI 外接矩形。
payload 中新增结果字段必须名称稳定，方便 UI 和日志读取。
```

### 3.4 位置修正约束

涉及检测区域、ROI、配置保存、Adapter 或 Runner 的任务时，应明确位置修正链路不得被破坏：

```text
颜色识别已按 FID 公共规范接入位置修正占位链路。
UI 文案必须保持：
- 独立位置修正使能 ⓘ
- 位置修正
- 默认来源 1 基准图.位置修正信息
配置字段必须保持：
- params.enablePositionCorrection
- params.positionCorrectionSource
Adapter 必须解析并透传到 ColorRecognitionHalconConfig。
Runner payload 必须输出：
- enablePositionCorrection
- positionCorrectionSource
- positionCorrectionApplied
- positionCorrectionReason
当前尚未实现实际位置补偿时，必须固定输出：
- positionCorrectionApplied=false
- positionCorrectionReason=not implemented
不允许开关开启后静默忽略，也不允许假报已应用。
```

## 4. 推荐提示词结构

后续可以按以下结构写：

```markdown
# 任务标题

## 背景
说明当前已实现功能、参考文档、相关文件。

## 目标
用 1-3 条写清楚这次要完成什么。

## 范围
- In:
- Out:

## 详细需求
按 UI、配置、Adapter、HALCON Runner、Overlay、文档分层描述。

## 约束
列出 HALCON、兼容、UI、不可改动项。

## 验收标准
列出必须通过的测试、编译、手动验证场景。

## 输出要求
说明需要直接改代码、只写计划、只分析问题，还是新增文档。
```

## 5. 可直接复制的标准提示词模板

```markdown
基于当前已实现的颜色识别功能继续开发，请先阅读：
- `AGENTS.md`
- `docs/FID/Function_Docs.md`
- `docs/FID/ColorRecognition/颜色识别流程.md`
- `docs/FID/ColorRecognition/color_recognition_function_implementation.md`
- `src/ColorRecognitionDialog.cpp`
- `src/ColorTemplateDialog.cpp`
- `src/tooladapters/ColorRecognitionAdapter.cpp`
- `src/algorithms/recognition/ColorRecognitionHalconRunner.cpp`
- `src/algorithms/recognition/ColorRecognitionHalconRunner.h`

## 目标
实现/修复/整理：<写清楚本次要做的功能或问题>。

## 当前基础
当前颜色识别已经实现：
- 主界面 `ColorRecognitionDialog`。
- 模板对话框 `ColorTemplateDialog`。
- `ToolConfig.params` / `judgeRule` 保存和回显。
- `ColorRecognitionAdapter` 配置解析。
- `ColorRecognitionHalconRunner` 的 HALCON 直方图链路。
- 矩形 ROI、圆形 ROI、屏蔽多边形。
- `dominant_ratio` 主颜色占比和 `histogram_intersection` 整体相似度。
- 亮度关闭时 H/S 优先，亮度开启时 H/S/V；两类历史样本要保持兼容。
- 已有位置修正占位链路：`enablePositionCorrection` / `positionCorrectionSource` 保存、回显、Adapter 透传，Runner payload 明确 `positionCorrectionApplied=false`、`positionCorrectionReason=not implemented`。

## 范围
In:
- <允许修改的 UI、配置、Adapter、Runner、测试、文档文件>

Out:
- 不改无关工具。
- 不重构非颜色识别模块。
- 不删除旧配置字段。
- 不把 OpenCV、自写算法或第三方库作为核心识别算法。

## UI 要求
- <说明新增或修改的控件放在哪个区域>
- <说明控件默认值、显示/隐藏条件、启用/禁用条件>
- <说明交互状态，例如 ROI 绘制、选中态、按钮状态>
- 所有左侧控件保持白底黑字。

## 配置要求
- 新增字段：`params.<字段名>` 或 `judgeRule.<字段名>`。
- 默认值：<默认值>。
- 旧配置兼容：<旧配置没有字段时怎么读取>。
- 保存和回显必须一致。
- 不得删除或改名已有位置修正字段：`params.enablePositionCorrection`、`params.positionCorrectionSource`。

## Adapter 要求
- 在 `ColorRecognitionAdapter::toRunnerConfig()` 中解析新增字段。
- 不改变已有字段含义。
- 错误状态必须通过 `ToolResult` 返回，不允许崩溃。

## HALCON Runner 要求
- 核心算法必须使用 HALCON 算子。
- 实现前列出用到的 HALCON 算子链。
- 如果本机 HALCON 24.11 缺少符号，停止并说明，不允许 fallback。
- payload 必须输出：<列出新增 payload 字段>。
- overlay 必须输出：<列出新增 overlay 类型和显示内容>。
- 若涉及 ROI 或检测区域，必须保留位置修正占位 payload：`enablePositionCorrection`、`positionCorrectionSource`、`positionCorrectionApplied=false`、`positionCorrectionReason=not implemented`，除非本次明确实现真实位置补偿。

## 兼容要求
- 旧模板样本仍可运行。
- H/S 与 H/S/V 特征维度兼容逻辑不能破坏。
- `histogram_intersection` 旧版整体相似度模式必须保留。
- `dominant_ratio` 默认主颜色占比模式必须保留。
- 位置修正开关和来源字段必须继续保存、回显和透传；当前未实现真实补偿时不得改变 `not implemented` 语义。

## 验收标准
- 新增或扩展 smoke test 覆盖：
  - 正常成功路径。
  - 空图像 / 无效 ROI / 无样本 / 配置缺失中的至少一个异常路径。
- 运行：
  - `git diff --check`
  - `/home/tt/Qt/5.15.2/gcc_64/bin/qmake qt_ui_test.pro`
  - `make -j8`
- 最终回复说明：
  - 修改了哪些文件。
  - 新增了哪些字段或接口。
  - 运行了哪些验证命令。
  - 是否存在未完成项或风险。
```

## 6. 针对不同任务的提示词示例

### 6.1 新增 UI 控件

```markdown
基于颜色识别当前实现，在 `ColorRecognitionDialog` 的 `结果判断` 区新增 `<控件名称>`。

要求：
- 控件位于 `<具体区域>`。
- 默认值为 `<默认值>`。
- 保存到 `params.<字段名>`。
- `loadFromConfig()` 能回显旧配置和新配置。
- 不改变现有 `判别方式`、`判断依据`、`最低得分`、`目标类别` 行为。
- 左侧控件保持白底黑字。

验收：
- 修改后 `git diff --check` 通过。
- qmake 和 make 通过。
- 手动说明控件保存/回显链路。
```

### 6.2 新增 HALCON 算法能力

```markdown
基于颜色识别当前 HALCON runner，新增 `<算法能力>`。

要求：
- 实现前先确认 HALCON 24.11 中可用的算子链，并写入文档。
- 算法核心只能在 `ColorRecognitionHalconRunner` 中实现。
- `ColorRecognitionAdapter` 只做配置解析，不写算法。
- 不允许用 OpenCV、自写算法或第三方库替代。
- 缺少 HALCON 符号时返回明确错误。
- 保留 `dominant_ratio` 和 `histogram_intersection` 两个现有模式。

验收：
- 新增 smoke test 覆盖成功路径和异常路径。
- qmake 和 make 通过。
- payload 输出新增字段，UI 能显示或记录。
```

### 6.3 修复识别结果问题

```markdown
当前颜色识别出现问题：<描述现象>。

请按系统化调试方式处理：
- 先定位问题发生在 UI、配置、Adapter、Runner 还是 HALCON runtime。
- 先复现或补 smoke test，再修改。
- 修复范围最小化，不改无关 UI 和算法。
- 如果涉及特征维度，不能破坏 H/S 与 H/S/V 兼容。
- 如果涉及 ROI，不能破坏矩形 ROI、圆形 ROI、屏蔽区域的现有行为。

验收：
- 给出根因说明。
- 给出修改文件。
- 给出验证命令和结果。
```

### 6.4 写文档或方案

```markdown
基于当前颜色识别实现，新增文档 `<文档名>.md`。

要求：
- 不修改 C++ 代码。
- 文档必须拆分 UI、配置、Adapter、Runner、验证五层。
- 用文本图描述主流程。
- 明确当前已实现、兼容保留、预留未实现三类内容。
- 给出下一功能接入建议。

验收：
- `git diff --check <文档路径>` 通过。
- `rg "<关键章节1>|<关键章节2>" <文档路径>` 能检索到关键章节。
```

### 6.5 涉及位置修正或检测区域

```markdown
基于颜色识别当前实现，修改 `<检测区域/ROI/运行配置>`。

要求：
- 保留 `独立位置修正使能 ⓘ` 和 `位置修正` 来源行。
- 开关默认关闭；关闭时隐藏来源行，开启时显示来源行。
- 默认来源为 `1 基准图.位置修正信息`。
- 保存字段保持为 `params.enablePositionCorrection` 和 `params.positionCorrectionSource`。
- `ColorRecognitionAdapter` 必须继续解析并透传到 `ColorRecognitionHalconConfig`。
- Runner payload 必须继续输出 `enablePositionCorrection`、`positionCorrectionSource`、`positionCorrectionApplied`、`positionCorrectionReason`。
- 当前没有实现实际位置补偿时，必须输出 `positionCorrectionApplied=false` 和 `positionCorrectionReason=not implemented`。
- 不允许因为位置修正开关开启而改变 ROI 坐标，除非本次需求明确实现真实位置补偿并列出 HALCON 算子链。

验收：
- 扩展或运行颜色识别 smoke，断言位置修正开启时 payload 字段完整。
- qmake 和 make 通过。
- 说明位置修正当前是占位链路还是已实际应用。
```

## 7. 提示词检查清单

发送提示词前，用下面清单检查：

```text
[ ] 是否写清楚这次到底要做什么？
[ ] 是否说明基于当前颜色识别已实现功能？
[ ] 是否指出参考文档和关键文件？
[ ] 是否分清 UI、配置、Adapter、Runner、测试？
[ ] 是否写明 HALCON 约束？
[ ] 是否写明不能用 OpenCV 或自写算法替代？
[ ] 是否写明旧配置兼容要求？
[ ] 是否写明默认值和回显规则？
[ ] 是否写明位置修正字段、占位 payload 和 not implemented 语义？
[ ] 是否写明异常路径？
[ ] 是否写明验证命令？
[ ] 是否说明最终回复需要包含哪些内容？
```

## 8. 常见反例

### 8.1 需求太泛

```text
优化颜色识别算法。
```

问题：没有目标、没有验收、没有范围。

### 8.2 缺少约束

```text
加一个颜色分割功能，怎么方便怎么做。
```

问题：可能导致 OpenCV 或自写算法进入核心链路，违反 HALCON 前置规则。

### 8.3 缺少兼容

```text
把亮度逻辑改成新的。
```

问题：没有说明旧 H/S、H/S/V 样本如何处理，容易造成旧模板无结果。

### 8.4 缺少验证

```text
改完告诉我。
```

问题：没有测试命令和验收标准，无法判断是否真的完成。

## 9. 推荐最终回复要求

提示词最后建议加上：

```text
完成后请用中文回复，包含：
- 修改摘要。
- 修改文件。
- 新增/变更字段。
- 验证命令和结果。
- 未完成项或风险。
```
