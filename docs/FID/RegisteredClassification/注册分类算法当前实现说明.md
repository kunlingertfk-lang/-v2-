# 注册分类算法当前实现说明

## 1. 当前后端边界

注册分类当前使用 HALCON 原生 Feature V2 和两个 `class_knn` 分类器。当前固定契约为：

```text
modelType    = halcon_knn_registered_classification
schemaVersion = 2
featureVersion = halcon_registered_feature_v2
featureLength = 59
```

MLP/DL 不属于当前实现。现有 schema 1 MLP 包只通过只读 inspection 被识别为 legacy，进入列表和重新训练流程，不进入直接推理；不得恢复任何 MLP/DL 兼容运行分支。

## 2. HALCON Feature V2

`RegisteredClassificationFeatureExtractor` 负责 HALCON 图像桥接、真实 ROI、前景分割、规范化和特征提取；`RegisteredClassificationFeatureSpace` 负责名称、长度、分组权重、归一化和距离换算。

| 特征组 | 维度 | 组权重 |
| --- | ---: | ---: |
| shape | 13 | 0.35 |
| occupancy | 16 | 0.25 |
| gray | 18 | 0.15 |
| color/Lab | 6 | 0.15 |
| texture | 6 | 0.10 |

总长度为 `13 + 16 + 18 + 6 + 6 = 59`。每维先乘 `sqrt(groupWeight / groupDimension)`，完整向量再做 L2 归一化；KNN 自动 normalization 固定为 false。

### 2.1 ROI

训练样本 `full`、`rectangle`、`polygon` 分别进入 HALCON 区域构造。矩形使用 `gen_rectangle1`，多边形使用 `gen_region_polygon_filled`，多边形点少于 3 个或包含非有限值时返回 `invalid_roi`。多边形分割、边界带和质心都基于真实填充区域，不能使用多边形外接矩形替代。

主 Dialog 的在线检测区域仍只有 `full` 和 `rectangle`。这不是训练多边形能力缺失，而是在线检测配置的当前 UI 边界。

### 2.2 固定 HALCON 链

核心链使用 `gen_image_interleaved`、`reduce_domain`、`gauss_filter`、亮/暗 `binary_threshold`、`opening_circle`、`closing_circle`、`fill_up`、`connection`、`intersection`、`difference`、`area_center`、`smallest_rectangle2`、`orientation_region`、刚性/仿射变换、`crop_domain`、`zoom_image_size`、`zoom_region`、`intensity`、`gray_histo`、Lab 转换和 `cooc_feature_image` 等 HALCON 能力。所需符号通过现有动态 HALCON runtime 解析；缺失符号必须返回 `halcon_symbol_missing`。

前景候选使用面积 2% 至 98% 门限，并按中心、边界接触和面积计算固定候选分数。无有效前景返回 `foreground_not_found`，不回退成整块 ROI。规范化输出为 `128 x 128`。

任何 HALCON 数值输出、tuple 长度、特征值、距离或统计值缺失、非有限或越界时，返回明确错误，不用静默默认值继续运行。

## 3. 双 KNN 后端

### 3.1 训练

训练 Runner 从有效样本的 59 维向量构建：

1. 样本 KNN：每个 ROI 样本独立 `add_sample_class_knn`，写为 `model.gnc`。
2. 中心 KNN：每类样本向量求均值并 L2 归一化，每类中心作为一个样本，写为 `class_centers.gnc`。
3. 每类计算 `class_stats.json`，记录样本数、中心距离均值、population standard deviation、最大距离、半径及 `radiusEnabled`。

两个 KNN 都固定使用：

| 参数 | 值 |
| --- | --- |
| `method` | `classes_distance` |
| `normalization` | `false` |
| `num_trees` | `4` |
| `num_checks` | `0` |
| `epsilon` | `0.0` |
| 样本/中心融合权重 | `0.70 / 0.30` |

样本 KNN 的 `k` 为有效样本总数，中心 KNN 的 `k` 为类别数；`max_num_classes` 为类别数。模型包严格校验 `metadata.json`、两个 `.gnc` 文件和 `class_stats.json`，单 KNN 文件不能直接运行。

半径公式为：

```text
radius = max(maxDistance * 1.10,
             meanDistance + 2.5 * populationStdDev)
radius = clamp(radius, 0.10, 2.00)
```

样本少于 3 个时半径关闭并写入 `radius=0`；样本数达到 3 时半径开启。

### 3.2 推理

Runner 每次运行读取两个 KNN，提取同版本查询向量，并分别得到每类样本距离 `dSample` 和中心距离 `dCenter`：

```text
similarity01 = clamp(1 - distance^2 / 2, 0, 1)
sampleSimilarity = 100 * similarity01(dSample)
centerSimilarity = 100 * similarity01(dCenter)
score = 0.70 * sampleSimilarity + 0.30 * centerSimilarity
```

按 score 降序、classId 升序稳定排序。默认拒识参数是 `minSimilarity=80` 和
`minMargin=8`；工具配置可在 `[0,100]` 内覆盖运行时阈值，但拒识顺序不能改变：

| 条件 | status/rejectionReason |
| --- | --- |
| Top1 score `< minSimilarity` | `classification_rejected_low_similarity` |
| `Top1 - Top2 < minMargin` | `classification_rejected_ambiguous` |
| 半径启用且 `dCenter > radius` | `classification_rejected_out_of_radius` |

拒识不是算法错误。三种拒识都返回 `success=true`、`ok=false`、`predictedLabel=UNKNOWN`、`predictedClassId=-1`，并保留 `bestCandidateClassId`、`bestCandidateLabel`、score、TopK、距离、半径和 `rejectionReason`。模型加载、输入、ROI、HALCON 或特征错误才返回 `success=false`。

## 4. 结果和位置修正

Adapter 将 Runner 的 `success`、`ok`、`status`、`message`、score、文本、耗时、overlay 和 payload 原样映射到统一 `ToolResult`。payload 至少包含模型目录、模型类型、schema/feature 版本、预测类别、候选、ROI、阈值、拒识诊断、耗时和错误字段。

`class_match` 与 `min_score` 均在拒识之后执行；UNKNOWN 一律 NG。`topK` 只控制候选展示数量，不减少内部 Top2 和全类别拒识所需计算。

位置修正配置通过公共 helper 解析并写回。稳定来源 ID 使用
`positionCorrectionSourceId=reference.positionCorrection`，当前基准图显示文本为
`0 基准图.位置修正信息`；历史 `1 基准图.位置修正信息` 只作为兼容迁移输入。

开启位置修正后，Adapter 必须通过 `PositionCorrectionConsumer::resolve()` 取得
当前帧 `referenceToRunHomMat2D`，Runner 将基准全屏/矩形 ROI 生成为 HALCON
Region，再执行 `affine_trans_region` 和 `clip_region`。修正后的 Region 直接进入
原有 Feature V2 前景与 59D 特征链，分类算法、模型格式和拒识阈值不变。

显示层的 `detect_roi` 使用同一矩阵；匹配轮廓由
`showPositionCorrectionMatchContour` 控制，匹配原点始终保留。payload 必须包含
请求、应用、来源、矩阵、尺度、修正 ROI 面积/包围框和 HALCON 操作诊断。
来源或矩阵错误以及 ROI 完全越界时必须失败，不得静默改用固定 ROI。

## 5. 资源生命周期

HALCON library handle、tuple、图像/区域对象和 sample/center KNN handle 都采用作用域清理器。句柄只有在成功创建或读取后标记有效，析构时各清理一次。异常、拒识、加载另一模型或重复测试均必须走同一 RAII 路径；当前不跨运行缓存 KNN 句柄。

## 6. 模型管理和升级

模型包目录为：

```text
ModelFiles/RegisteredClass/yyyyMMdd/model_HHmmss_zzz/
├── model.gnc
├── class_centers.gnc
├── metadata.json
├── class_stats.json
├── training_report.json                         # 训练器生成
└── training_session/session.json + images/*.png # 可选
```

运行最小包校验只要求 `metadata.json`、两个 `.gnc` 和 `class_stats.json`；
`training_report.json` 是训练记录，`training_session/` 只在需要恢复训练时存在。

新训练使用新的日期/时间目录。模型管理重新训练使用所选模型的同一目录，临时目录写入完成并校验通过后原子替换；旧目录不会因为训练中途失败而被覆盖。

模型管理仍显示 legacy 和不完整记录，以便用户处理历史资产。schema 1/`model.gmc` legacy：

- 可以列出、导出、删除和重新训练；
- 重新训练按钮可用，使用训练会话恢复原图、类别、命名和 ROI；没有会话则以空白训练状态提示用户重新添加；
- 不可直接运行、不可作为当前模型选择，也不发出可运行 `modelSelected`；
- 成功升级后必须存在完整 schema 2 双 KNN 包，才允许使用。

MLP/DL 只允许作为历史资产的标签和重训提示出现，不得重新引入可执行的 MLP/DL 兼容层、旧特征回退、旧模型直接读取或权重转换。

## 7. 当前接口状态

当前公开/使用中的错误与状态包括：

- 输入和特征：`image_empty`、`invalid_roi`、`foreground_not_found`、`invalid_feature_value`；
- 包和升级：`model_package_incomplete`、`legacy_model_requires_retraining`、`unsupported_model_type`；
- HALCON/KNN：`halcon_so_not_found`、`halcon_load_failed`、`halcon_symbol_missing`、`knn_read_failed`、`knn_model_mismatch`、`knn_classify_failed`；
- 拒识：`classification_rejected_low_similarity`、`classification_rejected_ambiguous`、`classification_rejected_out_of_radius`。
- 位置修正：`position_correction_source_missing`、
  `position_correction_match_not_found`、`position_correction_source_failed`、
  `position_correction_source_invalid`、`position_correction_frame_mismatch`、
  `invalid_position_correction_matrix`、`invalid_pose_scale`、
  `corrected_roi_out_of_image`。

## 8. HALCON深度Embedding预留接口

当前生产推理仍只有本说明前述schema 2 Feature V2后端，尚未增加DL推理分支。
为后续通用少样本注册分类，工程已预留：

- `RegisteredClassificationEmbeddingModelProvider`
  - 从`ModelFiles/RegisteredClass/_feature_models`解析基础模型descriptor；
  - 严格校验模型ID、版本、输入规格、Embedding层、`.hdl`/`.hdict`路径和SHA-256；
  - 基础模型缺失、描述非法、文件损坏均返回明确错误，不回退Feature V2。
- `RegisteredClassificationDlCapability`
  - 通过HALCON `query_available_dl_devices`探测真实DL设备；
  - 返回设备ID、类型、名称、是否仅推理、HALCON版本和license路径诊断。

2026-07-25专项smoke实测返回1个CPU设备：
`AMD Ryzen 7 H 260 w/ Radeon 780M Graphics`，`inferenceOnly=false`。这证明本机
HALCON DL设备查询链可用。

2026-07-26验证阶段采用公开ONNX Model Zoo MobileNetV2 opset 7作为临时基础模型。
HALCON 20.11已完成实际导入、转存`.hdl`、生成`.hdict`、截取
`mobilenetv20_features_pool0_fwd`以及真实图像推理，输出`1×1×1280`特征；
CPU单次首次观测约127 ms。该结果仅证明深度特征技术链可用，尚未证明类别可分性、
旋转尺度泛化或生产节拍，也未改变当前Feature V2默认后端。

现场Feature V2注册训练保持原行为：训练器在临时目录完成双KNN构建和完整包校验后再交换
目标目录；训练窗口收到成功结果后自动选择新模型，用户可立即对当前工件执行测试检测。
安装合格基础`.hdl`后，DL注册模式复用该交互，但使用独立schema 3模型类型。

深度升级的完整边界、模型合同和后续阶段见
`注册分类通用HALCON深度Embedding升级实施规划.md`。
