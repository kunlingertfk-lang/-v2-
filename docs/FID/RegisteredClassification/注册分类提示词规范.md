## 第一版固定范围

第一版锁定为“推理闭环”，目标是让工具能创建、保存、回显、导入 HALCON 可用分类模型、执行分类推理、输出 OK/NG 和错误状态。

In:

- 工具库入口可见，能新建注册分类工具。
- 配置对话框能保存、重新打开并回显模型、检测区域、位置修正占位和结果判断。
- 支持全屏检测和矩形检测 ROI。
- 支持导入、删除、导出 HALCON 可用模型文件。
- 支持类别判断和最低得分两类判断依据。
- 测试运行返回统一 `ToolResult`，UI 显示 OK/NG、类别、得分、ROI 和耗时。
- 空图像、无模型、模型路径不存在、不支持模型格式、无效 ROI、HALCON runtime/license/符号缺失时不崩溃，返回明确错误。
- 文档按时间记录实现状态、剩余事项、阻塞项和验证结果。

Out:

- 不实现海康 `.scbin` 解析。
- 不伪装兼容 `.scbin`；导入 `.scbin` 必须返回 `unsupported_model_format`。
- 不实现注册图像窗口。
- 不实现本地标注、数据集管理和模型训练。
- 不实现模型管理窗口的真实训练能力。
- 不接入海康底层模型 `OLClassify*.bin`，除非后续确认其可被 HALCON 原生读取。
- 不引入 OpenCV、自写算法、RKNN、ONNX Runtime、TensorRT 或其他第三方库作为核心分类推理。

## 提示词分层原则

注册分类后续开发必须把 UI 和后端分开提示、分开实现、分开验证。除非用户明确要求一次性联调，否则不要用一个提示词同时要求完成 Dialog、Adapter、Runner、HALCON 推理和 smoke 测试。

推荐拆分顺序：

1. UI 接入提示词：只做工具入口、配置对话框、参数保存回显、按钮状态、ROI 交互和未实现提示。
2. 后端和 HALCON 提示词：只做 Adapter、Runner、HALCON 模型读取/推理、错误状态、payload 和 smoke 测试。
3. 联调闭环提示词：在 UI 和后端都已存在后，连接测试运行、结果展示、工具页预览和手动验证。

分层边界：

- UI 阶段不得伪造分类算法结果；测试运行可返回明确 `backend_not_implemented` 或禁用运行按钮。
- 后端阶段不得重做 UI 布局；只通过 `ToolConfig` / `ToolRequest` / `ToolResult` 合同工作。
- 联调阶段不得改变模型格式策略；`.scbin` 仍必须返回 `unsupported_model_format`。

第一优先方案是 HALCON DL 分类推理链。实现前必须确认本机 HALCON 环境具备以下符号：
- `T_read_dl_model`
- `T_apply_dl_model`
- `T_set_dl_model_param`
- `T_get_dl_model_param`
- `T_create_dict`
- `T_set_dict_object`
- `T_set_dict_tuple`
- `T_get_dict_tuple`
- `T_clear_dl_model`
- `T_clear_handle`
- `gen_image_interleaved`
- `gen_rectangle1`
- `reduce_domain`
- `clear_obj`

备选经典分类链仅用于 HALCON 经典分类模型，不作为 `.scbin` 替代方案：
- `read_class_knn` / `read_class_svm` / `read_class_mlp`
- `T_classify_class_knn` / `T_classify_class_svm` / `T_classify_class_mlp`

- 返回 `halcon_so_not_found`、`halcon_load_failed` 或 `halcon_symbol_missing`。
- 不允许 fallback 到 OpenCV、自写算法或第三方库。

## 算法流程

第一版 HALCON DL 分类推理流程：

```text
输入图像 cv::Mat
        |
        v
转换为 8-bit BGR 图像载体
        |
        v
gen_image_interleaved 桥接为 HALCON image
        |
        v
按 full/rectangle 生成有效检测 domain
        |
        v
read_dl_model 读取 HALCON DL 分类模型
        |
        v
构造 DLSample dict，写入 image 等必要字段
        |
        v
apply_dl_model 执行分类推理
        |
        v
读取预测类别、得分、TopK
        |
        v
按 judgeRule 判断 OK/NG
        |
        v
输出 ToolResult / overlays / payload
```

如果模型需要预处理参数或类别名称映射，必须优先从 HALCON 模型参数或伴随配置读取；没有可靠来源时返回明确错误，不允许猜类别。

## 结果判断要求

类别判断：
- `judgeRule.mode = "class_match"`。
- `predictedLabel == expectedLabel` 时 OK，否则 NG。
- `expectedLabel` 为空时返回 `missing_expected_label`。

最低得分：
- `judgeRule.mode = "min_score"`。
- `score >= minScore` 时 OK，否则 NG。
- `minScore` 范围限制为 0-100。

得分要求：
- `score` 统一使用 0-100。
- `scoreDirection = "higher_is_better"`。
- payload 中保留原始置信度字段，便于调试。

## 模型格式红线

海康官方文档中的 `.scbin` 属于海康专有模型格式。当前项目的 HALCON 约束不允许在没有可靠格式说明或转换器的情况下自行解析或伪装兼容。

第一版规则：

- `.scbin` 导入必须返回 `unsupported_model_format`。
- 若用户要求支持 `.scbin`，必须先确认是否存在可调用的 HALCON 原生读取接口或官方转换链。
- 不允许把 `.scbin` 当作普通二进制、JSON、ONNX 或 HALCON DL 模型硬读。
- 不允许自动降级到颜色识别、模板匹配、OpenCV 分类或其他非注册分类算法。

可支持的模型格式应以本机 HALCON 实测可读为准，提示词中不得写死未经验证的扩展名。若后续确认 `.hdl`、`.hdict` 或其他 HALCON 模型包可读，应在实现记录中补充验证结果和读取链路。

## 分阶段规划

第一版只做推理闭环。

后续阶段可以独立规划：

- 注册图像窗口：导入注册图像、标签管理、ROI/标注、数据集保存。
- HALCON 训练：基于 HALCON DL 训练接口或经典分类训练接口生成模型。
- 模型管理：编辑本地数据集、重新训练、导出和删除模型。
- 底层模型选择：仅在确认模型格式和 HALCON 读取能力后接入。
- 位置修正真实应用：订阅基准图或位置修正工具输出，并将变换应用到检测 ROI。

以上后续阶段不得混入第一版推理闭环，除非用户明确扩大范围并接受对应验证成本。
