# 模板定位与位置修正衔接

## 当前边界

模板定位已经输出可供位置修正消费的主位姿：`x`、`y`、`angle`（角度制）、`angleDeg`、`scale` 和 `pose`。多匹配时顶层位姿固定取 HALCON 返回的第一个最佳结果，`primaryMatchIndex=0`；全部候选保存在 `matches`。

当前 `PositionCorrectionDialog` 只有 X/Y/角度来源绑定和配置保存，运行后端仍明确为 `not implemented`；`ToolEngine::runTools` 也尚未把前序 `ToolResult` 传给后序工具。因此现阶段可以在 UI 中绑定模板定位，但不能声称已经应用了位置修正。

## 三类节点的职责

- 模板定位工具：真实位姿生产者，输出 `x/y/angle`，不计算修正矩阵。
- 工具位置修正：订阅前置模板定位的位姿，保存基准姿态并计算矩阵；自身不做模板匹配。
- 基准图位置修正：方案级组合节点，内部拥有私有模板定位器并直接输出修正矩阵；它不是工具位置修正的 X/Y/角度来源。

基准图位置修正建立产品级全局坐标系；工具位置修正建立局部对象坐标系。两者可以同时存在：局部模板定位可以先使用全局修正移动搜索 ROI，再输出当前图像中的实际位姿。工具位置修正据此生成的矩阵已经是局部对象从基准图到运行图的绝对矩阵，因此选择局部修正的下游工具不能再重复叠加全局矩阵。

完整设计与实施顺序见 `../PositionCorrection/位置修正下一阶段实施计划.md`。

## 基准姿态与运行姿态

工具位置修正的订阅字段 `x/y/angle` 表示运行姿态来源。创建基准时，在基准图上执行同一个模板定位实例，并把该次输出保存为 `referencePose`；后续运行时，同一实例在当前图像上的输出是 `runPose`。因此内部存在两组 X/Y/角度，但 UI 不需要让用户再绑定一套独立的基准字段。

当前 `PositionCorrectionDialog` 使用 `runPointX/runPointY/runAngle` 作为配置键，却把默认显示路径写成“基准点坐标/基准角度”，属于现有占位实现的语义错误，接入后端时必须统一修正为“运行点坐标/运行角度”。

## 接入顺序

1. 工具链顺序固定为“模板定位 → 位置修正 → 被修正的检测工具”，禁止后向引用。
2. 位置修正的 `runPointX/runPointY/runAngle` 绑定模板定位实例的稳定 `toolId`，输出键分别使用 `x/y/angle`。
3. 创建基准时以基准图同时作为模板定位的运行图和基准图，重新执行绑定的模板定位，并保存 `referencePose={x0,y0,angle0}`。
4. 每帧运行时读取当前 `runPose={x,y,angle}`。下游 ROI 定义在基准图坐标系中，因此使用 HALCON `vector_angle_to_rigid(referencePose, runPose)` 生成 `referenceToRunHomMat2D`；同时生成反向的 `runToReferenceHomMat2D`，禁止混用方向。
5. 位置修正结果输出双向矩阵、`deltaX`、`deltaY`、`deltaAngleDeg`、`sourceToolId` 和 `applied=true`。
6. `ToolEngine` 顺序执行时把前序结果放入运行上下文；后续工具根据所选位置修正 ID，用 HALCON `affine_trans_region` / `affine_trans_contour_xld` 或对应 ROI 变换接口，将基准 ROI 按 `referenceToRunHomMat2D` 修正到当前运行图。
7. 消费工具选择 `reference.positionCorrection` 时使用产品级全局矩阵；选择工具位置修正的稳定 `toolId` 时使用该局部对象的绝对矩阵。第一版每个消费工具只选择一个最终来源。

## 多匹配约束

位置修正默认消费最佳结果。若现场存在多个相同目标，应先通过搜索 ROI、数量判定或更高最低得分保证第一结果稳定；以后需要按编号或最近邻跟踪时，再增加 `primaryMatchStrategy`，不能在位置修正层静默随机选择。

## 失败传播

- 模板定位执行失败、未找到或数量判定 NG：位置修正返回 `source_invalid`，不得沿用上一帧位姿。
- 绑定来源不存在：返回 `source_unavailable`。
- 基准位姿未创建：返回 `reference_pose_missing`。
- 位置修正失败时，下游工具不得标记 `positionCorrectionApplied=true`，是否停止整链由方案级失败策略决定。
