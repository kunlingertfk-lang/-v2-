# 相机/坐标系标定 SOP

## 1. 文档定位

本文档归属 `Calibration` 功能，规定相机/坐标系标定的范围、现场操作流程、数据合同、开发路径和验收门禁。

本文档既是现场 SOP，也是当前实现基线。工具页已提供统一“快速标定”入口，N 点方式已形成 HALCON 求解、质量门禁、原生 XML 持久化和 `CalibrationTransform` 生产消费闭环；平移旋转与标定板方式当前以 `planned` 状态注册，不允许静默执行替代算法。相机参数页和基准图页的历史重复入口已隐藏。

本文档同时遵守：

- 根目录 `AGENTS.md`；
- `docs/FID/Function_Docs.md`；
- `docs/V2视觉工具开发SOP.md`。

## 2. 理解复述

### 2.1 目标

建立像素坐标与物理平面坐标之间可验证、可保存、可回显、可失效管理的映射，使测量、定位、结果显示及后续坐标输出能够使用统一坐标合同。

### 2.2 首版范围

首版推荐实现：

> 固定相机、平面工件、单相机的二维平面标定。

首版支持两种模式：

1. **像素当量**：适用于远心镜头或工作区域内比例近似一致的场景。
2. **二维平面标定**：适用于普通固定相机，建立图像平面到工件物理平面的映射。

首版不包含：

- 机器人手眼标定；
- 3D 标定；
- 多相机联合标定；
- 在线自动重标定；
- 用 OpenCV、自写算法或第三方算法替代 HALCON；
- 将模板定位的基准姿态混入相机标定配置。

### 2.3 输入、输出和边界

输入至少包括：

- 未绘制 Overlay 的原始标定图像；
- 标定类型及标定板规格；
- 点间距、单位、世界坐标原点和轴方向；
- 相机身份、图像分辨率及关键参数快照；
- 独立的求解数据和验证数据。

输出至少包括：

- 像素坐标到物理坐标的映射；
- 物理坐标到像素坐标的逆映射；
- 有效标定区域；
- 标定质量指标和验收结论；
- 标定版本、时间、操作者、HALCON 版本及相机参数指纹；
- 明确的 `empty/draft/ready/stale/invalid/unsupported` 生命周期状态。

边界要求：

- 标定只负责坐标映射，不负责目标查找和下游 ROI 位置修正。
- 标定板所在平面必须与实际检测平面一致；存在明显高度差时，二维映射不可直接复用。
- 相机、镜头、焦距、分辨率、安装位置或工作距离变化后，原标定必须进入失效或待复验状态。

## 3. 信息缺口与默认假设

### 3.1 当前已确认事实

- 工程是 Qt 工业视觉项目。
- 视觉核心算法必须使用本机 HALCON 能力。
- `CameraParamsDialog` 中已有 `setupQuickCalibrateButton`，但尚未连接标定流程。
- 当前 `SchemeState` 尚无独立的相机标定数据字段。
- 模板定位和位置修正已有独立链路，相机标定不得与其混用。

### 3.2 开发前必须确认

- 现场相机是固定相机还是随机器人运动。
- 镜头类型、工作距离、视野范围和生产图像分辨率。
- 标定板类型、尺寸、点间距和精度等级。
- 物理坐标系原点、X/Y 方向、单位以及是否需要外部设备坐标。
- 产品允许的位置或尺寸误差。
- HALCON 版本、license 以及所需标定接口和符号是否可用。
- 是否需要畸变校正图，还是只需要坐标点转换。

上述信息会改变算法类型或验收结果时，必须先确认，不得直接进入实现。

### 3.3 当前安全默认假设

- 首版按固定相机、平面工件、单位 `mm` 设计。
- 标定结果作为方案级前置能力保存，不注册成普通检测 `ToolType`。
- 质量阈值由现场公差推导，不在代码中写死通用毫米值。
- 发布新标定时采用原子替换，失败时继续保留上一版有效标定。

## 4. 相机/坐标系标定现场 SOP

### 4.1 阶段 A：作业准备

操作员确认：

- 相机、镜头和支架已固定，机械紧固无松动；
- 焦距、光圈、工作距离和对焦状态已固定；
- 图像分辨率、裁剪、旋转和镜像设置与生产一致；
- 曝光、增益及光源状态与生产一致；
- 会改变图像几何或灰度稳定性的自动功能已经按生产要求锁定；
- 相机完成预热，镜头和标定板清洁；
- 标定板放置平面与工件实际检测平面一致；
- 世界坐标原点、X/Y 正方向和单位已经明确。

任一前置条件不满足时，不进入采集。

### 4.2 阶段 B：新建标定

从相机参数页点击“快速标定”，进入独立标定向导：

1. 选择标定类型：像素当量或二维平面标定。
2. 录入或选择标定板类型、规格、点间距和单位。
3. 设置世界坐标原点和 X/Y 正方向。
4. 读取并冻结当前相机参数快照。
5. 生成新的 `calibrationId`，状态置为 `draft`。
6. 进入标定图像采集页。

不得覆盖当前 `ready` 标定；新标定发布前，旧版本继续可用。

### 4.3 阶段 C：图像采集

采集要求：

- 标定板覆盖实际生产工作区域；
- 中心、四角和四边均有有效样本；
- 对多图求解模式，采集不同位置和适量角度的图像；
- 每幅图显示点位检测数量、覆盖范围、清晰度和可用状态；
- 求解图像与验证图像分组保存，验证数据不得参与参数求解。

以下图像应拒绝：

- 空图或分辨率不一致；
- 明显失焦、运动模糊、过曝或欠曝；
- 标定板严重截断；
- 有效特征点不足或点序异常；
- 标定板翘曲、污染或不在生产工作平面；
- 图像已经写入 ROI、文字、十字或结果 Overlay。

采集数量不是唯一门槛，必须同时满足工作区域覆盖和最终误差要求。

### 4.4 阶段 D：HALCON 求解

求解前必须完成 HALCON 能力预检：

- runtime 路径通过现有 `HalconRuntimePaths` 逻辑解析；
- license 可用；
- 所选标定模式需要的 HALCON 接口和符号存在；
- 使用一组最小样例完成调用验证。

求解过程必须：

1. 将原始图像通过现有桥接方式转换为 HALCON 图像。
2. 使用 HALCON 检测标定特征和计算映射。
3. 计算像素到物理坐标映射及其逆映射。
4. 计算每幅图、每个有效点的残差。
5. 生成平均、P95、最大误差和有效覆盖区域。
6. 返回稳定的成功、失败或不支持状态。

HALCON 能力缺失、求解异常、矩阵不可逆或结果包含非有限数值时，不得生成 `ready` 结果，也不得静默切换到其他算法。

### 4.5 阶段 E：独立验证

验证应使用未参与求解的已知点、量块或验证标定板：

1. 覆盖中心、四角和主要生产区域。
2. 将验证点的像素坐标转换为物理坐标。
3. 与真实物理坐标比较。
4. 输出逐点误差、平均误差、P95 误差和最大误差。
5. 检查原点、轴方向、单位和正负号。
6. 显示最大误差点的位置，避免平均值掩盖边缘异常。

推荐质量门槛：

```text
标定最大误差 <= 产品允许位置或尺寸误差的 1/3
```

项目可设置更严格的绝对上限，但必须由现场精度要求确认，不能直接采用未经验证的固定毫米值。

验证未通过时：

- 状态保持 `draft` 或置为 `invalid`；
- 显示失败项和超差点；
- 允许重新采集或调整配置后重新求解；
- 禁止发布和生产使用。

### 4.6 阶段 F：发布

只有独立验证通过后，才允许点击“应用标定”：

- 保存完整标定数据、质量指标和输入指纹；
- 状态置为 `ready`；
- 原子替换当前方案引用的标定版本；
- 保留上一版有效标定用于审计和回退；
- 记录创建时间、验证时间和操作者；
- 刷新相机参数页中的标定状态、版本和质量摘要。

保存失败时必须继续使用旧版有效标定，并返回明确错误。

### 4.7 阶段 G：生产前复验

每次生产启动、换型或加载方案时：

1. 比对相机身份、分辨率和关键参数指纹。
2. 检查标定状态是否为 `ready`。
3. 检查当前工作平面和硬件条件是否发生变化。
4. 通过一个或多个已知基准点执行快速复验。
5. 超差时将标定置为 `stale` 或 `invalid`，禁止继续输出物理坐标。

不得在标定缺失或失效时，将像素坐标冒充物理坐标输出。

## 5. 失效和重标定规则

以下变化应触发强制失效：

- 更换相机或镜头；
- 调整焦距、变焦倍率或明显重新对焦；
- 修改生产分辨率、裁剪、旋转或镜像；
- 相机或镜头安装位置改变；
- 工作距离或工件平面高度超过允许范围；
- 标定板规格与保存配置不一致；
- 标定矩阵损坏、不可逆或出现非有限数值。

以下情况至少触发复验：

- 光源、曝光或增益有较大调整；
- 设备受撞击、维护或长期停机后重新启用；
- 温度或机械状态变化可能影响安装位置；
- 周期性质量管理规定到期。

## 6. 配置和数据合同

标定建议作为方案级数据加入 `SchemeState`，不要放入某个普通 `ToolConfig.params`。

建议结构：

```text
cameraCalibration
├─ schemaVersion
├─ calibrationId
├─ type
├─ status
├─ cameraId
├─ imageWidth
├─ imageHeight
├─ cameraParameterFingerprint
├─ boardType
├─ boardSpecification
├─ worldFrameName
├─ unit
├─ origin
├─ axisConvention
├─ pixelToWorldHomMat2D
├─ worldToPixelHomMat2D
├─ cameraParameters
├─ distortionParameters
├─ validImageRegion
├─ sampleSummary
├─ quality
│  ├─ meanError
│  ├─ p95Error
│  ├─ maxError
│  ├─ threshold
│  └─ passed
├─ createdAt
├─ verifiedAt
├─ operator
└─ halconVersion
```

生命周期：

| 状态 | 含义 | 是否允许生产消费 |
| --- | --- | --- |
| `empty` | 尚无标定 | 否 |
| `draft` | 已采集或已求解但未通过发布验证 | 否 |
| `ready` | 已验证并发布 | 是 |
| `stale` | 输入指纹或环境变化，需要复验 | 否 |
| `invalid` | 数据损坏、超差或计算失败 | 否 |
| `unsupported` | 当前 HALCON 环境不支持所选模式 | 否 |

旧方案中没有 `cameraCalibration` 字段时，按 `empty` 读取，不影响旧方案和已有工具加载。

## 7. UI 和交互规划

### 7.1 入口

- `CameraParamsDialog` 的“快速标定”作为主入口。
- `ReferenceImageDialog` 如保留相同按钮，应进入同一个标定流程，不实现第二套逻辑。
- 相机参数页应显示当前标定状态、版本、类型、单位、最大误差和最近验证时间。

### 7.2 标定向导页面

建议依次包含：

1. 类型和标定板设置；
2. 坐标系设置；
3. 图像采集与样本管理；
4. 求解结果和残差分布；
5. 独立验证；
6. 发布确认和历史版本。

### 7.3 交互约束

- 求解、验证和发布按钮必须按状态启用。
- 普通按钮不得误触发窗口关闭或方案保存。
- 删除样本或回退版本等操作必须明确目标并二次确认。
- 原始图像与 Overlay 分层，标定特征点和误差文字不得写回算法输入。
- 空图、相机断开、HALCON 异常和保存失败时不得崩溃。

## 8. 工程实施路径

### 工作包 A：专项确认和 HALCON 预检

- 确认现场标定类型、精度、坐标系和标定板。
- 确认 HALCON runtime、license、接口和符号。
- 用最小样例验证特征检测、求解和坐标转换。
- 将最终采用的 HALCON 接口补充到本文档。

完成证据：预检记录、样例输入、输出参数和明确的支持结论。

### 工作包 B：数据模型和持久化

- 新增标定数据结构及 JSON 序列化。
- 扩展 `SchemeState` 和 `SchemeStore`。
- 实现 schema 版本、旧方案默认值和未知版本拒绝。
- 明确“另存为”时标定结果及历史版本的复制规则。
- 增加输入指纹和失效判断。

完成证据：JSON 往返测试、旧方案加载、保存后重新打开回显。

### 工作包 C：HALCON Runner 和转换服务

- 新增 `src/algorithms/calibration/CalibrationHalconRunner.{h,cpp}`。
- 所有核心检测和求解使用 HALCON。
- 新增公共只读坐标转换辅助层。
- 对矩阵方向、逆矩阵、有效区域和非有限值统一校验。
- 返回稳定错误码及诊断信息。

完成证据：runner smoke、固定图集误差报告、异常路径结果。

### 工作包 D：标定向导 UI

- 新增独立 `CalibrationDialog`。
- 将现有“快速标定”入口接入同一 Dialog。
- 完成采集、样本剔除、求解、验证、发布和回显。
- 显示标定覆盖、逐点残差和质量结论。

完成证据：Dialog offscreen 测试和人工交互检查。

### 工作包 E：生产消费接入

- 加载方案时检查标定状态和输入指纹。
- 由统一转换服务提供像素/物理坐标转换。
- 首先选择一个代表性工具完成真实消费验证。
- 标定无效时返回明确错误，不静默降级。
- 后续再按需接入测量、定位、结果展示和外部坐标输出。

完成证据：代表性工具端到端测试以及失效传播测试。

## 10. 与基准姿态标定的边界

基准姿态标定继续归属模板定位和位置修正链路：

```text
参考图
  ↓ 同一个模板定位实例
referencePose = {x0, y0, angle0}

当前帧
  ↓ 同一个模板定位实例
runPose = {x, y, angle}

referencePose + runPose
  ↓
位置修正矩阵
```

基准姿态标定解决工件在图像中的位姿变化；相机/坐标系标定解决像素与物理坐标之间的转换。两者可以组合使用，但必须：

- 使用独立 schema 和状态；
- 分别验证质量；
- 明确矩阵方向和消费顺序；
- 失败时分别传播，不相互静默替代。

基准姿态和位置修正的详细流程以 `docs/FID/TemplateLocation/` 和 `docs/FID/PositionCorrection/` 文档为准。

## 11. 首版完成标准

只有同时满足以下条件，才能将标定从“界面占位”提升为“闭环可运行”：

- HALCON 能力已确认且核心算法全部使用 HALCON；
- 能新建、采集、求解、独立验证和发布；
- 标定数据能保存、重新加载和正确回显；
- 像素与物理坐标双向转换可用；
- 质量指标、有效区域和状态清晰可查；
- 标定缺失、超差或失效时禁止物理坐标消费；
- 空图、坏图、HALCON 异常和保存失败均返回可定位错误；
- 已完成构建、runner smoke、UI 检查和现场精度验收。
