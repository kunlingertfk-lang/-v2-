# 位置修正 UI 设计规范

## 1. 文档目的

本文档定义位置修正在“基准图”和“工具栏”两种入口中的 UI、交互、引用和状态规范。后续 UI 实现必须同时遵守：

- `AGENTS.md`
- `docs/FID/Function_Docs.md`
- `docs/FID/PositionCorrection/position_correction_function_implementation.md`
- `docs/FID/PositionCorrection/screenshots/README.md`

正式功能名称统一为“位置修正”；代码、配置和英文类型使用 `PositionCorrection`。

## 2. 已确认的产品模型

位置修正不是一个全局单例界面，而是两类独立节点：

1. **基准图位置修正**：属于当前方案的基准图配置，只允许一份，固定来源标识为 `reference.positionCorrection`。
2. **工具位置修正**：属于工具链中的普通定位工具，允许创建多个实例，每个实例拥有独立 `toolId`、参数、模板区域和输出。

其他视觉工具开启“独立位置修正使能”后，可以指定：

- `1 基准图.位置修正信息`；
- 当前工具之前、已启用且类型为位置修正的工具实例。

不得引用当前工具自身、后置工具、已删除工具或形成循环依赖的节点。

## 3. 视觉与布局原则

视觉基调为工业工作台：浅色参数面、深色图像画布、橙色主操作和状态强调。界面必须沿用现有方案编辑页与工具 Dialog 的尺寸、字体、控件角色和 QSS，不创建另一套视觉体系。

- 左侧配置区使用白色或近白底，深色文字。
- 右侧图像预览区允许使用近黑底，状态文字必须高对比。
- 主按钮使用橙色；普通操作使用白底、可见边框；危险状态使用红色。
- 参数卡片使用现有 `panelRole=configCard`。
- 卡片标题使用 `role=cardTitle`，字段标题使用 `role=rowField`，折叠入口使用 `role=collapseCard`。
- 无文字图标按钮必须设置具体 tooltip，不使用临时字符代替正式图标。
- `基础 / 全部` 使用互斥分段按钮；ROI 类型使用 `QButtonGroup` 或单一编辑状态管理。

截图用于结构、文案、显隐关系和操作顺序比对。截图中多基准图数量、缩略图槽位和其他工具结果属于外围方案能力，不在本文档中扩展当前工程的数据模型。

## 4. 基准图入口

### 4.1 所属位置

基准图位置修正位于 `ReferenceImageDialog` 左侧参数区，在基准图选择卡片之后。它不出现在工具列表中，不占用工具序号，也不计入工具数量。

### 4.2 关闭态与说明态

关闭时显示：

- 卡片标题：`位置修正`；
- 右侧开关，tooltip：`启用基准图位置修正`；
- 说明：`建立检测基准，修正视觉工具检测区域相对偏移，跟随基准移动。`；
- 启用与未启用位置修正的示意区。

关闭时不显示模板区域编辑控件，不产生可供下游实际使用的位置修正输出。下游若已引用该节点，应显示“来源未启用”，不得自动改选其他来源。

### 4.3 开启态

开启后保留标题和开关，并显示：

- `测试运行` 按钮；
- `模板区域设置` 卡片；
- 模板区域列表或单一模板区域行；
- 矩形 ROI 和多边形 ROI 两种互斥工具；
- `完成` 按钮。

模板区域编辑状态定义为：

```text
None
ReferenceTemplateRect
ReferenceTemplatePolygon
```

进入任一状态时必须退出另一状态；点击 `完成` 后保留 ROI 并回到 `None`。无基准图时禁止开始 ROI 编辑，提示 `请先设置基准图`。

### 4.4 基准图入口校验

- 开关打开但无基准图：允许保存方案草稿，禁止测试运行。
- 开关打开但无模板区域：允许保存方案草稿，禁止测试运行，并提示 `请先设置模板区域`。
- 后端未实现：测试入口不得显示伪造结果，统一提示 `位置修正后端尚未实现`，内部状态为 `not implemented`。

## 5. 工具库与工具列表入口

### 5.1 工具库

“位置修正”位于工具库的“定位工具”分类，与模板定位、单点对位、单点纠偏等定位类入口保持同级。工具按钮包含正式图标和文字 `位置修正`。

- 未选中时使用普通定位工具样式。
- 选中时使用现有橙色选中态。
- 右侧说明区显示：`根据基准与运行位置计算平移和旋转修正信息。`
- 点击确定后创建新的独立实例；不得复用已有位置修正工具。

### 5.2 工具列表

每次创建都生成新的稳定 `toolId`。工具列表按当前执行顺序显示动态序号，例如：

```text
12 位置修正
13 位置修正
```

卡片还应显示当前基准图上下文、配置状态和设置入口。动态序号仅用于显示，任何引用都不得保存序号作为唯一标识。

- 复制位置修正工具时生成新 `toolId`，复制其参数，但不复制其他工具对原实例的引用。
- 删除实例前检查引用关系；存在下游引用时给出明确影响提示。
- 删除后，下游保留原来源 ID 并进入“来源不可用”状态。
- 重排工具后重新计算菜单可见性；稳定 ID 不变，合法引用不串位。

## 6. 独立位置修正 Dialog

### 6.1 整体结构

完整 Dialog 沿用现有工具对话框：

```text
顶部：方案标题、工具名称、保存/另存为等方案动作
左侧：位置修正参数、基础/全部、底部动作按钮
右侧：基准图/当前图像预览、工具栏、状态栏、基准图缩略区
```

基础页必须包含：

1. `订阅基准范围` 卡片；
2. `运行点坐标X`；
3. `运行点坐标Y`；
4. `运行角度`；
5. `创建基准`；
6. `模板区域设置`；
7. `测试运行` 与 `完成`。

全部页第一阶段与基础页保持相同核心字段，只预留后续高级匹配参数区域；不得为了填满页面创建无定义参数。

### 6.2 输出字段绑定

运行点 X、Y、角度不是自由文本，而是上游输出绑定字段。每行右侧显示链接按钮，点击后打开两级菜单：

```text
一级：位于当前工具之前的有效节点
二级：该节点可提供的数值输出字段
```

菜单要求：

- 只列前置且已启用的节点；基准图节点固定在首项。
- 输出字段必须带稳定 `outputKey`，显示文本不能作为唯一键。
- X/Y 只接受坐标类数值，角度只接受角度类数值。
- 选择后输入框显示 `<序号 工具名>.<输出字段名>`。
- 来源被删除、禁用或移动到当前工具之后时，保留绑定并显示红色 `来源不可用`。
- 任一必需绑定无效时，禁止 `创建基准`、`测试运行` 和 Dialog `完成`。

### 6.3 创建基准

`创建基准` 使用当前绑定的 X、Y、角度和当前基准图建立该工具实例自己的检测基准。UI 阶段只保存配置意图和基准创建状态，不得伪造算法成功。

按钮状态：

- 无基准图：禁用，提示 `请先设置基准图`。
- 绑定不完整：禁用，提示缺少的字段。
- 后端未实现：可打开说明或返回 `not implemented`，不得写入成功状态。

### 6.4 模板区域

工具实例的模板区域与基准图位置修正互不共享。每个实例独立保存矩形或多边形模板 ROI，编辑状态为：

```text
None
ToolTemplateRect
ToolTemplatePolygon
```

右侧预览只显示当前实例的交互 ROI；退出 Dialog 后不得把编辑态 ROI 泄漏到工具页。后续真实测试结果 overlay 与编辑态 ROI 分开管理。

### 6.5 底部动作

- `测试运行`：后端未实现时显示明确未实现状态。
- `完成`：校验三项绑定、基准图和模板区域；失败时保持 Dialog 打开并定位到首个错误字段。
- 普通字段绑定、ROI、创建基准按钮不得触发 `accept`、`reject` 或程序退出。

## 7. 其他工具选择位置修正来源

其他视觉工具继续使用公共文案：

- 开关：`独立位置修正使能 ⓘ`
- 字段：`位置修正`
- 默认显示：`1 基准图.位置修正信息`

开关关闭时隐藏来源行；开启时显示来源选择器。来源菜单按执行顺序显示：

```text
1 基准图
12 位置修正
13 位置修正
```

选择结果显示为 `<序号 节点名>.位置修正信息`，但内部保存稳定来源 ID。

有效候选必须同时满足：

- 基准图位置修正已启用且有效；或工具类型为位置修正；
- 工具已启用；
- 位于当前消费工具之前；
- 不会形成循环依赖。

当使能开启且来源无效时：

- 来源框使用错误态边框；
- 显示 `来源不可用，请重新选择位置修正`；
- 禁止保存完成和测试运行；
- 不得自动回退到基准图。

使能关闭时允许保存原失效 ID，以便用户恢复来源后继续使用，但运行时不得应用位置修正。

## 8. 目标配置合同

以下为后续 UI 实施需要遵守的目标合同，本阶段只写文档，不修改代码。

### 8.1 消费工具

```json
{
  "enablePositionCorrection": true,
  "positionCorrectionSourceId": "tool_opaque_id",
  "positionCorrectionSource": "12 位置修正.位置修正信息"
}
```

- `positionCorrectionSourceId` 是真实引用键。
- `positionCorrectionSource` 是显示文本和旧配置兼容字段。
- 基准图来源 ID 固定为 `reference.positionCorrection`。

旧配置只有 `positionCorrectionSource` 时：

1. 精确等于 `1 基准图.位置修正信息` 时映射到固定基准图 ID；
2. 其他文本仅在前置节点中唯一匹配时补齐 ID；
3. 无法匹配或匹配不唯一时标为无效，不自动选择默认来源。

### 8.2 工具实例

位置修正工具目标类型为 `ToolType::PositionCorrection`，分类为 `ToolCategory::Location`。实例参数建议收敛到 `params.positionCorrection`：

```json
{
  "version": 1,
  "runPointX": {"producerId": "upstream_id", "outputKey": "x", "displayPath": "6 工具.匹配点X"},
  "runPointY": {"producerId": "upstream_id", "outputKey": "y", "displayPath": "6 工具.匹配点Y"},
  "runAngle": {"producerId": "upstream_id", "outputKey": "angle", "displayPath": "6 工具.匹配角度"},
  "templateRegionType": "rectangle",
  "templateRoiNormalized": {"x": 0.0, "y": 0.0, "width": 0.0, "height": 0.0},
  "templatePolygonNormalized": [],
  "referenceCreated": false
}
```

`displayPath` 只用于回显；解析和运行必须使用 `producerId + outputKey`。

### 8.3 基准图配置

基准图位置修正属于方案级配置，不写入 `toolConfigs`。目标存储节点为 `referencePositionCorrection`，至少包含：

```text
version
enabled
templateRegionType
templateRoiNormalized
templatePolygonNormalized
```

旧方案缺少该节点时按 `enabled=false` 处理。

## 9. 状态与提示

| 场景 | UI 行为 | 状态文本 |
| --- | --- | --- |
| 无基准图 | 禁止 ROI、创建基准和测试 | `请先设置基准图` |
| 未设置模板区域 | 允许保存草稿，禁止测试 | `请先设置模板区域` |
| 运行值绑定缺失 | 标红缺失行，禁止完成和测试 | `请绑定运行点坐标X/Y/运行角度` |
| 来源已删除或后置 | 保留 ID，来源框错误态 | `来源不可用，请重新选择` |
| 来源未启用 | 保留 ID，不自动回退 | `位置修正来源未启用` |
| 后端未实现 | 不生成 OK/NG | `位置修正后端尚未实现` |
| 配置有效但尚未测试 | 使用中性状态 | `配置已保存，尚未测试` |

## 10. 截图对照验收

| 截图 | 界面区域 | 必须复现 | 不纳入本功能 |
| --- | --- | --- | --- |
| PC-UI-01 | 基准图说明态 | 标题、开关、说明、双示意区 | 多基准图业务逻辑 |
| PC-UI-02 | 基准图设置态 | 测试运行、模板区域、两种 ROI、完成 | 基准图 2/8 数据模型 |
| PC-UI-03 | 工具库 | 定位分类、位置修正入口、选中态 | 其他未实现定位工具 |
| PC-UI-04 | 工具 Dialog | 基础/全部、三项绑定、创建基准、预览 | 截图中的具体检测结果 |
| PC-UI-05 | 字段菜单 | 工具分组、字段二级菜单、选中回显 | 未定义字段的算法含义 |
| PC-UI-06 | 工具列表 | 多实例、动态编号、独立设置入口 | 其他工具的真实 OK/NG |
| PC-UI-07 | 下游工具 | 使能开关、基准图和多实例来源 | 颜色比较算法本身 |

验收优先级为：交互和数据安全 > 控件显隐与文案 > 布局层级 > 像素细节。不得为了像素相似破坏现有 QSS、可读性或按钮安全约束。

## 11. 本阶段范围

本阶段只建立 UI 和配置设计规范：

- 不新增 `ToolType`、Dialog、Adapter 或 Runner。
- 不修改 `SchemeStore` 或配置迁移代码。
- 不实现模板匹配、位置计算或 ROI 补偿。
- 不伪造基准创建、测试成功、OK/NG 或输出字段。
- 后续实施必须另行编制计划，并验证 qmake、make、配置回显和 UI 交互。
