# 位置修正公共消费辅助层实施计划

新增工具需要接入本公共层时，按《[工具级功能接入位置修正指南](工具级功能接入位置修正指南.md)》逐步实施和验收。

更新时间：2026-07-23

## 当前实施事实

- 公共 Consumer、普通几何 Transform 和 HALCON Region Transform 均已落地。
- 颜色比较与 Blob 有无是当前两个完整消费者；其他工具只可参考本文接入，不能视为已经完成。
- 每帧动态结果由 `ToolEngine` 重建，Consumer 校验稳定 ID、工具类型和 `frameId`。
- 位姿与尺度执行严格数值校验；历史编号 1 的基准显示文本迁移到当前编号 0 和固定 ID。

第 2 节保留公共层实施前的历史基线；当前状态以本节和第 12 节后的实施记录为准。

## 1. 理解复述

### 1.1 目标

在已经完成的位置修正计算底座之上，抽取公共的下游消费能力，使颜色比较、Blob、圆、边、线、轮廓、OCR 等工具能够用一致方式消费本帧位置修正结果。

公共能力拆成两个职责明确的部分：

- `PositionCorrectionConsumer`：取得、校验并整理位置修正上下文，不修改、不保存也不移动任何 ROI。
- `PositionCorrectionTransform`：把 Consumer 提供的同一份 `referenceToRunHomMat2D` 真正应用到算法 Region 和 UI Overlay，完成平移、旋转和缩放。

位置修正来源仍由上游基准图位置修正或工具位置修正执行。公共消费层不得再次做模板匹配，也不得修改下游工具保存的基准 ROI。

### 1.2 输入

- 当前消费工具的 `ToolConfig.params.positionCorrection`。
- 当前帧 `ToolRequest.runtimeContext.positionCorrectionsById`。
- 消费工具保存在基准坐标系中的归一化 ROI、屏蔽区和显示几何。
- 上游修正结果中的 `referenceToRunHomMat2D`、`runToReferenceHomMat2D`、尺度信息和匹配轮廓。

### 1.3 输出

- 一个只读的 `PositionCorrectionContext`，描述本帧是否请求、是否应用、来源、矩阵、尺度、匹配轮廓和诊断状态。
- 由公共 Transform 生成的本帧临时 HALCON Region。
- 由公共 Transform 生成的本帧临时 Overlay 几何。
- 统一的失败结果、错误码和用户可见提示。

### 1.4 边界

- 原始 ROI 继续由各工具保存，公共层不拥有 ROI。
- 配置保存归一化 ROI；矩阵只作用于按基准图尺寸还原后的像素坐标。
- 实际算法区域必须使用 HALCON `affine_trans_region` 等既有算子。
- UI Overlay 可以使用公共坐标变换，但必须和算法 Region 使用同一矩阵。
- 同一个消费工具一次只应用一个最终绝对修正来源，不自动叠加全局和局部矩阵。
- 匹配失败时禁止静默回退到未修正 ROI。
- 修正后的临时 ROI 不写回 `ToolConfig`，避免连续运行累计变换。

## 2. 历史：实施前事实、缺口与默认假设

### 2.1 已确认事实

- `PositionCorrectionHalconRunner` 已输出正向、逆向相似变换矩阵。
- 位姿合同已经包含 `x/y/angle/scale`，旧配置缺少尺度时按 `1.0` 兼容。
- `ToolEngine` 已按来源 ID 将当帧修正结果登记到 `positionCorrectionsById`。
- 颜色比较已经完整消费矩阵，并用 HALCON 修正实际 Region。
- 颜色比较已经验证矩形、圆形、旋转、平移、缩放和匹配轮廓显示。

### 2.2 当时缺口

- 运行上下文解析和错误处理仍写在 `ColorComparisonAdapter` 中。
- 点、矩形、圆、多边形和 Overlay 的变换仍写在颜色比较 Runner 中。
- 其他工具虽然部分界面已有位置修正开关，但 Adapter/Runner 尚未统一消费修正矩阵。
- 公共层尚未定义“不开启、成功、匹配失败、来源缺失、轮廓缺失”的统一结果语义。

### 2.3 默认假设

- 第一批迁移选择 ROI 结构简单、HALCON Region 链路稳定的工具。
- 公共层先支持当前已经出现的点、矩形、圆、多边形、轮廓和屏蔽区。
- 非等比缩放或透视变换不在本阶段范围内；当前矩阵为二维平移、旋转和等比缩放。
- AI 工具只复用 Consumer 和普通坐标变换，不强制使用 HALCON Region 输入。

## 5. PositionCorrectionConsumer 详细职责

按以下顺序执行：

1. 读取消费工具的启用状态和稳定 `sourceId`。
2. 未启用时返回空的成功上下文。
3. 启用但 `sourceId` 为空时返回 `position_correction_source_missing`。
4. 从 `request.runtimeContext.positionCorrectionsById` 查找本帧结果。
5. 校验结果属于选定的稳定来源 ID。
6. 校验来源状态；将 `not_found` 映射为明确的匹配失败。
7. 读取并校验正向矩阵必须包含六个有限数值。
8. 读取逆矩阵、参考尺度、运行尺度和尺度比；缺少尺度按 `1.0` 兼容，非法尺度严格失败。
9. 从来源结果 Overlay 中提取 `match_result` 或标准匹配轮廓角色。
10. 返回只读上下文，不改动工具 ROI，不调用 HALCON Region 变换。

统一错误码：

| 场景 | 错误码 |
| --- | --- |
| 未选择或找不到来源 | `position_correction_source_missing` |
| 来源 ID 不一致 | `position_correction_source_invalid` |
| 模板未匹配到 | `position_correction_match_not_found` |
| 来源执行失败 | `position_correction_source_failed` |
| 矩阵不是六个有限数值 | `invalid_position_correction_matrix` |
| 尺度不是有限正数 | `invalid_pose_scale` |

Consumer 不负责：

- 不创建或更新模板。
- 不运行定位工具。
- 不修改 ROI。
- 不裁剪 Region。
- 不保存运行矩阵到工具配置。
- 不决定具体算法是否使用矩形、圆形或多边形。

## 6. PositionCorrectionTransform 详细职责

### 6.1 普通几何和 Overlay

建议新增：

```text
src/toolcore/PositionCorrectionTransform.h
src/toolcore/PositionCorrectionTransform.cpp
```

接口建议：

```cpp
QPointF transformPoint(
        const QPointF &point,
        const QVector<double> &homMat2D);

QPolygonF transformPolygon(
        const QPolygonF &polygon,
        const QVector<double> &homMat2D);

ToolOverlay transformOverlay(
        const ToolOverlay &overlay,
        const QVector<double> &homMat2D);
```

几何规则：

- 点：直接应用矩阵。
- 线：变换起点和终点。
- 多边形/轮廓：逐点变换。
- 矩形：变换四个角，旋转后优先输出四点多边形，不丢失方向。
- 圆：变换圆心和一个半径点，两点距离作为修正后半径。
- 文本锚点：变换锚点，文字本身不随对象缩放。
- 匹配轮廓：上游结果已经位于运行图坐标系，不得再次变换。

矩阵坐标约定：

```text
Qt:     x = column, y = row
HALCON: row = y, column = x
```

所有公共点变换必须增加 90° 旋转 smoke，防止 Row/Column 交换。

### 6.2 HALCON Region

建议新增：

```text
src/algorithms/location/PositionCorrectionHalconTransform.h
src/algorithms/location/PositionCorrectionHalconTransform.cpp
```

接口建议：

```cpp
PositionCorrectionTransformResult transformRegion(
        const HalconCpp::HObject &referenceRegion,
        const PositionCorrectionContext &context,
        HalconCpp::HObject *runRegion);
```

实现规则：

1. 未请求修正时返回原始 Region 的等价对象。
2. 已请求但 `applied=false` 时严格失败。
3. 使用 `referenceToRunHomMat2D` 调用 HALCON `affine_trans_region`。
4. 插值方式先沿用颜色比较已验证的 `nearest_neighbor`。
5. 主 ROI、屏蔽区和所有子 ROI 必须使用同一矩阵。
6. 输出只在当前 runner 调用中使用，不写回配置。
7. 变换后与当前图像域求交；完全落在图外时返回明确的 `corrected_roi_out_of_image`。
8. HALCON runtime、license 或符号异常沿用现有 runner 错误转换，不使用 OpenCV 或自写替代算法。

若工具以 XLD 轮廓作为实际算法输入，再补充：

```cpp
transformContourXld(...)
```

内部使用 HALCON `affine_trans_contour_xld`。

## 7. 配置和结果语义

消费工具继续使用现有配置：

```json
{
  "positionCorrection": {
    "enabled": true,
    "sourceId": "position-correction-tool-id",
    "showMatchContour": true
  }
}
```

公共 Consumer 只读该配置。运行结果建议统一补充：

```json
{
  "positionCorrectionRequested": true,
  "positionCorrectionApplied": true,
  "positionCorrectionSourceId": "position-correction-tool-id",
  "referenceToRunHomMat2D": [1, 0, 0, 0, 1, 0],
  "referenceScale": 1.0,
  "runScale": 1.2,
  "scaleRatio": 1.2,
  "positionCorrectionContourStatus": "available"
}
```

匹配轮廓 Overlay 统一使用：

```json
{
  "role": "position_correction_match_contour",
  "positionCorrectionSourceId": "position-correction-tool-id"
}
```

实际匹配原点 Overlay 统一使用两条相交直线：

```json
{
  "role": "position_correction_match_origin",
  "positionCorrectionSourceId": "position-correction-tool-id"
}
```

该原点是模板定位按质心或自定义原点计算得到的本帧实际运行坐标，不是基准图上的静态编辑标记。显示开关关闭时只过滤匹配轮廓角色，不删除位置修正上下文、不影响真实 ROI 修正，也不隐藏实际匹配原点。

### 步骤 4：抽取 HALCON Region Transform

- 将颜色比较中的 `affine_trans_region` 调用收口到公共 HALCON Transform。

完成证据：

- HALCON Region 面积、中心、方向和尺度回归通过。
- 颜色比较实际检测 Region 与 UI Overlay 使用同一矩阵。
- HALCON 缺失时返回明确错误。

### 步骤 5：迁移颜色比较作为样板

- Adapter 只负责解析颜色参数和调用 Consumer。
- Runner 只负责创建基准 ROI、调用公共 Transform、执行颜色算法。
- 结果组装调用公共轮廓追加和诊断写入能力。
- 删除颜色比较内部已经被公共层替代的重复函数。

完成证据：

- 配置保存和回显不变。
- 同一测试图片迁移前后得分、OK/NG、ROI 和轮廓显示一致。
- 连续运行不会把上一次修正后的 ROI 当作下一次基准继续变换。

### 步骤 6：选择第二个 ROI 工具验证通用性

优先选择 Blob 或轮廓有无工具：

- 接入统一位置修正配置读取。
- Adapter 调用 Consumer。
- Runner 对主 ROI 和屏蔽区调用 HALCON Transform。
- Overlay 调用普通几何 Transform。

完成证据：

- 第二个工具没有复制颜色比较的上下文解析代码。
- 平移、旋转、缩放和匹配失败路径通过。
- 证明公共层不是颜色比较专用封装。

### 步骤 7：分批迁移其他工具

建议顺序：

1. Blob、轮廓有无、颜色识别。
2. 圆、边、线等几何检测。
3. OCR、分类等裁剪区域工具。
4. AI 检测等非 HALCON Region 输入工具。

每个工具迁移时只修改自己的 Dialog/Adapter/Runner 和专项测试，不批量重构无关算法。

- 更新位置修正实现文档和 `HANDOFF.md` 当前状态。

## 9. 验收矩阵

| 类别 | 场景 | 预期 |
| --- | --- | --- |
| 开关 | 未开启位置修正 | 使用原 ROI，不产生错误 |
| 来源 | 来源不存在、禁用或后置 | 明确失败，不使用旧矩阵 |
| 匹配 | 当前帧未匹配到 | 明确 NG，不回退原 ROI |
| 帧一致性 | 上帧成功、本帧失败 | 本帧不得沿用上帧矩阵 |
| 平移 | 目标向右下移动 | 实际 Region 和显示框同向移动 |
| 旋转 | 目标旋转 90° | 四角、Region 和 Row/Column 方向正确 |
| 缩放 | 运行尺度为基准 1.5 倍 | ROI 尺寸和圆半径变为 1.5 倍 |
| 组合 | 平移、旋转、缩放同时发生 | 使用完整矩阵，不能拆成简单坐标加减 |
| 屏蔽区 | 主 ROI 带屏蔽区 | 两者使用同一矩阵 |
| 图像边界 | 修正 ROI 部分出图 | 与图像域求交后执行 |
| 图像边界 | 修正 ROI 完全出图 | 返回 `corrected_roi_out_of_image` |
| 显示 | 关闭匹配轮廓 | 只隐藏轮廓，不关闭位置修正 |
| 显示 | 开启但没有可显示轮廓 | 算法可成功，同时给出明确警告 |
| 配置 | 连续运行 | 原始归一化 ROI 始终不变 |
| 兼容 | 旧位姿缺少 scale | 按 `1.0` 执行 |
| 异常 | 非法矩阵、非法尺度 | 返回稳定错误码，不崩溃 |
| HALCON | runtime/license/符号缺失 | 明确失败，不切换替代算法 |

## 10. 完成标准

公共消费辅助层完成必须同时满足：

- Consumer 完全不拥有、不修改、不移动 ROI。
- Transform 不查找位置来源，也不运行模板匹配。
- 颜色比较迁移后行为和得分无回归。
- 至少第二个独立 ROI 工具完成接入，证明公共性。
- 实际算法 Region 和显示 Overlay 共用同一矩阵。
- 平移、旋转、缩放、圆半径、屏蔽区和图像边界均有自动化测试。
- 匹配失败和来源异常不会静默使用原 ROI 或历史矩阵。
- 原始工具配置不会被运行态变换污染。
- qmake、主工程 make、公共 smoke 和消费工具专项 smoke 全部通过。

## 11. 本阶段不做

- 不重新设计模板定位。
- 不让 Consumer 保存 ROI。
- 不让 Transform 读取工具链上下文。
- 不自动组合多个修正来源。
- 不引入透视、仿射非等比缩放或三维标定。
- 不用 OpenCV、自写算法或第三方库替代 HALCON Region/XLD 变换。
- 不一次性迁移全部工具；先完成颜色比较样板和第二工具验证。

## 12. 2026-07-23 实施记录

本计划的公共底座和前两个消费工具已经落地：

- 新增 `PositionCorrectionConsumer`，统一处理启用状态、稳定来源 ID、本帧来源结果、矩阵、尺度、匹配轮廓和错误映射。
- 新增 `PositionCorrectionTransform`，统一处理点、线、矩形四角、圆、多边形、文本锚点和匹配轮廓 Overlay。
