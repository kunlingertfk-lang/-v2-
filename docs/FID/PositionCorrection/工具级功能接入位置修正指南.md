# 工具级功能接入位置修正指南

## 1. 文档目的

本文说明一个已有视觉工具如何作为“位置修正消费工具”接入公共位置修正能力，使该工具能够完整完成：

1. 在配置界面开启或关闭位置修正。
2. 选择方案级基准图位置修正，或选择位于当前工具之前的工具级位置修正节点。
3. 保存稳定的来源 ID，并在重新打开后正确回显。
4. 每帧取得所选来源生成的位置修正矩阵。
5. 使用 HALCON 将基准坐标系中的检测 ROI 平移、旋转和缩放到当前运行图。
6. 在修正后的真实 Region 内执行算法。
7. 显示修正后的检测 ROI、匹配轮廓和实际匹配原点。
8. 在工具配置窗口的“基准图测试/测试运行”中执行完整前置链路，而不是孤立运行当前工具。
9. 对来源缺失、模板未匹配、矩阵非法、修正 ROI 越界等情况给出明确错误。

本文适用于 Blob、圆、边、线、轮廓、OCR、颜色类等需要检测 ROI 的工具。本文不负责创建新的位置修正生产节点，也不改变模板定位或位置修正矩阵的计算逻辑。

## 2. 正常运行链路

工具级位置修正的标准链路是：

```text
基准图
  │
  ├─ 创建模板定位模型和基准姿态
  │
运行图
  │
  ├─ 模板定位工具
  │    输出当前 x / y / angle / scale、匹配轮廓和匹配原点
  │
  ├─ 位置修正工具
  │    对比 referencePose 与 runPose
  │    输出 referenceToRunHomMat2D
  │
  └─ 当前消费工具
       读取本帧位置修正结果
       变换基准 ROI
       在修正后的 HALCON Region 内检测
       输出结果和运行 Overlay
```

方案级基准图位置修正不依赖工具列表中的模板定位节点，但消费方式相同。它使用固定稳定 ID：

```text
reference.positionCorrection
```

一个消费工具一次只能选择一个最终位置修正来源。不得自动叠加全局和工具级矩阵，否则会产生双重补偿。

## 3. 接入前检查

开始修改前必须确认：

- 工具已有完整的 Dialog、`ToolConfig`、Adapter、HALCON Runner 和 `ToolResult` 链路。
- 工具的检测 ROI 以基准图归一化坐标保存。
- Runner 能在整张运行图的绝对坐标系中创建 HALCON Region。
- 工具位于所选位置修正节点之后。
- `qt_ui_test.pro` 已包含公共位置修正文件。
- 不使用 OpenCV 或自写算法替代 HALCON Region 变换。

需要使用的公共文件：

```text
src/toolcore/PositionCorrection.h
src/toolcore/PositionCorrectionConsumer.h
src/toolcore/PositionCorrectionTransform.h
src/algorithms/location/PositionCorrectionHalconTransform.h
```

职责边界：

| 模块 | 职责 | 不负责 |
|---|---|---|
| `PositionCorrectionConsumer` | 查找本帧来源、校验状态、矩阵和尺度、提取匹配 Overlay | 不移动 ROI，不执行模板匹配 |
| `PositionCorrectionTransform` | 移动普通几何和 UI Overlay | 不读取运行上下文，不变换 HALCON Region |
| `PositionCorrectionHalconTransform` | 用 HALCON 变换并裁剪真实检测 Region | 不保存配置，不生成来源结果 |
| 当前工具 Adapter | 解析消费配置、调用 Consumer、传递 Context | 不自行解析矩阵元素 |
| 当前工具 Runner | 创建基准 Region、应用矩阵、执行算法和生成 Overlay | 不重新查找位置修正来源 |

## 4. 第一步：在配置结构中增加位置修正

### 4.1 推荐配置字段

在 `ToolConfig.params` 顶层保存：

```json
{
  "enablePositionCorrection": true,
  "positionCorrectionSourceId": "position-correction-tool-id",
  "positionCorrectionSource": "2 位置修正.位置修正信息",
  "showPositionCorrectionMatchContour": true
}
```

字段语义：

- `enablePositionCorrection`：是否应用位置修正。
- `positionCorrectionSourceId`：运行引用使用的稳定 ID，必须保存。
- `positionCorrectionSource`：界面显示文本，只用于回显和旧配置兼容。
- `showPositionCorrectionMatchContour`：是否显示匹配轮廓；默认 `true`。

禁止只保存下拉框文字。工具序号会随着插入、删除和重排发生变化，运行时必须使用 `positionCorrectionSourceId`。

### 4.2 使用公共读写接口

保存时优先使用：

```cpp
PositionCorrectionConfig correction;
correction.enabled = positionCorrectionSwitch->isChecked();
correction.sourceId = positionCorrectionComboBox->currentData().toString();
correction.source = positionCorrectionComboBox->currentText();

QJsonObject params = config.params;
PositionCorrection::writeParams(correction, &params);
params.insert(QStringLiteral("showPositionCorrectionMatchContour"),
              showMatchContourCheckBox->isChecked());
config.params = params;
```

读取时：

```cpp
const PositionCorrectionConfig correction =
        PositionCorrection::fromParams(config.params);
positionCorrectionSwitch->setChecked(correction.enabled);
```

回显下拉框时按稳定 ID 查找 `itemData`，不能按显示文字作为唯一依据。

## 5. 第二步：接入 Dialog 控件和来源菜单

### 5.1 必要控件

Dialog 至少提供：

- “位置修正”开关。
- “位置修正来源”下拉框。
- “显示匹配轮廓”开关；如果产品要求简化界面，可以默认写入 `true` 并暂时隐藏控件。

位置修正关闭时可以隐藏来源行，但不得清空已保存的稳定来源 ID。

### 5.2 控件命名

当前 `ToolsDialog` 会查找对象名中包含 `positionCorrection` 的 `QComboBox`，并自动注入合法前置来源。因此建议命名：

```text
positionCorrectionComboBox
basicPositionCorrectionComboBox
```

### 5.3 来源过滤规则

来源列表必须通过公共顺序规则生成：

- 方案级基准图位置修正已开启并创建成功时，列为可选来源。
- 只列出当前消费工具之前、已启用的位置修正节点。
- 禁止选择当前工具自身。
- 禁止选择当前工具之后的节点。
- 来源被删除、禁用或移到当前工具之后时，保留原稳定 ID，并显示“来源不可用”，不得自动切换到其他来源。

现有 `ToolsDialog` 已通过 `positionCorrectionSourcesFor()`、`configurePositionSourceCombos()` 和 `persistPositionSource()`处理该规则。

### 5.4 Dialog 内测试必须直接取得稳定 ID

`ToolsDialog::persistPositionSource()` 只会在 Dialog 点击“完成”后执行。Dialog 内的“基准图测试/测试运行”发生在点击“完成”之前，因此当前临时 `ToolConfig` 必须直接读取：

```cpp
const QString sourceId =
        positionCorrectionComboBox->currentData().toString().trimmed();
```

并写入：

```cpp
params.insert(QStringLiteral("positionCorrectionSourceId"), sourceId);
```

否则 Dialog 测试可能把“2 位置修正.位置修正信息”当作来源 ID，导致运行上下文中查找不到对应节点。

## 6. 第三步：在 Runner 配置中保存公共 Context

在当前工具的 HALCON 配置结构中增加：

```cpp
#include "toolcore/PositionCorrectionConsumer.h"

struct XxxHalconConfig
{
    // 原有字段……
    bool enablePositionCorrection = false;
    QString positionCorrectionSource;
    PositionCorrectionContext positionCorrection;
};
```

Runner 只读取 `PositionCorrectionContext`。不要让 Runner 再从 JSON 或 `ToolRequest.runtimeContext` 查找来源。

## 7. 第四步：Adapter 调用公共 Consumer

Adapter 负责把保存配置和本帧运行上下文连接起来。

标准代码结构：

```cpp
#include "toolcore/PositionCorrection.h"
#include "toolcore/PositionCorrectionConsumer.h"

ToolResult XxxAdapter::run(const ToolRequest &request)
{
    XxxHalconConfig runnerConfig = toHalconConfig(request.config);

    const PositionCorrectionConfig savedCorrection =
            PositionCorrection::fromParams(request.config.params);

    PositionCorrectionConsumerOptions options;
    options.requested = savedCorrection.enabled;
    options.sourceId = savedCorrection.sourceId;
    options.showMatchContour =
            request.config.params
            .value(QStringLiteral("showPositionCorrectionMatchContour"))
            .toBool(true);

    const PositionCorrectionResolveResult resolved =
            PositionCorrectionConsumer::resolve(request, options);

    if (!resolved.success) {
        return ToolResult::error(
                    request.config.toolId,
                    request.config.toolType,
                    resolved.message,
                    resolved.status);
    }

    runnerConfig.enablePositionCorrection = savedCorrection.enabled;
    runnerConfig.positionCorrectionSource = savedCorrection.source;
    runnerConfig.positionCorrection = resolved.context;

    const XxxHalconResult runnerResult =
            m_runner.run(request.image, runnerConfig);

    return convertResult(request.config, runnerResult);
}
```

公共 Consumer 已处理：

- 未开启位置修正时正常放行，`applied=false`。
- 默认基准图稳定 ID 映射。
- `positionCorrectionsById` 来源查找。
- 来源运行成功、OK 和 `positionCorrectionApplied` 状态。
- `referenceToRunHomMat2D` 六个有限数值校验。
- 可选反向矩阵校验。
- `referenceScale`、`runScale`、`scaleRatio` 正数校验。
- 匹配轮廓和匹配原点提取。

Adapter 不应复制这些判断。

## 8. 第五步：理解运行上下文的来源

`ToolEngine::runTools()` 会按方案顺序执行工具，并把每个结果注册到本帧上下文：

```json
{
  "toolResultsById": {
    "tool-id": {}
  },
  "positionCorrectionsById": {
    "position-correction-tool-id": {}
  }
}
```

消费工具只有在以下条件同时成立时才能取得修正：

1. 使用 `ToolEngine::runTools()` 执行工具链。
2. 所选位置修正来源在消费工具之前。
3. 来源在本帧确实执行。
4. 来源输出成功并包含有效矩阵。
5. 消费工具的稳定来源 ID 与上下文键一致。

不能通过单独调用：

```cpp
engine.runTool(request);
```

自动获得前置位置修正结果。`runTool()` 只运行当前工具，调用方必须自行提供完整 `request.runtimeContext`。

## 9. 第六步：用 HALCON 变换真实检测 Region

这是接入是否真正生效的核心。只移动显示框不算完成位置修正。

### 9.1 正确处理顺序

```text
基准归一化 ROI
  ↓
换算为整张图的绝对像素坐标
  ↓
在整张运行图坐标系中创建 HALCON Region
  ↓
使用 referenceToRunHomMat2D 执行 affine_trans_region
  ↓
将变换后 Region 裁剪到运行图范围
  ↓
reduce_domain
  ↓
执行当前工具算法
```

禁止先从原 ROI 裁剪一张局部 `cv::Mat`，再对局部坐标 Region 应用全图矩阵。这样会混用局部坐标和绝对坐标，平移、旋转中心及缩放都会错误。

### 9.2 创建基准 Region

矩形、圆和多边形都必须在整张图像坐标中创建：

```cpp
if (rectangleMode) {
    // gen_rectangle1
} else if (circleMode) {
    // gen_circle
} else if (polygonMode) {
    // gen_region_polygon_filled
}
```

### 9.3 应用公共 HALCON 变换

```cpp
Hobject transformedRegion = 0;
Hobject clippedRegion = 0;

const PositionCorrectionHalconTransformResult transformed =
        PositionCorrectionHalconTransform::transformAndClipRegion(
            positionCorrectionRegionApi(api),
            referenceRegion,
            &transformedRegion,
            &clippedRegion,
            config.positionCorrection.referenceToRunHomMat2D,
            image.cols,
            image.rows);

if (!transformed.success) {
    // 返回 transformed.status 和具体 operation
}

if (transformed.area <= 0.0) {
    // 返回 corrected_roi_out_of_image
}
```

随后：

```cpp
reduce_domain(fullImage, clippedRegion, &reducedImage);
```

当前算法必须在 `reducedImage` 或 `clippedRegion` 内运行。

### 9.4 未开启位置修正时

未开启时保留工具原有路径，不能强制依赖位置修正：

```cpp
if (config.positionCorrection.applied) {
    // 全图 Region + 位置修正路径
} else {
    // 原有固定 ROI 路径
}
```

## 10. 第七步：同步修正显示 Overlay

算法 Region 和显示 Overlay 必须使用同一份 `referenceToRunHomMat2D`。

### 10.1 修正检测 ROI

先根据基准 ROI 创建 Overlay：

```cpp
ToolOverlay detectOverlay = makeDetectOverlay(baseRoi);
```

再应用公共变换：

```cpp
if (config.positionCorrection.applied) {
    detectOverlay = PositionCorrectionTransform::transformOverlay(
                detectOverlay,
                config.positionCorrection.referenceToRunHomMat2D);
    detectOverlay.extra.insert(
                QStringLiteral("positionCorrectionSourceId"),
                config.positionCorrection.sourceId);
}
detectOverlay.extra.insert(QStringLiteral("role"),
                           QStringLiteral("detect_roi"));
result.overlays.append(detectOverlay);
```

矩形经过旋转后会变成四点 Polygon；不要再用轴对齐矩形冒充真实 ROI。

### 10.2 显示匹配轮廓

```cpp
if (config.positionCorrection.applied
        && config.positionCorrection.showMatchContour) {
    result.overlays +=
            PositionCorrectionTransform::matchContourOverlays(
                config.positionCorrection.matchContours,
                config.positionCorrection.sourceId);
}
```

标准角色：

```text
position_correction_match_contour
```

### 10.3 显示实际匹配原点

```cpp
if (config.positionCorrection.applied) {
    result.overlays +=
            PositionCorrectionTransform::matchOriginOverlays(
                config.positionCorrection.matchOrigins,
                config.positionCorrection.sourceId);
}
```

标准角色：

```text
position_correction_match_origin
```

当前约定中，“显示匹配轮廓”开关只隐藏轮廓，不隐藏实际匹配原点。

匹配原点已经是模板定位计算出的当前运行坐标，不要再次应用位置修正矩阵，否则会二次变换。

### 10.4 运行后必须过滤配置阶段的基准 ROI

很多 Dialog 使用两套彼此独立的显示层：

- `setRoiRectNormalized()`、`setPolygonRoiNormalized()`、
  `setCircleRoiNormalized()` 绘制配置阶段的基准 ROI。
- `setToolOverlays(result.overlays)` 绘制 Runner 返回的运行态 Overlay。

`setToolOverlays()` 只会清除上一批运行 Overlay，不会清除配置 ROI。若运行结果已经包含
角色为 `detect_roi` 的修正后 ROI，却仍调用 `refreshDisplayedRoiOverlay()`，画布就会同时
出现基准 ROI 和修正后 ROI。此时算法可能完全正确，但显示层会让用户误以为旧 ROI 仍参与检测。

正确规则：

1. 编辑态或运行结果没有 `detect_roi` 时，显示配置 ROI。
2. 运行结果包含 `detect_roi` 时，先调用 `clearRoi()`、`clearPolygonRoi()` 和
   `clearCircleRoi()` 清除所有配置 ROI。
3. 再通过 `setToolOverlays(result.overlays)` 显示唯一的运行态检测 ROI。
4. 下一次重新进入 ROI 编辑态时，再恢复配置 ROI。
5. 不允许通过颜色相同或坐标重合掩盖两套 ROI；必须按 `extra.role == "detect_roi"`
   明确切换显示所有权。

参考实现：

```cpp
const bool hasRuntimeDetectRoi = std::any_of(
            result.overlays.cbegin(), result.overlays.cend(),
            [](const ToolOverlay &overlay) {
    return overlay.extra.value("role").toString() == "detect_roi";
});
if (hasRuntimeDetectRoi) {
    preview->clearRoi();
    preview->clearPolygonRoi();
    preview->clearCircleRoi();
} else {
    refreshConfiguredRoi();
}
preview->setToolOverlays(result.overlays);
```

这项检查属于所有位置修正消费工具的必做项，不是 Blob 专项行为。

### 10.5 重跑、退出测试和恢复基准图时必须重置显示层

`FrameViewHelper::setImage()` 只替换底图，不会删除 `setToolOverlays()` 创建的运行结果项。
因此仅恢复基准图而不调用 `clearToolOverlays()`，会把上一轮匹配轮廓、匹配原点、修正 ROI、
算法框和结果文字叠加到编辑态基准图上。

必须遵循以下显示层生命周期：

1. 发起新一轮测试前，调用 `clearToolOverlays()` 删除上一轮运行结果。
2. 清除运行结果后，通过 `refreshConfiguredRoi()` 或等价函数恢复配置 ROI。
3. 显示“运行中…”或包含前置链阶段的等价状态，再发射新请求。
4. 本轮结果返回后，根据第 10.4 节规则切换配置 ROI 与运行态 `detect_roi` 的显示所有权。
5. 点击“退出测试”、切换回基准图或基准图内容更新时，必须再次
   `clearToolOverlays()`，然后只恢复配置 ROI。
6. 退出测试后必须清除导入图测试来源；后续“测试运行”不得继续使用旧导入帧。

参考顺序：

```cpp
preview->setImage(referenceImage);
preview->clearToolOverlays();
refreshConfiguredRoi();
```

禁止依赖 `setImage()`、相同图片覆盖或相同坐标重绘来隐藏旧结果。无论新旧结果是否一致，
每轮请求都必须具有明确的“旧结果移除 → 运行中 → 新结果填充”状态变化。

## 11. 第八步：写入诊断 Payload

当前工具结果至少写入：

```json
{
  "positionCorrectionRequested": true,
  "positionCorrectionApplied": true,
  "positionCorrectionSourceId": "position-correction-tool-id",
  "positionCorrectionReason": "applied",
  "referenceToRunHomMat2D": [1, 0, 0, 0, 1, 0],
  "referenceScale": 1.0,
  "runScale": 1.2,
  "scaleRatio": 1.2
}
```

另外建议记录：

- 修正前 ROI。
- 修正后 ROI 或其包围框。
- 修正 Region 面积。
- ROI 类型。
- HALCON 变换操作名。
- 匹配轮廓是否可用。
- 匹配原点是否可用。

这些字段用于区分“算法没检出”和“位置修正根本没有应用”。

## 12. 第九步：让 Dialog 测试执行完整前置工具链

### 12.1 为什么不能只运行当前 Adapter

以下写法只适用于未开启位置修正的独立测试：

```cpp
ToolRequest request;
request.config = currentConfig;
request.image = frame;
const ToolResult result = testEngine.runTool(request);
```

开启位置修正后，这个请求没有：

```text
runtimeContext.positionCorrectionsById
```

因此必然返回：

```text
position_correction_source_missing
```

下拉框选中了来源，只代表配置完成；它不会自动执行前置节点。

### 12.2 正确测试方式

打开工具 Dialog 时，外层应同时传入：

- 当前方案工具配置。
- 当前消费工具在方案中的索引。
- 当前基准图位置修正配置。
- 能运行所有前置工具类型的共享 `ToolEngine`，或等价测试服务。

测试时：

1. 取得当前消费工具之前的所有启用工具。
2. 用 Dialog 当前未保存配置替换消费工具配置。
3. 确保临时配置已写入下拉框的 `currentData()` 稳定来源 ID。
4. 将消费工具追加到测试前缀末尾。
5. 使用同一张测试图和同一张基准图调用 `runTools()`。
6. 取返回结果中的最后一个结果作为当前消费工具结果。
7. 显示该结果的修正 ROI、匹配轮廓、匹配原点和 OK/NG。

示意代码：

```cpp
QVector<ToolConfig> prefixConfigs =
        enabledConfigsThroughCurrentTool(currentIndex);
prefixConfigs.last() = currentDialogToolConfig();
prefixConfigs.last().enabled = true;

ToolResult referenceCorrectionResult;
const QVector<ToolResult> results =
        sharedEngine->runTools(
            prefixConfigs,
            testImage,
            referenceImage,
            runtimeContext,
            &referenceCorrectionResult);

const ToolResult currentResult =
        results.isEmpty()
        ? ToolResult::error(currentToolId, currentToolType,
                            QStringLiteral("工具链没有返回当前工具结果"),
                            QStringLiteral("tool_chain_result_missing"))
        : results.last();
```

注意：测试 Engine 必须注册前缀中所有工具的 Adapter。只注册当前工具 Adapter 仍然无法产生位置修正结果。

### 12.3 基准图测试

“基准图测试”使用：

```text
image = referenceImage
referenceImage = referenceImage
```

但仍然要执行完整前置链路。不能因为两张图相同就跳过模板定位和位置修正。

### 12.4 相机测试

“测试运行”使用：

```text
image = 当前相机帧快照
referenceImage = 当前方案基准图
```

模板定位、位置修正和当前工具必须消费同一张相机帧快照，不能在执行过程中重新读取不同帧。

### 12.5 暂时无法接入前置链路时

如果某个 Dialog 暂时没有工具链测试上下文，应在开启位置修正后禁用单工具测试，并明确提示：

```text
位置修正测试需要执行前置工具链，请在主运行界面测试。
```

不得继续孤立运行并让用户误以为模板没有匹配。

### 12.6 PC 图片离线测试准入规范

后续接入位置修正的功能必须先完成 PC 图片离线测试，再进入相机连续测试和现场联调。离线测试不是临时调试入口，而是位置修正消费工具的统一验收路径。

重复测试的请求和刷新口径统一以颜色比较为基准；按钮状态、导入来源和退出行为使用同一套离线测试状态：

1. 点击“PC导入图片”后读取并缓存单张图片，将测试来源切换为 `Imported`、测试状态切换为暂停态，并立即执行一次完整前置工具链。
2. 导入图是静态来源。此时“测试运行”必须显示为“测试运行（导入图）”，每次点击只重新执行一次，不得启动连续定时器重复计算同一张图片。
3. “完成”在导入测试态显示为“运行一次”；“基准图测试”隐藏，并显示“退出测试”。
4. 修改矩形、圆形、多边形 ROI 或屏蔽区并结束绘制后，必须在当前导入图上立即重测，不能悄悄切回基准图或相机帧。
5. 点击“退出测试”后清除当前导入测试来源，恢复编辑态按钮和基准图预览；之后“测试运行”才重新表示相机测试。
6. 测试请求必须携带导入图的输入元数据、当前方案基准图、基准位置修正上下文，并执行模板定位、位置修正和当前消费工具的完整依赖链。
7. 文件读取失败、无模型、无模板、无效 ROI、来源缺失或前置定位 NG 时必须返回明确错误；不得回退到相机、基准图或未修正算法路径。
8. 每次点击必须创建新的 `requestId` / `frameId` 并重新发起请求。发射请求前先清除上一轮运行 Overlay、恢复配置 ROI 并显示“运行中…”；结果返回后再填充本轮 Overlay，不能只在后台重算而让界面保持不变。

重复测试时只允许复用已创建的 HALCON 模型资源，不允许复用上一轮匹配结果、位置修正结果
或消费工具结果。同步实现必须在执行算法前处理一次排除用户输入的界面刷新；异步实现应使用
generation/pending 请求机制，防止旧请求结果覆盖新请求画面。

禁止以下行为：

- 导入图下启动连续定时器，重复计算同一张静态图片。
- 点击测试按钮后不创建新请求，只重新显示上一轮结果。
- 新请求运行期间继续保留上一轮轮廓、原点、检测框和结果文字。
- 退出测试时只调用 `setImage()`，不清除运行 Overlay。
- 没有新 `frameId` 的重复测试共用同一帧上下文。

离线测试至少覆盖：

- 同一张导入图首次运行和重复运行结果稳定。
- 未修正图、已知平移图、已知旋转图，以及功能支持缩放时的已知缩放图。
- 位置修正关闭、正常应用、来源缺失、前置定位 NG、矩阵非法和修正 ROI 越界。
- 导入态修改每一种受支持 ROI 后立即重测，且算法 Region 与运行 Overlay 一致。
- 退出离线测试后，相机测试不再复用已导入图片。

只有上述离线用例通过并留有结果、payload 或截图证据后，才能开展相机连续运行、节拍和现场稳定性验证。

## 13. 第十步：错误处理

消费工具不得静默退回固定 ROI。

| 场景 | 推荐状态 | 行为 |
|---|---|---|
| 未开启位置修正 | 正常运行 | 使用原固定 ROI |
| 来源上下文不存在 | `position_correction_source_missing` | 当前工具失败，不回退 |
| 来源模板未匹配 | `position_correction_match_not_found` | 当前工具失败，显示明确提示 |
| 来源运行失败 | `position_correction_source_failed` | 当前工具失败 |
| 来源 ID 不一致 | `position_correction_source_invalid` | 当前工具失败 |
| 矩阵缺失或非法 | `invalid_position_correction_matrix` | 当前工具失败 |
| 尺度非法 | `invalid_pose_scale` | 当前工具失败 |
| HALCON 变换失败 | 保留 HALCON 操作状态 | 当前工具失败 |
| 修正 ROI 完全在图外 | `corrected_roi_out_of_image` | 当前工具失败 |
| 请求显示轮廓但来源无轮廓 | `position_correction_contour_unavailable` 警告 | 算法可继续，给出明确提示 |

失败后必须清除上一帧运行 Overlay，避免残留旧轮廓、旧原点或旧 ROI。

## 15. 第十二步：专项测试

每个新消费工具至少增加一个位置修正 smoke。

### 15.1 配置测试

- 开关默认状态正确。
- 来源列表只包含基准图和合法前置节点。
- 保存后包含稳定来源 ID。
- 重新打开按稳定 ID 回显。
- 来源失效时保留配置并显示不可用。
- “显示匹配轮廓”保存和回显正确。

### 15.2 Consumer 测试

- 未开启时正常放行。
- 合法来源成功解析。
- 来源缺失明确失败。
- 模板未找到映射为统一状态。
- 非六元素矩阵失败。
- NaN/Inf 矩阵失败。
- 非正尺度失败。
- 匹配轮廓和匹配原点能够提取。

### 15.3 算法 Region 测试

- 平移后只能在新 ROI 中检测到目标。
- 反方向矩阵不能误检。
- 旋转后的 Region 与目标方向一致。
- 1.5 倍缩放后矩形宽高同步变化。
- 圆形 ROI 半径同步缩放。
- 多边形每个顶点同步变换。
- 部分越界时正确裁剪。
- 完全越界时明确失败。
- 算法 Region 与显示 Overlay 使用同一矩阵。

### 15.4 Overlay 测试

- 开启轮廓时包含 `position_correction_match_contour`。
- 关闭轮廓时不包含该角色。
- 关闭轮廓后仍包含 `position_correction_match_origin`。
- 检测 ROI 包含 `detect_roi`。
- 匹配失败后不保留上一帧 Overlay。
- 重复测试开始时旧轮廓、旧原点、旧检测框和旧结果文字立即移除。
- 重复测试结束后只显示本轮请求产生的 Overlay。
- 退出测试或恢复基准图后不保留任何运行 Overlay，只显示配置 ROI。
- 基准图内容更新后不保留更新前的运行 Overlay。

### 15.5 Dialog 工具链测试

这是防止出现“配置窗口已选择位置修正，但没有模板匹配显示”的必测项：

- Dialog 基准图测试执行前置模板定位和位置修正。
- Dialog 相机测试执行前置模板定位和位置修正。
- 当前临时配置使用下拉框 `currentData()` 中的稳定 ID。
- 前置模板匹配成功时显示轮廓、原点和修正 ROI。
- 前置模板未匹配时显示明确提示。
- 不允许出现仅因为 `runtimeContext` 为空导致的伪失败。
- 导入同一图片后连续点击两次“测试运行（导入图）”，两次请求的
  `requestId` / `frameId` 不同。
- 每次重复测试都重新执行模板定位、位置修正和当前消费工具，不能复用上一轮结果。
- 发射请求后立即显示“运行中…”或等价状态，结果返回后再填充本轮 Overlay。
- 点击“退出测试”后按钮、基准图和配置 ROI 恢复，下一次“测试运行”读取相机帧。

## 16. 最终验收步骤

按以下实际操作顺序验收：

1. 创建或打开方案并设置基准图。
2. 添加模板定位工具，在基准图上创建模板。
3. 添加位置修正工具，绑定该模板定位工具并创建基准姿态。
4. 在位置修正工具之后添加当前消费工具。
5. 在消费工具基准图上绘制检测 ROI。
6. 开启位置修正。
7. 选择前面创建的位置修正节点。
8. 保持“显示匹配轮廓”开启。
9. 点击“基准图测试”，确认前置匹配、修正 ROI 和算法结果均显示。
10. 通过“PC导入图片”载入发生平移、旋转或缩放的离线运行图，确认导入后立即执行完整链。
11. 再次点击“测试运行（导入图）”，确认旧结果先清除、显示运行中状态，并产生新的
    `requestId` / `frameId` 和本轮 Overlay。
12. 修改每一种受支持 ROI，确认在同一导入图上立即重新执行完整链。
13. 点击“退出测试”，确认所有运行 Overlay 清除，只恢复基准图和配置 ROI。
14. 确认退出后“测试运行”读取相机帧，不再复用导入图。
15. 确认检测 ROI 跟随目标位置、角度和大小变化，且算法只在修正后的 ROI 内运行。
16. 关闭“显示匹配轮廓”，确认仅轮廓消失，ROI 修正和匹配原点仍保留。
17. 故意让模板匹配失败，确认显示明确错误且无上一帧残留。
18. 保存方案、关闭并重新打开，确认开关和稳定来源正确回显。
19. 离线测试全部通过并留有证据后，再在主界面执行相机单次和连续运行，确认行为一致。

完成标准：

- 配置、保存、回显、测试运行和主运行形成闭环。
- ROI 的实际 HALCON Region 与显示 Overlay 同步平移、旋转和缩放。
- Dialog 测试和主工具链运行都能获得前置位置修正上下文。
- 来源异常不崩溃、不静默回退、不显示旧结果。
- PC 图片首次测试、重复测试、ROI 重测和退出测试均符合颜色比较的刷新口径。
- 相机联调开始前已有离线测试结果、payload 或截图证据。
- 对应 smoke、主工程 qmake 和 make 全部通过。

### 19.3 Blob 双 ROI 显示修正

### 19.4 Blob 重复测试和退出清理
