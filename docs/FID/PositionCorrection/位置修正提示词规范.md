# 位置修正提示词规范

## 文档用途

本文档规范后续位置修正开发任务的提示词，避免把 UI、配置引用和 HALCON 算法混在一次改动中。所有任务必须先阅读项目约束和位置修正当前状态。

## 当前事实（2026-07-23）

- 基准图位置修正固定 ID 为 `reference.positionCorrection`，当前显示编号为 `0 基准图`。
- 工具级位置修正是纯姿态变换节点，不拥有模板区域；运行姿态可以来自前置模板定位，也可以来自有效的
  `reference.positionCorrection`。
- `ToolEngine` 已建立逐帧结果上下文，位置修正会校验稳定 ID、工具类型和 `frameId`，不复用上一帧结果。
- 位姿的 X、Y、角度以及显式提供的尺度必须是有效有限数值，非法输入返回明确错误。
- 当前完整消费者不只有颜色比较，还包括 Blob 有无；其他工具链尚未接入。

下文“UI 第一阶段标准提示词”只作为历史任务模板保留，不代表当前实现状态。新任务必须以上述当前事实和
当前代码为准。

## 分层顺序

位置修正必须按以下阶段实施：

1. UI 与配置闭环。
2. 公共输出描述和依赖解析。
3. HALCON runner 与 Adapter。
4. 消费工具 ROI 修正联调。

除非用户明确要求跨阶段联调，否则一次提示词只处理一个阶段。

## 目标

只实现位置修正 UI、配置和引用闭环：

- 基准图页面拥有独立的一份位置修正配置。
- 工具库“定位工具”分类可以创建多个位置修正实例。
- 每个位置修正实例拥有独立 Dialog 和字段绑定。
- 其他视觉工具开启独立位置修正后，可以选择基准图或合法前置位置修正实例。
- 界面显示动态序号，配置内部使用稳定来源 ID。
- 删除、禁用或重排来源后显示失效状态，不静默回退。
- 保存、重新打开和编辑时完整回显。
- 当时后端未实现时明确显示 `not implemented`，不伪造结果。

## 范围

In:

- 新增 `ToolType::PositionCorrection` 和字符串映射。
- 增加方案级 `referencePositionCorrection` 配置及旧方案默认值。
- 增加 `positionCorrectionSourceId`，保留现有 `positionCorrectionSource`。
- 接入工具库、工具页和独立位置修正 Dialog。
- 实现上游字段两级选择菜单和合法前置节点过滤。
- 实现矩形/多边形模板 ROI 的保存与回显（该历史设计已废止，当前工具级位置修正不再拥有模板 ROI）。
- 实现基准图配置与工具实例配置互不覆盖。
- 增加 UI/config smoke，并更新实现记录。

Out:

- 不新增 Adapter 或 HALCON Runner。
- 不实现模板匹配、姿态计算或检测 ROI 变换。
- 不生成伪造 OK/NG、分数、修正矩阵或成功输出。
- 不扩展多基准图数据模型。
- 不重构无关工具 UI、公共配置或算法链路。

## 交互约束

- 基准图固定 ID 为 `reference.positionCorrection`。
- 工具实例引用使用 `toolId`，不使用显示序号。
- 来源菜单只显示基准图和当前工具之前的有效位置修正实例。
- X/Y/角度字段绑定保存 `producerId + outputKey + displayPath`。
- 来源无效且位置修正使能打开时，禁止完成和测试。
- 无基准图时允许保存草稿，但禁止测试。
- 普通按钮不得误触发窗口关闭或程序退出。

## HALCON 阶段提示词约束

HALCON 阶段开始前必须先执行能力确认，并在专项设计中列出本机实际存在的 HALCON 接口。提示词必须明确：

- Runner 位于 `src/algorithms/` 对应定位域目录，使用 HALCON runner 形态。
- Adapter 只负责配置解析、调用 runner 和统一 `ToolResult` 转换。
- OpenCV 不得承担模板匹配、角度计算或变换计算。
- runtime、license 或符号缺失时返回明确错误，不做算法降级。
- UI 阶段的稳定 ID、依赖顺序和失效来源规则不得被后端改写。

本机能力未确认前，不得在提示词中指定未经验证的 HALCON 符号为既定实现。

## 联调阶段提示词约束

联调阶段只连接已经存在的 UI/config 与已经验证的 Adapter/Runner：

- 将位置修正输出解析为下游检测 ROI 的平移和旋转输入。
- 保留原始 ROI 配置，运行时生成修正后的临时 ROI。
- payload 同时输出来源、是否应用、修正量、耗时和错误原因。
- 编辑 ROI 与运行结果 overlay 分离。
- 来源失效时停止应用并返回明确错误，不使用上一次修正结果。
- 覆盖连续运行、运行一次、基准图测试和异常输入。

## 禁止写法

后续提示词不得包含以下要求：

- “先用 OpenCV 做出来，后续再换 HALCON”。
- “来源无效时自动使用第一个位置修正”。
- “直接保存 `12 位置修正` 作为唯一引用”。
- “后端未实现时先显示模拟 OK”。
- “为了位置修正顺便重构所有工具 Dialog”。
- “截图里有多基准，因此同时重做基准图存储”。
