# 基准图位置修正自定义定位点设计

更新时间：2026-07-22

## 1. 目标与边界

在方案级“基准图位置修正”中增加定位点选择，使用户可以选择模板质心或在整张基准图内指定任意自定义点。自定义点将成为模板匹配输出姿态的 X/Y 原点，并直接参与基准姿态、运行姿态和位置修正矩阵计算。

本次只扩展基准图位置修正的定位点配置与交互，不改变：

- 工具级位置修正的 `runPoseSource` 合同；
- 模板定位工具已有的定位点实现；
- 下游工具使用 `referenceToRunHomMat2D` 的方向；
- 第一阶段只进行平移和旋转、不引入尺度修正的边界。

## 2. 已确认语义

- 定位点模式包含“质心”和“自定义点”，默认使用质心。
- 自定义点允许选择基准图内任意位置，不要求落在模板 ROI 内。
- 自定义点使用整张基准图归一化坐标保存，范围为 `[0, 1]`。
- 自定义点不是单纯的显示标记。它必须成为 HALCON 模板匹配的真实姿态原点。
- 创建基准时保存的 `referencePose.x/y` 是自定义点在基准图中的位置。
- 每帧匹配得到的 `runPose.x/y` 是同一自定义点随目标平移、旋转后的实际位置。
- `referenceToRunHomMat2D` 继续由 `referencePose -> runPose` 计算，下游无需知道定位点模式。

## 3. 方案选择

采用复用现有 `TemplateLocationHalconRunner` 定位点合同的方案：

```text
ReferencePositionCorrectionConfig
        |
        | originMode + customOriginNormalized
        v
TemplateLocationHalconConfig
        |
        | affine_trans_point_2d
        v
referencePose / runPose
        |
        v
PositionCorrectionHalconRunner
```

不在位置修正层重复计算自定义点，也不允许只显示自定义点而继续使用质心计算矩阵。这样可沿用已经验证的 HALCON Row/Column、角度和自定义点变换逻辑，避免显示语义与运行语义分离。

## 4. 配置合同

`ReferencePositionCorrectionConfig` 增加：

```json
{
  "originMode": "centroid",
  "customOriginNormalized": {"x": 0.5, "y": 0.5}
}
```

字段规则：

- `originMode` 只允许 `centroid` 或 `custom`。
- `customOriginNormalized` 始终可持久化，但只有 `originMode=custom` 时参与运行。
- 旧方案缺失字段时按 `centroid` 和 `{0.5, 0.5}` 读取，保持向后兼容。
- 自定义点坐标必须是有限数值且位于 `[0, 1]`；无效配置不得静默回退质心。
- 定位点模式或坐标发生变化时，必须清除 `referenceCreated`、`referencePose`、匹配轮廓和匹配定位点。
- 定位点不属于 HALCON shape model 的建模签名；改变定位点不要求重建模型文件，但必须重新执行基准图自匹配并冻结新的 `referencePose`。

## 5. UI 与交互

基准图位置修正配置卡新增一行“定位点”：

- 下拉框：`质心 / 自定义点`。
- 自定义点模式显示“选择点”按钮和归一化 X/Y 文本。
- 点击“选择点”进入点选模式，画布标题提示“点击基准图选择自定义定位点”。
- 在基准图任意位置单击后更新 `customOriginNormalized`；点选模式保持开启，允许继续点击调整，直到用户退出或切换其他操作。
- 自定义点在基准图上使用青色十字显示，与绿色匹配轮廓和绿色运行定位点区分。
- 切换为质心时停止点选并隐藏自定义点十字。
- ROI 绘制、当前图像模式、关闭位置修正和切换页面时停止点选，避免手势冲突。

完成模板 ROI 或点击“测试运行”时：

1. 校验定位点配置；
2. 调用私有 `TemplateLocationHalconRunner` 自匹配；
3. 成功后绘制绿色匹配轮廓和绿色匹配定位点；
4. 自定义模式下同时保留青色基准自定义点标记；
5. 保存新的 `referencePose`、分数、耗时和状态。

基准图自匹配时青色点与绿色匹配点通常重合；使用不同颜色和绘制层级保留二者，是为了明确“用户定义的原点”和“算法返回的当前姿态点”属于不同语义。

## 6. 算法与数据流

`ReferenceImageDialog::buildAndValidateReferencePositionModel()` 构造私有定位配置时传入：

```text
config.originMode = referenceConfig.originMode
config.customOriginNormalized = referenceConfig.customOriginNormalized
```

Runner 沿用现有逻辑：

- 先计算模板 ROI 质心；
- 自定义模式下计算自定义点相对模板质心的 Row/Column 偏移；
- 使用 HALCON `affine_trans_point_2d` 将该偏移随匹配角度和平移变换；
- 对外保持 `x = HALCON Column`、`y = HALCON Row`、角度为度。

基准图运行期私有定位配置必须读取同一份 `originMode/customOriginNormalized`，保证创建基准和每帧运行使用完全相同的姿态原点。工具级位置修正和下游消费工具无需增加字段。

## 7. 状态与错误处理

- 无基准图：`no_reference_image`。
- 无模板 ROI：`no_template_region`。
- 自定义点缺失、越界或非有限：`invalid_custom_origin`。
- 点选过程中不允许保存为已创建状态；状态为 `editing_origin`。
- 定位点变化后，旧 `referencePose` 和匹配 overlays 立即失效，不得继续注册为 `reference.positionCorrection`。
- 自匹配失败时不保留上一次轮廓、定位点或姿态。
- 更换基准图后保留定位点模式，但清除旧自定义点坐标并回到图像中心 `{0.5, 0.5}`，要求用户重新确认；避免旧图坐标被误用于新基准图。

## 8. 验证设计

### 配置与兼容

- 旧方案无定位点字段时默认质心。
- 质心和自定义点保存、重新打开后正确回显。
- 自定义点允许位于模板 ROI 外，但必须位于基准图内。
- 非有限或越界坐标返回 `invalid_custom_origin`。

### UI

- 下拉模式、选择点按钮和坐标文本显隐正确。
- 青色自定义点、绿色匹配轮廓和绿色匹配定位点同时可见。
- ROI 绘制与点选手势互斥。
- 切换当前图像、关闭位置修正、更换基准图或匹配失败后不显示旧标记。

### HALCON 与姿态

- 自定义点位于模板质心时，结果与质心模式一致。
- 自定义点位于模板 ROI 内和外时，自匹配 X/Y 均等于所选基准图像素坐标。
- 目标平移后，自定义点输出相同平移量。
- 目标旋转后，自定义点围绕模型姿态正确旋转，验证 `affine_trans_point_2d` 方向。
- `referenceToRunHomMat2D` 能把基准自定义点变换到运行自定义点。
- 连续两帧先成功后失败，第二帧不得沿用第一帧姿态或标记。

## 9. 不在本次范围

- 不增加多个自定义点或坐标系链。
- 不允许 X、Y 分别绑定不同点。
- 不把尺度加入位置修正矩阵。
- 不修改普通模板定位工具已有的定位点交互。
- 不为自定义点引入 OpenCV 或手写几何替代 HALCON 变换。
