# 位置修正下一阶段实施计划

更新时间：2026-07-23

下游工具公共接入的职责拆分、接口草案、执行顺序和验收矩阵见
《[位置修正公共消费辅助层实施计划](位置修正公共消费辅助层实施计划.md)》。

## 当前事实（2026-07-23）

- 阶段 A 至 D 已落地；公共消费辅助层已由颜色比较和 Blob 有无完整接入。
- 基准图固定 ID 为 `reference.positionCorrection`，当前显示为 `0 基准图`。
- 工具级位置修正是纯姿态变换节点，不保存模板 ROI；它可以订阅前置模板定位，也可以订阅
  有效的基准图位置修正。
- 每次 `runTools` 都重建当帧动态结果，来源身份和帧 ID 必须一致。
- X、Y、角度以及显式尺度使用严格数值校验，不再把非法值回退为零。
- 其他工具链的阶段 E 接入尚未执行。

下文的阶段描述同时保留设计过程和历史计划；与本节冲突时，以本节和当前代码为准。

## 0. 开发前讨论确认与官方语义核对

2026-07-21 已确认：

1. 每个下游工具只选择一个最终修正来源；选择局部位置修正时使用局部绝对矩阵，不再叠加全局矩阵。
2. 工具位置修正的 X、Y、角度必须来自同一个上游实例，不允许跨实例拼接姿态。
3. 基准图模板 ROI 点击“完成”时立即创建模型并进行一次自匹配验证，成功后才标记基准图位置修正可用。

结合海康机器人 VM 官方手册重新核对后，位置修正的数据语义锁定如下：

- 二维位置修正内部需要两组姿态：`referencePose`（基准姿态）和 `runPose`（运行姿态），每组包含 X、Y、角度和尺度。尺度缺失时按 `1.0` 兼容。
- 工具位置修正 Dialog 中的三个可订阅字段是**运行姿态来源**，不是由用户分别填写的基准姿态。
- 点击“创建基准”时，先在基准图上执行同一个上游实例，将该次输出冻结为 `referencePose`；后续每帧从同一来源读取 `runPose`。
- 下游既可以订阅完整“位置修正信息”，也可以按点或按坐标消费基准点、运行点及对应角度。因此本项目对外输出应保留完整修正对象，同时保留结构化基准/运行姿态用于显示和诊断。
- 模板定位输出的 `scale` 已纳入位置修正合同。运行时使用 `runScale/referenceScale` 得到尺度比，并通过 HALCON 相似变换统一修正平移、旋转和尺度。界面不新增基准范围或手动尺度参数；旧配置缺失尺度时自动按 `1.0` 处理。

当前代码的 `runPointX/runPointY/runAngle` 键名表达的是运行姿态，但默认 `displayPath` 使用了“基准点坐标/基准角度”，容易造成误解。实施时应把显示语义修正为“运行点”，并将新版配置收敛为 `runPoseSource`；基准姿态只由“创建基准”动作生成。

当前阶段暂不接入海康 SDK。海康 SDK、相机触发、曝光、增益和像素格式一致性只作为后续相机接入时的扩展接口与验证建议，不作为本阶段位置修正是否可用的判断条件。

## 1. 本阶段结论

模板定位已经完成，下一阶段不再扩展模板定位本身，而是建立定位结果到位置修正、再到下游 ROI 的运行链路。

需要明确区分三类对象：

| 对象 | 身份 | 是否做模板匹配 | 输入 | 输出 |
| --- | --- | --- | --- | --- |
| 模板定位工具 | 工具链中的定位生产者，使用稳定 `toolId` | 是 | 基准图、运行图、模板/搜索 ROI 和匹配参数 | `x/y/angle/score/matches` |
| 工具位置修正 | 工具链中的局部坐标系节点，使用稳定 `toolId` | 否 | 前置位姿生产者的运行姿态 + 创建基准时保存的基准姿态 | 指定局部对象的参考坐标到运行坐标变换 |
| 基准图位置修正 | 方案级全局坐标系节点，固定 ID `reference.positionCorrection` | 是，使用节点内部的私有定位器 | 方案基准图、基准图模板 ROI、当前运行图 | 产品整体的参考坐标到运行坐标变换 |

因此：

- 基准图位置修正和工具位置修正使用相同的**变换合同**，但不使用相同的配置和基准数据。
- 基准图位置修正既是下游工具可选择的修正来源，也可作为工具级位置修正的有效姿态来源。
- 工具位置修正可以订阅真实声明了 X/Y/角度位姿输出的前置工具，或固定基准图来源；
  不能仅凭字段同名推断能力。当前普通工具生产者是模板定位。
- 不应让工具位置修正再绘制一份模板 ROI；当前 `PositionCorrectionDialog` 中的模板 ROI 字段属于早期混合设计，应迁移为兼容字段并停止新增写入。

## 2. 链接关系

### 2.1 工具位置修正链路

```text
TemplateLocation(toolId=A)
        |
        | pose: x/y/angle，按 toolId + outputKey 引用
        v
PositionCorrection(toolId=B)
        |
        | correction: referenceToRunHomMat2D
        v
后续检测工具(toolId=C)
```

规则：

1. `B` 必须位于 `A` 之后，`C` 必须位于 `B` 之后。
2. X、Y、角度三项必须来自同一个生产者和同一次结果，不能拼接不同工具的字段。
3. `创建基准` 时，用基准图作为运行图重新执行 `A`，保存 `B.referencePose`；不能取当前实时帧结果，也不能依赖上一次缓存结果。
4. 每帧运行时，`B` 从当帧运行上下文读取 `A.runPose`，计算变换并写回自己的 `ToolResult`。

`创建基准` 必须使用专用上下文执行上游实例，建议标记为 `frameKind=referenceCalibration`。该上下文只允许读取基准图、上游实例自身配置和必要的静态参数，不允许读取上一帧工具结果、下游位置修正结果或运行态缓存，避免创建基准时出现递归依赖或把运行帧状态冻结为基准姿态。

### 2.2 基准图位置修正链路

```text
SchemeState.referencePositionCorrection
        |
        | 私有 locator 配置/模型，固定内部 ID
        v
基准图上创建模型并保存 referencePose
        |
        | 每帧在运行图上模板匹配得到 runPose
        v
固定来源 reference.positionCorrection
        |
        v
选择该来源的后续检测工具
```

基准图节点不进入 `toolConfigs`，不占工具序号。它可以出现在工具级位置修正的来源菜单及
下游检测工具的“位置修正来源”菜单中，运行引用始终使用固定 ID。

### 2.3 全局与局部的作用范围

- 基准图位置修正建立产品级全局坐标系，适用于随整件产品一起移动的检测 ROI。
- 工具位置修正建立某个局部对象的坐标系，适用于产品内部仍会独立偏移的零件、字符、孔位或焊盘。
- “全局”不表示无条件修改全部工具。只有启用了位置修正并选择 `reference.positionCorrection` 的工具才使用全局矩阵。
- “局部”也不限定只能服务紧邻的一个工具。任意位于该位置修正之后、明确选择其稳定 `toolId` 的工具都可以共享这个局部坐标系。

典型层级：

```text
基准图位置修正 G（产品整体）
        |
        +--> 普通检测工具：直接选择 G
        |
        +--> 局部定位工具：可用 G 修正搜索 ROI
                    |
                    v
              工具位置修正 L
                    |
                    +--> 局部精密检测工具：选择 L
```

两者可以同时存在，但同一个消费工具第一版只选择一个**最终修正来源**。局部定位工具输出的是当前图像中的绝对位姿，因此工具位置修正生成的 `referenceToRunHomMat2D` 已经包含产品整体运动和局部相对运动；下游选择局部修正时不能再把全局矩阵重复乘一次。

若需要展示局部对象相对产品的剩余偏移，可以额外计算 `localResidual`，满足概念关系 `localAbsolute = global ∘ localResidual`。该残差只用于诊断或未来显式的坐标系链，不替代下游使用的绝对 `referenceToRunHomMat2D`；实际组合必须使用 HALCON `hom_mat2d_compose` 并通过方向 smoke 锁定顺序。

## 3. 基准图中的模板匹配处理

### 3.1 算法复用边界

基准图位置修正不应再实现一套新的模板匹配算法。它应复用模板定位已经验证的 HALCON 形状模板能力，但保持独立身份和缓存：

- 短期实现可以由方案级执行器直接调用 `TemplateLocationHalconRunner`，将方案级配置映射为 `TemplateLocationHalconConfig`。
- 若后续出现第三个形状模板消费者，再把模型创建/查找抽成底层 `ShapeModelMatcher`；本阶段不为了抽象而重构已稳定的模板定位 UI 和 Adapter。
- 基准图节点使用独立 `modelCacheKey`，建议固定前缀 `reference.positionCorrection.locator`，不得与任何模板定位工具共享缓存键。
- 缓存签名继续包含基准图内容、模板 ROI 和全部建模参数；基准图或 ROI 改变时必须使 `referenceCreated=false` 并使旧缓存失效。

### 3.2 创建基准

基准图页面点击“完成”或后续明确的“创建基准”动作时执行：

1. 校验基准图、模板 ROI 和 HALCON 环境。
2. 用方案级私有 locator 在基准图上建模并在同一基准图上做一次自匹配验证。
3. 只接受一个主结果，保存其 `referencePose={x,y,angleDeg,scale}`；上游未提供尺度时保存 `scale=1.0`。
4. 保存 `referenceCreated=true`、模型配置版本和稳定缓存键；模型本体沿用现有持久缓存机制，不写入方案 JSON。
5. 自匹配失败、数量不为 1 或得分不足时不创建基准，并返回明确错误。

第一版建议固定：`maxMatches=1`、`minMatchCount=1`、`maxMatchCount=1`、搜索范围为全图。高级匹配参数可以进入“全部”页，但不应与模板定位工具的配置对象相互引用。

### 3.3 每帧运行

1. 用私有 locator 在当前图像上执行模板匹配。
2. 匹配成功且判定 OK 时取得 `runPose`。
3. 调用公共位置变换计算能力生成双向矩阵。
4. 把结果放入当帧运行上下文的 `positionCorrectionsById["reference.positionCorrection"]`。
5. 当前帧失败时立即输出失败，不得沿用上一帧姿态或矩阵。

## 4. 变换方向与结果合同

下游工具的 ROI 是在基准图坐标系中配置的。对象在运行图中移动后，检测 ROI 应从基准位置移动到运行位置。因此下游真正使用的主矩阵必须是：

```text
referenceToRunHomMat2D =
    hom_mat2d_scale(
        vector_angle_to_rigid(referencePose, runPose),
        runScale/referenceScale,
        runScale/referenceScale,
        runPose)
```

已有衔接文档中“运行位姿到基准位姿，并用该矩阵移动 ROI”的表述方向相反，需要纠正。为避免未来图像归一化等需求产生歧义，结果同时输出逆矩阵：

```text
runToReferenceHomMat2D = vector_angle_to_rigid(runPose, referencePose)
```

统一 payload 至少包含：

```text
sourceKind: "tool" | "reference"
scope: "local" | "global"
sourceId
poseProducerId
referencePose: {x, y, angleDeg, scale}
runPose: {x, y, angleDeg, scale}
referenceScale
runScale
scaleRatio
referenceToRunHomMat2D
runToReferenceHomMat2D
deltaX
deltaY
deltaAngleDeg
positionCorrectionApplied
positionCorrectionReason
frameId
frameMeta
```

`deltaX/deltaY/deltaAngleDeg` 只用于显示和诊断；涉及旋转时，下游几何变换必须使用完整矩阵，不能只做 X/Y 加减。

坐标合同必须固定为：`x = HALCON Column`，`y = HALCON Row`；payload 对外角度使用度，HALCON 算子内部按需转换为弧度。任何输出注册、矩阵计算、overlay 和下游 ROI 变换都不得交换 Row/Column 或混用角度单位。

`frameMeta` 是运行帧一致性检查的预留结构。本阶段至少允许记录 `frameId`、`frameKind`、`imageWidth`、`imageHeight` 和 `sourceTag`；若未来接入海康 SDK，可扩展 `cameraId`、`frameNum`、`deviceTimestamp`、`hostTimestamp`、`triggerMode`、`exposureTime`、`gain`、`pixelFormat` 等字段。当前阶段不根据触发、曝光、增益或像素格式判断位置修正有效性，但运行上下文必须保证模板定位、位置修正和下游工具消费的是同一张运行图。

## 5. 配置调整与兼容

### 5.1 工具位置修正

`ToolConfig.params.positionCorrection` 目标结构：

```json
{
  "version": 2,
  "runPoseSource": {
    "producerId": "template-location-tool-id",
    "xKey": "x",
    "yKey": "y",
    "angleKey": "angle",
    "scaleKey": "scale"
  },
  "referenceCreated": true,
  "referencePose": {"x": 0.0, "y": 0.0, "angleDeg": 0.0, "scale": 1.0}
}
```

兼容策略：

- 继续读取旧 `runPointX/runPointY/runAngle`；三项来源一致时迁移为 `runPoseSource`。
- 旧配置没有 `scaleKey`、`referencePose.scale` 或运行结果没有 `scale` 时，按 `1.0` 兼容；字段存在但不是有限正数时返回 `invalid_pose_scale`。
- 三项来源不一致时标记 `inconsistent_pose_source`，要求用户重新绑定，不能静默选择其中一个。
- 旧 `templateRegionType/templateRoiNormalized/templatePolygonNormalized` 保留读取但不参与工具位置修正运行；保存新版配置时不再新增或覆盖这些字段。

### 5.2 基准图位置修正

`SchemeState.referencePositionCorrection` 升级为版本 2，除现有 ROI 外增加私有 locator 参数、`referenceCreated`、`referencePose` 和 `modelCacheKey`。基准图或建模参数改变时统一清除创建状态。

## 6. 执行上下文

`ToolEngine::runTools` 应在每帧创建新的上下文并按顺序追加结果，至少包含：

```text
toolResultsById[toolId]
positionCorrectionsById[sourceId]
frameId
```

执行顺序：

1. 如果方案级基准图位置修正启用，先执行该固定节点并登记结果。
2. 顺序执行 `toolConfigs`；每个结果完成后立即按稳定 `toolId` 登记。
3. 工具位置修正只读取已登记的前置位姿结果。
4. 下游工具只读取已登记的前置修正结果。

当全局与局部同时启用时：全局矩阵可先帮助局部定位工具移动搜索 ROI；局部位置修正随后根据该定位工具的实际输出生成局部对象的绝对修正矩阵。消费局部修正的下游工具只应用这个绝对矩阵，不再次叠加全局矩阵。

不能把用户传入的只读 `runtimeContext` 原样传给所有工具而不追加当帧结果；也不能跨帧复用可变上下文。

若后续接入海康 SDK，SDK 采集层应在进入 `ToolEngine` 前完成图像所有权交接：从 SDK buffer 复制或转换为生命周期独立的图像对象，并在释放 SDK buffer 后不得继续引用原始指针。位置修正算法层只依赖 `cv::Mat` / `QImage` 等已稳定拥有内存的图像输入，不直接依赖海康 SDK 句柄。相机帧号、设备时间戳、主机时间戳等信息通过 `frameMeta` 透传，不参与本阶段核心判断。

## 7. 分阶段实施顺序

### 阶段 A：锁定合同与输出注册

- 增加带类型的定位输出描述，只让模板定位声明 `x/y/angle` 位姿能力。
- 输出注册机制允许未来的边缘定位、圆定位或目标检测声明其真实具备的位姿字段；没有可靠角度的生产者不能伪造角度输出。
- 修正 `PositionCorrectionDialog` 菜单：移除基准图位姿节点，过滤非定位生产者，三项绑定收敛为同一 `runPoseSource`，显示文本统一使用“运行点/运行角度”。
- 定义双向矩阵 payload 和稳定错误码。

### 阶段 B：建立当帧运行上下文

- `ToolEngine` 按顺序登记 `ToolResult`。
- 增加前向引用、禁用来源、来源 NG、帧 ID 一致性校验，并为基准创建引入 `referenceCalibration` 专用上下文。
- 保证模板定位当前帧失败后不会读取历史结果。

### 阶段 C：实现工具位置修正

- 新增 `PositionCorrectionAdapter` 和只负责姿态变换的 `PositionCorrectionHalconRunner`。
- “创建基准”通过基准图执行绑定的模板定位并保存 `referencePose`。
- 每帧读取模板定位 `runPose`，输出双向矩阵。
- 工具位置修正不创建或查找模板。

### 阶段 D：实现基准图组合节点

- 扩展 `ReferencePositionCorrectionConfig`。
- 复用 `TemplateLocationHalconRunner` 完成私有模板建模和每帧匹配。
- 使用与工具位置修正相同的变换计算和结果合同。
- 以固定 ID 注册到 `positionCorrectionsById`。

### 阶段 E：接入下游 ROI

- 先选择一个已稳定、ROI 结构清晰的工具做端到端试点。
- 使用 HALCON `affine_trans_region`、`affine_trans_contour_xld` 或对应几何接口应用 `referenceToRunHomMat2D`。
- 下游工具的原始配置继续保存基准图归一化 ROI；运行时先按当前图像尺寸还原为原图像素坐标，再应用 `referenceToRunHomMat2D` 生成临时检测 ROI。临时 ROI 必须裁剪到当前图像范围，只进入本次 runner，不写回原配置。
- 试点通过后再逐类接入矩形、圆形、多边形、轮廓等 ROI，避免一次修改所有 Adapter/Runner。

### 阶段 F：兼容、UI 和回归

- 迁移旧位置修正绑定，清理工具位置修正的模板 ROI 占位交互。
- 统一为 `0 基准图` 显示文案；历史编号 1 仅作为迁移输入，运行继续只用稳定 ID。
- 更新旧状态文档，补齐主工程、算法 smoke、UI smoke 和真实桌面验证。

## 8. 必测场景

- 模板定位 → 工具位置修正 → 下游工具的平移、旋转、缩放及组合变换。
- 基准图内置匹配 → 下游工具的同等变换，且结果合同与工具位置修正一致。
- 全局修正与局部修正同时存在：普通工具选择全局源，局部工具选择局部源，验证无重复补偿。
- 局部定位工具先使用全局矩阵移动搜索 ROI，再由局部位置修正产生最终绝对矩阵。
- `referenceToRun` 方向验证：目标向右移动时，下游 ROI 也必须向右移动。
- Row/Column 和角度单位验证：模板定位输出 `x` 必须对应 HALCON Column，`y` 必须对应 Row；payload 角度为度，内部调用 HALCON 前再转换。
- 下游 ROI 运行态验证：基准归一化 ROI 不被写回修改，修正后的临时 ROI 按当前图像边界裁剪。
- 创建基准上下文隔离：创建基准不得读取上一帧结果、下游修正结果或运行态缓存。
- 来源缺失、禁用、后置、字段类型错误、三字段来源不一致。
- 基准未创建、基准图变化、模型缓存失效、模板匹配 NG、数量判定 NG。
- 连续两帧先成功后失败，第二帧不得使用第一帧矩阵。
- 多个位置修正实例独立创建基准、独立输出，复制/删除/重排后稳定 ID 行为正确。
- HALCON runtime、license 或必要符号缺失时返回明确错误，不使用替代算法。

## 9. 本阶段不做

- 不把基准图位置修正伪装成普通 `ToolConfig`。
- 不让工具位置修正重复模板匹配。
- 不在位置修正层自行挑选模板定位的非主匹配结果。
- 不扩展多基准图数据模型。
- 不用 OpenCV 或自写算法替代 HALCON 匹配与几何变换。
- 不在本阶段把触发、曝光、增益或像素格式一致性作为位置修正可用性的硬判断。

## 10. 海康 SDK 预留接口建议

后续大概率不直接接入海康 SDK。本阶段不新增 MVS 依赖、不链接 `libMvCameraControl.so`，也不改变当前 OpenCV/Qt 图像输入链路。

为以后可能接入相机 SDK，建议把预留边界放在采集层而不是位置修正算法层：

```text
Camera SDK / OpenCV / 文件图像
        |
        v
FrameProvider 输出 ImageFrame{image, frameMeta}
        |
        v
ToolEngine / ToolRequest
        |
        v
TemplateLocation / PositionCorrection / 下游工具
```

`ImageFrame` 建议包含稳定拥有内存的图像对象和可选 `frameMeta`。如果未来使用海康 MVS 的 `MV_CC_GetImageBuffer()`，采集层必须在 `MV_CC_FreeImageBuffer()` 前完成深拷贝或像素格式转换；位置修正不得持有 SDK buffer 指针。海康帧号、时间戳、触发和相机参数只通过 `frameMeta` 透传，用于日志、诊断和未来更严格的一致性校验。
